# タスク詳細: 5.1 document-server 柔軟な統計項目対応

## 概要

データカタログの基本統計量（`statistics`）セクションに、テーブル固有の任意統計項目を追加できるようにする。YAML 上では `statistics` セクション内に既知3フィールド（`row_count`, `date_range`, `update_frequency`）以外のキーを自由に記述でき、API レスポンスでは `additional` オブジェクトとしてまとめて返却する。

テーブルごとに異なる統計指標（例: 平均バスケットサイズ、アクティブ率、上位カテゴリ等）をカタログに定義し、AI が分析時に参照できるようにするために必要。

#### ステップ 1: モデル追加（`models.py`）

`Statistics` モデル（現在 98-101行目）に `additional` フィールドを追加する。

```python
class Statistics(BaseModel):
    """基本統計量"""
    row_count: int | None = None
    date_range: DateRange | None = None
    update_frequency: str | None = None
    additional: dict[str, Any] = Field(default_factory=dict)
```

- `additional` はデフォルト空 dict とし、拡張統計項目がない場合でもフィールドが存在する
- 値の型は `Any`（数値、文字列、配列等を許容）

#### ステップ 2: パース拡張（`catalog_loader.py`）

`_parse_statistics` 関数（現在 114-124行目付近）で、既知3フィールド以外のキーを `additional` に収集するロジックを追加する。

```python
_KNOWN_STATISTICS_FIELDS = {"row_count", "date_range", "update_frequency"}

def _parse_statistics(stats_data: dict[str, Any] | None) -> Statistics | None:
    if stats_data is None:
        return None
    # 既知フィールドの抽出（既存ロジック）
    date_range = ...  # 既存
    # additional の収集
    additional = {
        k: v for k, v in stats_data.items()
        if k not in _KNOWN_STATISTICS_FIELDS
    }
    return Statistics(
        row_count=stats_data.get("row_count"),
        date_range=date_range,
        update_frequency=stats_data.get("update_frequency"),
        additional=additional,
    )
```

### 技術的な考慮事項

- **後方互換性**: `additional` はデフォルト `{}` なので、既存 YAML（拡張統計項目なし）は `additional: {}` として返却される。既存テストへの影響なし
- **JSON シリアライズ**: `additional` は常に存在する（空 dict でも）。`exclude_none=True` の対象外。これは `key_types`（`None` 時に除外）とは異なる設計判断だが、API 仕様でレスポンスに `additional` が常に含まれる方が一貫性がある
- **値の型制約なし**: `dict[str, Any]` なので、数値・文字列・配列・ネストオブジェクト等を自由に格納可能。YAML の自然な型推論に従う
- **既知フィールドの定義**: `_KNOWN_STATISTICS_FIELDS` を定数として定義し、パースロジック内でハードコードを避ける

# タスク詳細: 4.1 document-server: key_types 対応

## 概要

カラムの結合キー種別（key_type）が、別カラムの値によって異なるケースに対応する。`key_types` フィールド（条件付きキー種別の配列）を `ColumnInfo` に追加し、`key_type`（単一）と排他的に使用できるようにする。

YAMLカタログ定義で以下の2パターンをサポートする：

```yaml
# パターン1：単一キー種別（既存）
key_type: "統合会員番号"

# パターン2：条件付きキー種別（新規）
key_types:
  - value: "統合会員番号"
    condition: "member_type = '正会員'"
  - value: "仮会員番号"
    condition: "member_type = '仮会員'"
  - value: "一般番号"
    condition: null  # デフォルトのキー種別（条件なし）
```

また、domain には2つのバリアントがある：
- マスタ参照型: `master_table`, `master_column`, `label_column`
- 固定値リスト型: `values` 配列（例: `["active", "inactive"]`）

| ファイル | 内容 |
|----------|------|
| `document-server/src/models.py` | `ConditionalKeyType` モデル追加、`ColumnInfo` に `key_types` フィールド追加、排他バリデーション |
| `document-server/src/catalog_loader.py` | `_parse_key_types()` ヘルパー追加、`_parse_column()` で key_types パース |
| `document-server/tests/test_models.py` | `ConditionalKeyType` / `ColumnInfo.key_types` のモデル単体テスト |

### 実装手順

1. **`models.py` にモデル追加**
   - `ConditionalKeyType(BaseModel)` を定義: `value: str`, `condition: str | None = None`（condition が null の場合はデフォルトのキー種別を表す）
   - `ColumnInfo` に `key_types: list[ConditionalKeyType] | None = None` を追加
   - `@model_validator` で `key_type` と `key_types` の排他チェックを実装（両方指定でエラー）

2. **`catalog_loader.py` のパース拡張**
   - `_parse_key_types(data: list[dict] | None) -> list[ConditionalKeyType] | None` ヘルパー追加
   - `_parse_column()` 内で `key_types` を `.get()` でパースし、`ColumnInfo` コンストラクタに渡す

3. **テスト用フィクスチャ追加（`conftest.py`）**
   - `SAMPLE_TABLE_FULL_YAML` に key_types を持つカラム定義を追加（既存の key_type カラムと共存させ、排他性を確認できるようにする）

4. **モデルテスト追加（`test_models.py`）**
   - `ConditionalKeyType` のインスタンス化テスト
   - `ColumnInfo` に key_types を設定したテスト
   - key_type と key_types の排他バリデーションテスト

5. **パーステスト追加（`test_catalog_loader.py`）**
   - key_types を含む YAML が正しくパースされるテスト
   - key_types なしの既存 YAML が影響を受けないテスト

6. **APIテスト追加（`test_tables_api.py`）**
   - POST /catalog/tables のレスポンスに key_types 配列が含まれるテスト

### 技術的な考慮事項

- **排他バリデーション**: Pydantic の `@model_validator(mode="after")` を使用して `key_type` と `key_types` の排他チェックを行う。既存の `_parse_domain()` パターンに倣い、`_parse_key_types()` を独立したヘルパー関数として実装する
- **後方互換性**: `key_types` はオプショナルフィールドのため、既存の YAML 定義は影響を受けない。既存テストも変更不要
- **JSON シリアライズ**: Pydantic の `model_dump(exclude_none=True)` により、key_types が None の場合はレスポンスに含まれない（既存の key_type と同様の動作）

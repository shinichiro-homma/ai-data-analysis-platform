# タスク詳細: 3.1 document-server 外部データ型カタログ対応

## 概要

DBにテーブルが存在しない外部データ（テナントマスタ等）のカタログ定義を `catalog/external/` ディレクトリから読み込み、既存のテーブルインデックス・詳細APIで返却できるようにする。

## 関連ドキュメント

- 要件定義: `docs/requirements/document-server.md` の「F1.1: テーブルインデックス」「F1.2: テーブル詳細」「AC」セクション
- API仕様: `docs/design/api-contracts.md` の「テーブル」セクション

## 実装計画

### 変更するファイル

| ファイル | 内容 |
|----------|------|
| `document-server/src/models.py` | `DataSource.type` を `Literal["postgresql", "csv", "external"]` に制約。`format`, `description` フィールド追加。`file_path` にパストラバーサル防止バリデータ追加。`max_length` を `BULK_REQUEST_MAX` 定数に抽出 |
| `document-server/src/catalog_loader.py` | `_load_external_tables` メソッド追加。`load_tables` で `catalog/external/` からも読み込み。`_load_resource` の戻り値型を `_TIdx`/`_TDetail` の2つの TypeVar に改善 |
| `document-server/data/sample/catalog/external/tenant_master.yaml` | サンプル外部データ定義（テナントマスタ） |

### 実装手順

1. `models.py` の `DataSource` モデルを拡張
   - `type` フィールドを `Literal["postgresql", "csv", "external"]` に変更
   - `format`, `description` フィールドを追加
   - `file_path` にパストラバーサル防止バリデータを追加
   - 一括取得リクエストの `max_length` を `BULK_REQUEST_MAX` 定数に抽出
2. `catalog_loader.py` の型安全性を改善
   - `_T` TypeVar を `_TIdx`/`_TDetail` の2つに分離
   - `_load_resource` の戻り値型を正確にする
3. `catalog_loader.py` に `_load_external_tables` メソッドを追加
   - `catalog/external/` ディレクトリ配下の YAML ファイルを読み込み
   - 各ファイルから `TableIndex` と `TableDetail` を生成
   - ディレクトリが存在しない場合はスキップ
4. `load_tables` メソッドで `_load_external_tables` の結果をマージ
5. サンプルデータとして `tenant_master.yaml` を作成

### 技術的な考慮事項

- `catalog/external/` は `DATA_DIR`（= `data/{DATA_ENV}`）配下に配置されるため、既存の環境分離（Phase 17）がそのまま適用される
- 外部テーブルは index.yaml を持たず、個別 YAML ファイルからインデックスと詳細の両方を生成する
- `_load_resource` とは別メソッドとして実装（外部テーブルは index/detail 分離構造を持たないため）

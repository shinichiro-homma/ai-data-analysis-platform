# タスク詳細: 2.2 用語の書き方ガイド作成

## 概要

`docs/guides/add-term.md` を他のガイド（`add-table.md`、`add-logic.md`）と同等の品質・構成に揃え、用語集への用語追加手順を完成させる。

現状、`add-term.md` は既に存在し aliases の書き方や各フィールドの説明が充実しているが、他の2ガイドと比較すると以下のセクションが不足している：

- 「概要」セクション（ガイドの目的・背景）
- 「前提条件」セクション
- 「動作確認」ステップ（curl コマンドによる検証）
- 「注意事項」セクション
- `values` の sub-field（`label`, `description`）の明示的な説明

## 関連ドキュメント

- 要件定義: `docs/requirements/document-server.md` の「F3: 用語情報取得」セクション（F3.1, F3.2）
- 既存ガイド: `docs/guides/add-table.md`（構成の参考）
- 既存ガイド: `docs/guides/add-logic.md`（構成の参考）
- 実データ: `document-server/data/glossary/` 配下の YAML ファイル

## 実装計画

### 変更するファイル

| ファイル | 内容 |
|----------|------|
| `docs/guides/add-term.md` | 既存ガイドの拡充・構成統一 |

### 実装手順

1. **「概要」セクションを冒頭に追加**
   - 用語集に登録する目的（AI が用語検索で正しい用語にマッチできるようにする）
   - `add-table.md` / `add-logic.md` と同様の書き出し

2. **「前提条件」セクションを追加**
   - Docker 環境起動済み
   - 追加する用語の定義・別名が決まっている

3. **「動作確認」ステップを手順の最後に追加**
   - `GET /glossary/index` でインデックスに表示されること
   - `GET /glossary/index?query={alias}` で aliases 検索がヒットすること
   - `POST /glossary/terms` で詳細が取得できること
   - curl コマンド例を記載

4. **「注意事項」セクションを末尾に追加**
   - name の一致（index.yaml の name、YAML ファイル名、YAML 内の name）
   - related_terms の参照先は index.yaml に存在する用語名を使うこと
   - aliases の重複（複数用語で同じ alias を使うと両方ヒットする）

5. **`values` フィールドの sub-field を明示的に説明**
   - 第2層フィールド表に `values[].label` と `values[].description` の説明を追加
   - またはフィールド表の下に補足として記載

6. **全体構成を他ガイドと統一**
   - セクション順序の調整（概要 → 前提条件 → ファイル構成 → 手順 → 各フィールドの説明 → aliases の書き方 → チェックリスト → 注意事項）

### 技術的な考慮事項

- 既存の aliases セクションは十分に充実しているため、大幅な変更は不要。構成の統一と不足セクションの追加が主な作業
- 実データ（`ロイヤルティランク.yaml`、`店舗.yaml`、`統合会員ID.yaml`）と矛盾しないことを確認する
- `add-table.md`（246行）、`add-logic.md`（203行）に対して `add-term.md`（123行）は簡潔すぎるため、動作確認・注意事項の追加で適切なボリュームにする

# タスク詳細: 1.1 PostgreSQL環境構築

## 概要

docker-compose にPostgreSQLサービスを追加し、カタログYAMLで定義しているテーブル（`id_pos_transactions`, `customer_master`）に対応するサンプルCSVデータを初期ロードする。

Phase 1（カタログ・用語集機能）の基盤となるタスク。ここで構築したPostgreSQLは、タスク 1.6 の結合テストで「カタログ参照 → SQL生成 → Jupyter実行」のE2Eフローに使用される。

### なぜこのタスクが必要か

- AIがカタログからテーブル情報（`data_source.type: postgresql`）を取得し、`pd.read_sql(...)` コードを生成してJupyterカーネルで実行する。そのための接続先PostgreSQLが必要
- jupyter-server の requirements.txt には `psycopg2-binary` が既に含まれているため、PostgreSQLコンテナを追加するだけでカーネルからDB接続が可能になる

### 実装手順

#### 1. PostgreSQL初期化スクリプト作成

`postgres/init/01-create-tables.sql`:

```sql
-- customer_master: 会員マスタ（カタログYAML定義に対応）
CREATE TABLE customer_master (
    member_id VARCHAR(16) PRIMARY KEY,
    customer_name VARCHAR(100) NOT NULL
);

-- id_pos_transactions: 購買履歴（カタログYAML定義に対応）
CREATE TABLE id_pos_transactions (
    transaction_id SERIAL PRIMARY KEY,
    customer_id VARCHAR(16) NOT NULL REFERENCES customer_master(member_id),
    transaction_date DATE NOT NULL,
    amount INTEGER NOT NULL,
    status VARCHAR(16) NOT NULL CHECK (status IN ('completed', 'cancelled', 'returned'))
);

-- インデックス
CREATE INDEX idx_transactions_customer ON id_pos_transactions(customer_id);
CREATE INDEX idx_transactions_date ON id_pos_transactions(transaction_date);
CREATE INDEX idx_transactions_status ON id_pos_transactions(status);
```

テーブルのカラムは `docs/requirements/document-server.md` のカタログYAML定義に準拠する。

#### 2. サンプルCSVデータ作成

カタログYAMLのexamplesやdomain定義に整合するデータを作成する。

- `customer_master.csv`: 20件（member_id: OT000xxxxx形式、customer_name: 日本語名）
- `id_pos_transactions.csv`: 200件（customer_id は customer_master を参照、status は completed/cancelled/returned、日付は 2024-2025年範囲）

#### 3. CSVロードスクリプト作成

`postgres/init/02-load-data.sh`:

```bash
#!/bin/bash
set -e

psql -v ON_ERROR_STOP=1 --username "$POSTGRES_USER" --dbname "$POSTGRES_DB" <<-EOSQL
    \COPY customer_master FROM '/tmp/data/customer_master.csv' CSV HEADER;
    \COPY id_pos_transactions(customer_id, transaction_date, amount, status) FROM '/tmp/data/id_pos_transactions.csv' CSV HEADER;
EOSQL
```

PostgreSQL公式イメージの `/docker-entrypoint-initdb.d/` を利用し、ファイル名の辞書順（01→02）で実行される。

#### 4. docker-compose.yml にPostgreSQLサービス追加

```yaml
services:
  postgres:
    image: postgres:16
    container_name: analysis-db
    environment:
      - POSTGRES_DB=${POSTGRES_DB:-analysis_db}
      - POSTGRES_USER=${POSTGRES_USER:-jupyter}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ../postgres/init:/docker-entrypoint-initdb.d
      - ../postgres/data:/tmp/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U jupyter -d analysis_db"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped

  jupyter-server:
    # 既存設定 + 以下を追加
    environment:
      - DATABASE_URL=postgresql://${POSTGRES_USER:-jupyter}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB:-analysis_db}
    depends_on:
      postgres:
        condition: service_healthy

volumes:
  postgres_data:
```

#### 5. 環境変数テンプレート更新

`.env.example` に追加:
```
POSTGRES_DB=analysis_db
POSTGRES_USER=jupyter
POSTGRES_PASSWORD=your-postgres-password-here
```

`.env` に開発用の値を設定:
```
POSTGRES_DB=analysis_db
POSTGRES_USER=jupyter
POSTGRES_PASSWORD=jupyter-dev-password
```

### 技術的な考慮事項

- **PostgreSQLバージョン**: 16を使用（最新安定版）
- **初期化の仕組み**: PostgreSQL公式イメージの `/docker-entrypoint-initdb.d/` を利用。初回起動時のみ実行される（`postgres_data` ボリュームが空の場合のみ）
- **データ永続化**: named volume (`postgres_data`) を使用。`docker-compose down` でもデータは保持される。完全リセットは `docker-compose down -v` で実行
- **ネットワーク**: docker-compose内部ネットワークで `postgres` というホスト名で接続可能。jupyter-serverからは `DATABASE_URL` 環境変数で接続先を参照
- **サンプルデータ量**: PoCフェーズとして20顧客 + 200トランザクション。実際の要件（1500万件）とは異なるが、機能検証には十分
- **document-serverとの関係**: document-serverはPostgreSQLに接続しない（YAMLカタログのみ）。PostgreSQL接続はJupyterカーネルの責務

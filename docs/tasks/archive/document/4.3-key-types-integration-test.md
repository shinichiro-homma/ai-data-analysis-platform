# タスク詳細: 4.3 条件付きkey_typesの結合テスト

## 概要

サンプルカタログに `key_types` 定義を持つカラムを追加し、document-server → document-mcp の一連のパイプラインで条件付きキー情報が正しく返却されることを結合テストで検証する。

タスク 4.1（document-server）・4.2（document-mcp）で実装した `key_types` 機能が、実際のサンプルデータを通じてエンドツーエンドで動作することを確認するためのタスク。

## 実装計画

### 作成・変更するファイル

| ファイル | 内容 |
|----------|------|
| `document-server/data/sample/catalog/tables/purchase_history.yaml` | `member_code` カラム（`key_types` 付き）を追加 |
| `document-mcp/tests/integration/catalog-integration.test.ts` | key_types 結合テストケースを追加 |

### 実装手順

1. **サンプルカタログに key_types 定義を追加**
   - `document-server/data/sample/catalog/tables/purchase_history.yaml` に `member_code` カラムを追加
   - `key_types` 配列として2つの条件付きキー種別を定義（要件定義の例に準拠）
   - 既存の `customer_id` カラム（`key_type` 単一）はそのまま維持し、混在パターンを確認可能にする

   ```yaml
   - name: member_code
     type: varchar(20)
     description: "会員コード（会員種別に応じて体系が異なる）"
     nullable: false
     key_types:
       - value: "統合会員番号"
         condition: "member_type = '正会員'"
       - value: "仮会員番号"
         condition: "member_type = '仮会員'"
     notes: |
       member_type カラムの値により、会員コード体系が異なる。
       正会員の場合は統合会員番号、仮会員の場合は仮会員番号として扱う。
   ```

2. **document-mcp 結合テストに key_types 検証を追加**
   - `catalog-integration.test.ts` の「カタログ参照フロー」describe ブロックにテストケースを追加
   - 既存の `handleToolCall("get_table_detail", ...)` パターンに従い、`purchase_history` を取得
   - `key_types` を持つ `member_code` カラムの検証
   - `key_type` のみの `customer_id` カラムとの混在検証

### 技術的な考慮事項

- **サンプルデータの変更は document-server の再起動で反映される**。結合テストは docker-compose 環境で実行するため、テスト実行前にサービスが最新データを読み込んでいる必要がある
- **既存テストへの影響**: `purchase_history` テーブルに新カラムを追加するため、既存テストでカラム数を固定値で検証している箇所がないか確認する
- **PostgreSQL テーブルとの不整合**: `member_code` カラムはカタログ定義にのみ存在し、PostgreSQL の `purchase_history` テーブルには存在しない。カタログはメタデータなのでこれは問題ないが、SQL 実行テストで `member_code` を SELECT しないよう注意

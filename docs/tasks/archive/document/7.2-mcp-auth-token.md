# タスク詳細: 7.2 document-mcp: 認証トークン付与

## 概要

document-mcp から document-server への全 HTTP リクエストに `Authorization: Bearer {token}` ヘッダーを付与する。トークンは環境変数 `DOCUMENT_SERVER_TOKEN` から読み込み、`DocumentServerClient` の axios インスタンスのデフォルトヘッダーに設定する。7.1 で実装済みの document-server 側の Bearer 認証を通過できるようにする。

## 関連ドキュメント

- 要件定義: `docs/requirements/document-mcp.md`（環境変数セクションの更新対象）
- 7.1 の計画: `docs/tasks/document/7.1-bearer-token-auth.md`（document-server 側の実装）
- セキュリティルール: `.claude/rules/security.md`（Bearer トークン付与パターン）
- 計画: `docs/plan/02-document.md` Phase 7

### 実装手順

1. **Red フェーズ: テストを先に書く**
   - `client.test.ts` に以下を追加:
     - `DOCUMENT_SERVER_TOKEN` が設定された状態で `new DocumentServerClient()` したとき、`axios.create` の引数 `headers.Authorization` に `Bearer {token}` が含まれること
     - `DOCUMENT_SERVER_TOKEN` が未設定の場合、コンストラクタが `Error` を投げること
   - 既存テスト（`client-term.test.ts` / `client-logic.test.ts`）の `beforeEach` でテスト用トークンを環境変数へ設定
   - `scripts/test.sh document-mcp` で Red を確認

2. **Green フェーズ: 実装**
   - `client.ts` の `DocumentServerClient` コンストラクタを修正:
     ```typescript
     const token = process.env.DOCUMENT_SERVER_TOKEN;
     if (!token) {
       throw new Error('DOCUMENT_SERVER_TOKEN 環境変数が設定されていません');
     }
     ```
   - `axios.create({ headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` } })` に変更
   - `scripts/test.sh --rebuild document-mcp` でテストパスを確認

3. **Refactor フェーズ**
   - `CLAUDE.md` / `docs/requirements/document-mcp.md` の環境変数テーブルを更新
   - ログにトークンが出力されていないことを確認（`logger.info('DocumentServerClient initialized')` は現状トークンを含まないが再確認）

### 技術的な考慮事項

- **環境変数未設定時の挙動**: jupyter-mcp / document-server と同じく、未設定ならインスタンス化時にエラー送出（シングルトン `getDocumentClient()` 経由で起動中止となる）。
- **機密情報のログ出力禁止**: トークン自体をログに出力しないこと（`.claude/rules/security.md`）。
- **テスト時の環境変数設定**: vitest の `tests/setup.ts` もしくは各テストファイルの `beforeEach` で `process.env.DOCUMENT_SERVER_TOKEN = 'test-token'` を設定する。既存 `setup.ts` を活用できるか確認する。
- **docker-compose での供給**: document-mcp は現状 docker-compose に含まれていない（ホスト側の MCP クライアントから起動）。`.env.example` には 7.1 で既に `DOCUMENT_SERVER_TOKEN=dev-document-token` が追加済みのため、MCP クライアント起動時にそれを読み込む構成にする。
- **統合テストでのトークン**: `tests/integration/` から document-server を直接叩いている箇所は、`DOCUMENT_SERVER_TOKEN` を参照して `Authorization` ヘッダーを付与する。
- **既存エラーハンドリングとの整合**: 401 レスポンスは既存の `handleError` → `DocumentClientError('HTTP_401', ..., 401)` に自然に落ちる。追加実装は不要。

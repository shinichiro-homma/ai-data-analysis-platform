# タスク詳細: 7.1 document-server: Bearer トークン認証の実装

## 概要

document-server の REST API に Bearer トークン認証を追加する。環境変数 `DOCUMENT_SERVER_TOKEN` で認証トークンを設定し、全エンドポイントで `Authorization: Bearer {token}` ヘッダーを検証する。無効なトークンや未設定リクエストは 401 で拒否する。

jupyter-server が `JUPYTER_TOKEN` 環境変数をもとに起動時に必須チェックを行っているパターンを踏襲する。

## 実装計画

### 作成するファイル

| ファイル | 内容 |
|----------|------|
| `document-server/src/auth.py` | FastAPI 依存関数 `verify_token` を定義。Authorization ヘッダーから Bearer トークンを抽出して検証する |
| `document-server/tests/test_auth.py` | 認証ミドルウェアのユニットテスト（401 系、200 系、`/health` 除外） |

### 変更するファイル

| ファイル | 変更内容 |
|----------|---------|
| `document-server/src/config.py` | `DOCUMENT_SERVER_TOKEN` 環境変数を読み込む。未設定ならモジュール import 時に `ValueError` を送出（起動中止） |
| `document-server/src/main.py` | `app = FastAPI(..., dependencies=[Depends(verify_token)])` で全ルートに認証を適用。`/health` は除外対象 |
| `document-server/tests/conftest.py` | テストクライアントで認証をバイパスする仕組み、または `Authorization` ヘッダー自動付与の `authed_client` フィクスチャを追加 |
| 既存テスト（`test_tables_api.py` / `test_terms_api.py` / `test_logic_api.py` / `test_health.py` / `test_config.py`） | 認証ヘッダー付きリクエストに変更、または `authed_client` フィクスチャへ差し替え |
| `docker-compose.yml` | `document-server` サービスに `DOCUMENT_SERVER_TOKEN=${DOCUMENT_SERVER_TOKEN}` を追加 |
| `.env.example` | `DOCUMENT_SERVER_TOKEN=dev-document-token` を追加 |
| `document-server/CLAUDE.md` | 環境変数テーブルに `DOCUMENT_SERVER_TOKEN` 追加 |

### 実装手順

1. **Red フェーズ: テストを先に書く**
   - `document-server/tests/test_auth.py` を新規作成:
     - `Authorization` ヘッダーなしリクエスト → 401
     - `Authorization: Bearer wrong-token` → 401
     - `Authorization: Bearer <correct>` → 200
     - `Authorization: invalid-format` （Bearer プレフィックスなし） → 401
     - `/health` はトークンなしでも 200
   - `conftest.py` に `authed_client` フィクスチャを追加（既存 `client` をそのまま使う既存テストの挙動を保つため、`client` も認証ヘッダー付きに変更する）
   - 既存テストの fixture を調整し、`scripts/test.sh document-server` で Red を確認

2. **Green フェーズ: 実装**
   - `src/config.py` に `DOCUMENT_SERVER_TOKEN` 読み込み・必須チェックを追加
   - `src/auth.py` に依存関数 `verify_token(authorization: str | None = Header(None))` を実装。`Bearer ` プレフィックス検証＋定数時間比較（`secrets.compare_digest`）
   - `src/main.py` の `FastAPI(...)` で `dependencies=[Depends(verify_token)]` を全体適用
   - `/health` は `dependencies=[]` で除外（またはルーター分離）
   - 環境変数未設定時はサーバー起動を中止（jupyter-server と同様）

3. **Refactor フェーズ**
   - conftest を整理し、DRY にする
   - `DOCUMENT_SERVER_TOKEN` を `.env.example` / `docker-compose.yml` へ反映

### 技術的な考慮事項

- **`/health` の認証除外**: Docker healthcheck が `curl -f http://localhost:3002/health` で叩くため、認証必須にすると healthcheck が落ちる。`/health` は必ず除外する。
- **定数時間比較**: トークン比較には `secrets.compare_digest` を使い、タイミング攻撃を回避する（`.claude/rules/security.md` 準拠）。
- **環境変数未設定時の挙動**: jupyter-server と同様、未設定なら起動中止（開発環境の事故防止）。テスト時は `conftest.py` で環境変数を設定してから `src.main` を import する。
- **テスト時の import 順序**: `config.py` が import 時に環境変数を読むため、`tests/conftest.py` の先頭（import 前）で `os.environ["DOCUMENT_SERVER_TOKEN"] = "test-token"` を設定する必要がある。
- **CORS ヘッダー**: 既に `Authorization` は `allow_headers` に含まれているため追加変更は不要。
- **エラー応答形式**: 401 のレスポンスボディは FastAPI 標準の `{"detail": "..."}` 形式で統一する。内部情報は含めない。
- **7.2 との関係**: 本タスクは document-server 側のみ。document-mcp クライアント側のトークン付与は 7.2 で実施するため、ローカル統合テストは 7.3 まで保留する。

## テスト計画

### ユニットテスト（`tests/test_auth.py`）

- 正常系
  - 正しいトークンで全エンドポイント（`/catalog/index`, `/glossary/index`, `/logic/index` 等）が 200
  - `/health` はトークンなしで 200
- 異常系
  - `Authorization` ヘッダーなし → 401
  - `Authorization: Bearer wrong` → 401
  - `Authorization: Basic xxx`（Bearer でない） → 401
  - `Authorization: Bearer `（空トークン） → 401

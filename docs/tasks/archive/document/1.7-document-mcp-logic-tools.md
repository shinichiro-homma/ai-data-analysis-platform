# タスク詳細: 1.7 document-mcp ロジックMCPツール実装

## 概要

document-mcp に既存ロジック（定型SQL/Python）参照用の3つのMCPツールを追加する。AIがデータ分析時に流用可能な既存ロジックを検索・確認・取得できるようにする。

- `get_logic_index` -- 全ロジックのインデックスを取得（第1層）
- `get_logic_detail` -- 指定ロジックのメタ情報を一括取得（第2層）
- `get_logic_code` -- 指定ロジックのコードファイルの中身を取得

前提タスク 1.6（document-server: ロジックAPI実装）は完了済み。

### 実装手順

#### ステップ1: 型定義の追加

`document-mcp/src/document-client/types.ts` に以下の型を追加:

```typescript
// ロジックインデックス
export interface LogicIndex {
  logic_name: string;
  summary: string;
  category: string;
}

export interface LogicIndexResponse {
  logic: LogicIndex[];
  total: number;
}

// ロジックメタ情報
export interface LogicMeta {
  logic_name: string;
  description: string;
  file_path: string;
  language: string;
  usage_type: string;
  input_tables: string[];
  output_description: string;
  usage_context: string;
  related_logic: string[];
  notes: string;
}

export interface LogicMetaResponse {
  logic: LogicMeta[];
  not_found: string[];
}

// ロジックコード
export interface LogicCode {
  logic_name: string;
  language: string;
  code: string;
}

export type LogicCodeResponse = LogicCode;
```

#### ステップ2: REST クライアントメソッドの追加

`document-mcp/src/document-client/client.ts` に3メソッドを追加:

- `getLogicIndex()` -- `GET /logic/index` → `LogicIndexResponse` を返却
- `getLogicMetas(logicNames: string[])` -- `POST /logic/meta` → `LogicMetaResponse` を返却
- `getLogicCode(logicName: string)` -- `GET /logic/code/${logicName}` → `LogicCodeResponse` を返却

既存の `getTableIndex()` / `getTermDetails()` と同パターン。

### 技術的な考慮事項

- **`get_logic_code` は単一文字列パラメータ**: テーブル・用語集の detail ツールは `string[]` 配列だが、`get_logic_code` は `logic_name: string` 単一値。これは要件定義に明記されており、コードファイルは1つずつ取得する設計。`validateStringParameter` を使用する。
- **2種類のエラーコード**: `get_logic_code` では `LOGIC_NOT_FOUND`（ロジック自体が存在しない）と `LOGIC_CODE_NOT_FOUND`（メタはあるがコードファイルがない）の2種類が返り得る。document-server 側で区別済みなので、`createErrorResponseFromError` でそのまま伝播する。
- **既存コードへの影響なし**: 新規ファイル追加 + 既存ファイルへの追記のみ。既存ツールのロジックは変更しない。

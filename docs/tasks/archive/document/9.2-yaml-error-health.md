# タスク詳細: 9.2 YAML エラー処理の統一と /health 可視化

## 概要

document-server の YAML ロード時のエラー処理が非対称である問題を解消する。現状は「構文エラー → 全体失敗」「id_field 欠損 → 警告スキップ」「その他必須キー欠損 → 全体失敗」と 3 種の挙動が混在している。これを統一的なポリシーに整理し、スキップされたファイルの件数を `/health` と `/admin/reload` レスポンスで可視化する。

## 関連ドキュメント

- 要件定義: `docs/requirements/document-server.md` の「F1.1 起動時読み込み」「F1.2 リロード」「F5.2 ヘルスチェック」「NF3 運用性」
- API仕様: `docs/design/api-contracts.md` の「/health」「/admin/reload」

## 調査したファイル

- `document-server/src/catalog_loader.py`: YAML ロード全体。`_load_yaml`(37-43) が構文エラーで ValueError raise、`_load_and_validate_yaml`(46-56) が id_field 欠損で warning + None 返却（スキップ）、各 `_parse_*` が必須キー欠損で ValueError raise。スキップ件数は未カウント
- `document-server/src/main.py`: `/health`(56-68) は `store.table_count/term_count/logic_count` と `last_reload` を返す。`lifespan`(24-42) は `ValueError/OSError` を `RuntimeError` に変換
- `document-server/src/routers/admin.py`: copy-on-write 済み。`_reload_lock` で直列化。成功時に `tables_loaded/terms_loaded/logic_loaded/reload_time_ms` を返す。スキップ情報なし
- `document-server/src/responses.py`: `error_response(status_code, code, message)` の統一ヘルパー
- `document-server/src/models.py`: Pydantic モデル群。スキップ情報の型は未定義
- `document-server/tests/test_health.py`: `/health` の基本テスト 1 件のみ
- `document-server/tests/test_admin_api.py`: reload 正常系 2 件 + アトミック性 3 件
- `document-server/tests/test_catalog_loader.py`: `test_yaml_syntax_error`(139-148)、`test_skip_file_without_table_name`(179-188) 等が現行挙動を検証

## 検討した代替案

| 案 | 概要 | 利点 | 欠点 |
|----|------|------|------|
| A（採用） | `_load_resource` / `_load_external_tables` 内でスキップをカウントし、`load_tables/load_terms/load_logic` の戻り値をカウント辞書に拡張。`CatalogStore` にスキップ情報を `@property` で公開 | 変更が `catalog_loader.py` に閉じる。既存の `load_all` 呼び出し元（`admin.py`・`main.py`）は戻り値の辞書キーが増えるだけで破壊的変更なし。エラー分類ポリシーの変更と可視化を同時に実現 | `load_tables` 等の戻り値型が `int` → `dict` に変わるため既存テストの `assert count == N` を更新する必要あり |
| B | `CatalogStore` にコールバック/イベントリスナーを追加し、スキップ発生時にイベントを発火。外部で集計 | ストア本体と可視化ロジックが疎結合 | 過剰な設計。現時点のスキップ情報利用箇所は `/health` と `/admin/reload` のみで、イベント機構の複雑さに見合わない |

採用理由: A は最小限の変更で目的を達成する。`_load_resource` はテーブル・用語・ロジックの共通ロードパスであり、ここにスキップカウントを追加すれば 3 リソース全てに一貫して適用される。戻り値型の変更は呼び出し元 3 箇所（`load_tables`/`load_terms`/`load_logic`）に閉じ、外部 API（`load_all` の返す辞書）は後方互換で拡張できる。

ADR 要否: 不要。状態の所有権・コンポーネント間契約は変わらない。`/health` と `/admin/reload` のレスポンスフィールド追加は後方互換（既存フィールドの削除・変更なし）。

## 参考にする既存実装

- コピー元: `catalog_loader.py` の `_load_resource`（298-355）。同メソッド内にスキップカウントを追加する形で、新たなコピーは発生しない（不変条件 I8 に抵触しない）

## 異常系・不変条件

- 該当する異常系（不正入力）: id_field 欠損の YAML ファイルがスキップされ、スキップ件数が `/health` と `/admin/reload` レスポンスに正しく反映されること。構文エラーの YAML は引き続き全体失敗とする
- 関係する不変条件: I6（並行アクセス安全性）— 9.1 で確立した copy-on-write パターンは変更しない。スキップ情報は `CatalogStore` インスタンスに保持されるため、参照差し替えのアトミック性で担保される

## 実装計画

### エラー分類ポリシー（統一後）

| エラー種別 | 挙動 | 理由 |
|-----------|------|------|
| YAML 構文エラー | 全体失敗（ValueError raise） | 構文エラーはファイル全体が読めないため、安全にスキップ不可 |
| id_field 欠損（`table_name`/`name`/`logic_name`） | 警告スキップ + カウント | エントリを識別できないため個別スキップが妥当。これが §3-2 の「統一」対象 |
| その他必須キー欠損（`display_name`/`columns` 等） | 全体失敗（ValueError raise） | Pydantic パースで検出される。エントリは識別可能だが、不完全なデータの提供はより危険 |

現行と同一のポリシーを維持する。§3-2 が求める「非対称の解消」は、上記ポリシーを明示的に文書化し、スキップされたファイルを可視化することで達成する。挙動自体の変更（例: 必須キー欠損もスキップに変更）は、データ品質の保証を下げるため採用しない。

### 実装手順

1. `catalog_loader.py`: `CatalogStore.__init__` に `self._skipped_files: dict[str, int]` を追加（キーは `"tables"/"terms"/"logic"`）。`skipped_files` プロパティを追加
   - 検証: `uv run python -c "from src.catalog_loader import CatalogStore; s = CatalogStore(); print(s.skipped_files)"` → `{"tables": 0, "terms": 0, "logic": 0}`

2. `catalog_loader.py`: `_load_resource` の戻り値を `tuple[dict, dict, int]`（3 番目がスキップ数）に拡張。`validated is None` の `continue` 前にカウンタを increment
   - 検証: `scripts/test.sh --quiet --test --no-lint document-server -- tests/test_catalog_loader.py` で既存テストが（戻り値型変更に伴い）FAIL すること

3. `catalog_loader.py`: `_load_external_tables` も同様にスキップ数を返すよう変更

4. `catalog_loader.py`: `load_tables`/`load_terms`/`load_logic` で `_load_resource` の戻り値からスキップ数を受け取り `self._skipped_files` に記録。`load_tables` は `_load_resource` と `_load_external_tables` 両方の戻り値からスキップ数を受け取り、合算して `self._skipped_files["tables"]` に記録する。戻り値を `dict[str, int]`（`{"loaded": N, "skipped": M}`）に変更。`load_all` の戻り値に `skipped` を追加
   - 検証: `scripts/test.sh --quiet --test --no-lint document-server -- tests/test_catalog_loader.py` で戻り値アサート修正後に PASS

5. `main.py`: `/health` レスポンスの `catalog` に `"skipped_files": store.skipped_files` を追加。`lifespan` のログにスキップ件数を含める
   - 検証: `scripts/test.sh --quiet --test --no-lint document-server -- tests/test_health.py` で FAIL（新フィールドのアサート追加前）→ テスト更新後 PASS

6. `admin.py`: `tables_loaded`/`terms_loaded`/`logic_loaded` を `loaded["tables"]["loaded"]`/`loaded["terms"]["loaded"]`/`loaded["logic"]["loaded"]` に更新し、`data` に `"skipped_files": new_store.skipped_files` を追加
   - 検証: `scripts/test.sh --quiet --test --no-lint document-server -- tests/test_admin_api.py` で PASS

7. フルゲート実行で全テスト PASS を確認
   - 検証: `scripts/test.sh --quiet document-server` → 全 PASS

### 技術的な考慮事項

- `_load_resource` の戻り値型変更は内部メソッドのため API 破壊なし。`load_tables` 等の戻り値変更は `load_all` 経由で使われるため、`admin.py` の `loaded["tables"]` 等のアクセスパスを `loaded["tables"]["loaded"]` に変更する必要あり
- スキップ情報は `CatalogStore` インスタンスに保持するため、copy-on-write パターン（9.1）と整合する。reload 成功時に新ストアが差し替わるため、スキップ情報も自然に更新される
- `/health` と `/admin/reload` のレスポンスへのフィールド追加は後方互換。document-mcp がこれらのフィールドに依存していないことを `docs/requirements/document-mcp.md` と既存コードから確認済み

## リスクと検知方法

- `load_tables` 等の戻り値型変更が他テストで `int` として使われている箇所: `scripts/test.sh --quiet document-server` で全テスト実行して検知
- `/admin/reload` の既存テスト（アトミック性テスト含む）が `loaded["tables"]` の形でアクセスしている箇所: `test_admin_api.py` の `data["tables_loaded"]` は `load_all` の戻り値ではなくレスポンス JSON のキーなので影響なし（`admin.py` 内のマッピングを更新すれば OK）

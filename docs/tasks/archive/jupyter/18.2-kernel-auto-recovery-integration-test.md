# タスク詳細: 18.2 カーネル自動復旧の結合テスト

## 概要

MCP 経由でコード実行中にカーネルをクラッシュさせ、自動復旧後に再実行が成功することを結合テストで検証する。タスク 18.1 で実装された `restart_dead_kernels = True` 設定と sandbox 再注入のラッパーが、実際の Docker 環境で正しく動作することを確認する。

### 技術的な考慮事項

- **カーネルクラッシュの再現方法**: `import os; os._exit(1)` を `execute_code` で実行する。これはカーネルプロセスを即座に終了させ、dead 状態にする。`execute_code` 自体はタイムアウトまたはエラーで返る
- **自動復旧の待機**: `restart_dead_kernels = True` による自動復旧は `cull_interval` に依存する（デフォルト: `max(60, KERNEL_TIMEOUT // 5)`）。テストではポーリングで kernel status が `idle` に戻るのを待機する。最大待機時間は 120 秒程度必要
- **カーネルステータスの確認**: `jupyterClient.getKernel(sessionId)` で kernel の `status` フィールドを確認する。クラッシュ直後は `dead`、復旧後は `idle` になる
- **変数状態のリセット**: カーネル再起動により実行状態（変数、import）は失われる。これは想定動作であり、テストで確認する
- **sandbox 再注入の検証**: 復旧後のカーネルでワークスペース外アクセスが `PermissionError` で拒否されることを確認する（`workspace-access-restriction.test.ts` と同様のパターン）
- **テストタイムアウト**: 自動復旧の待機を含むため、個別テストのタイムアウトを 180 秒（180000ms）に設定する

## テスト計画

### 結合テスト (`jupyter-mcp/tests/integration/kernel-crash-recovery.test.ts`)

**共通セットアップ** (`beforeAll`):
- `checkJupyterConnection()` で接続確認
- ワークスペース A を作成
- ワークスペース A にセッションを作成
- 初期コード実行（`x = 42; print(x)`）で正常動作を確認

**共通クリーンアップ** (`afterAll`):
- セッション、ワークスペースを削除

**ヘルパー関数**:
- `waitForKernelRecovery(sessionId, maxWaitMs)`: カーネルの status が `idle` になるまでポーリングする関数。`jupyterClient.getKernel()` を 3 秒間隔で呼び出し、`status === 'idle'` になるか最大待機時間を超えるまで繰り返す

#### テスト 1: カーネルクラッシュ後に自動復旧しコード実行が成功する

1. `execute_code` で `import os; os._exit(1)` を実行（タイムアウトまたはエラーで返る）
2. `waitForKernelRecovery()` でカーネルの自動復旧を待機
3. 復旧後に `execute_code` で `print("recovered")` を実行
4. `stdout` に `"recovered"` が含まれることを確認

#### テスト 2: 復旧後に変数状態がリセットされている

1. `execute_code` で `recovery_test_var = 123` を定義
2. `execute_code` で `import os; os._exit(1)` を実行してクラッシュ
3. `waitForKernelRecovery()` で復旧を待機
4. `execute_code` で `print(recovery_test_var)` を実行
5. `success === false` かつ `error.code === 'NameError'` であることを確認（変数がリセットされている）

#### テスト 3: 復旧後に sandbox が再注入されワークスペース外アクセスが拒否される

1. `execute_code` で `import os; os._exit(1)` を実行してクラッシュ
2. `waitForKernelRecovery()` で復旧を待機
3. ワークスペース外のパスへのファイルアクセスを試みるコードを実行
4. `stdout` に `PermissionError` が含まれることを確認

#### テスト 4: 明示的な再起動（POST /api/kernels/{id}/restart）後もコード実行が成功する

1. `jupyterClient.restartKernel(sessionId)` を呼び出して明示的に再起動
2. カーネルの準備完了を待機（ポーリング）
3. `execute_code` で `print("after restart")` を実行
4. `stdout` に `"after restart"` が含まれることを確認
5. ワークスペース外アクセスが `PermissionError` で拒否されることを確認

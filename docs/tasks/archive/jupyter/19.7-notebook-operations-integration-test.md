# タスク詳細: 19.7 ノートブック操作拡張の結合テスト

## 概要

Phase 19 で実装した全ノートブック操作ツール（19.1〜19.6）の統合テストを作成する。一括実行→結合→分割→タイプ変更→コピー→出力クリア→カーネル再起動→中断の一連フローが正しく動作することを確認する。

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyter-mcp.md` の「F3.2: セル操作」「F3.3: カーネル制御」セクション
- 受け入れ条件: `docs/requirements/jupyter-mcp.md` の「AC13: セル一括操作」「AC14: カーネル制御」

| `jupyter-mcp/tests/integration/notebook-operations.test.ts` | Phase 19 ノートブック操作拡張の統合テスト |

### 実装手順

1. `phase17-tools.test.ts` のパターンに倣い、テストファイルのボイラープレートを作成（import、describe、beforeAll/afterEach、createTestNotebook ヘルパー）

4. セクション C: notebook_change_cell_type / notebook_copy_cell の結合テストを実装
5. セクション D: notebook_clear_outputs の結合テストを実装
6. セクション E: kernel_restart の結合テストを実装
7. セクション F: KeyboardInterrupt レスポンスの結合テストを実装
8. セクション G: E2E フロー（全ツールを組み合わせた一連の操作）を実装
9. `scripts/test.sh --rebuild --integration jupyter-mcp` で全テスト通過を確認

| # | テスト | 確認内容 |

| A-2 | mode: up_to で指定セルまで実行 | cell_index 指定で、そこまでのセルのみ実行される |
| A-3 | mode: from で指定セル以降を実行 | cell_index 指定で、そこ以降のセルのみ実行される |
| A-4 | Markdown セルのスキップ | code/markdown 混在時に markdown がスキップされる |

#### G. E2E フロー

| # | テスト | 確認内容 |
|---|--------|----------|
| G-1 | Phase 19 ツール組み合わせフロー | セル追加→一括実行→結合→分割→タイプ変更→コピー→出力クリア→カーネル再起動→再実行の一連フロー |
| G-2 | 既存ツール + Phase 19 ツール混在フロー | セル追加→編集(Phase 16)→一括実行(Phase 19)→結合(Phase 19)→削除(Phase 16)→セル再実行(Phase 16)→出力クリア(Phase 19)の一連フロー。既存機能と新機能が組み合わせて正しく動作することを確認 |

### 技術的な考慮事項

- `phase17-tools.test.ts` と同じ構造（import パターン、createTestNotebook ヘルパー、afterEach クリーンアップ）を踏襲する
- 統合テストは singleFork（直列実行）で動作するため、テスト間の干渉は低いが、各テストで独立したワークスペース・セッションを作成する
- KeyboardInterrupt テスト（F-1, F-2）は `time.sleep()` の無限ループを使い、別途 `kernel_interrupt` で中断する。タイミングに注意が必要（実行開始を待ってから中断を送る）
- 個別テストのタイムアウトは 30000ms を基準とし、E2E フロー（G-1）は 60000ms に設定する

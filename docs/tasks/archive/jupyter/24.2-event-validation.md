# タスク詳細: 24.2 受信イベントの境界検証と手書き部分型の解消

## 概要

jupyterlab-ai-sync の不変条件 I4（プロセス境界を越えるデータは境界でランタイム検証する）違反を解消する。WebSocket 経由で受信するイベントの無検証キャストを zod スキーマによるランタイム検証に置換し、lock-manager の手書き部分型を `@jupyter/ydoc` の `ISharedNotebook` に置換する。

対象コンポーネント: jupyterlab-ai-sync
タスク種別: extension

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyterlab-ai-sync.md` の「F1: AI操作イベントの受信」「F1.2: イベント処理」
- 不変条件: `docs/design/invariants.md` の I4（プロセス境界を越えるデータは境界でランタイム検証する）

## 検討した代替案

| 案 | 概要 | 利点 | 欠点 |
|----|------|------|------|
| A（採用） | zod スキーマで interface を置換し、`handleEvent` 内で `safeParse` 検証 | DRY（スキーマが型定義と検証ロジックを兼ねる）。テスト容易（スキーマを純粋関数として検証可能）。I4 準拠 | zod 依存の追加（バンドルサイズ増）。interface の export が `z.infer<typeof ...>` に変わる差分 |
| B | 手動バリデーション関数（typeof / in チェック）を手書き。interface は維持 | 依存追加なし。バンドルサイズ変化なし | バリデーション関数と interface が二重管理で DRY 違反。フィールド追加時にメンテ漏れリスク |

採用理由: 案 A は zod の `z.infer` で型定義と検証ロジックを一体化でき、DRY を維持しつつ I4 を充足する。zod はフロントエンド拡張のバンドルサイズとして許容範囲（tree-shakeable、minified ~14KB）。案 B はフィールド追加時にバリデーション関数の更新漏れが起きやすく、I4 違反の再発リスクが高い。

ADR 要否: 不要。既存の I4 不変条件に従った実装方式の選択であり、新たなコンポーネント間契約・状態の所有権の変更はない。

## 参考にする既存実装

- コピー元: なし（zod スキーマ導入は jupyterlab-ai-sync で初。他コンポーネントの MCP サーバーで zod は使用済みだが、JupyterLab 拡張でのパターンは初回。I8 の共通化閾値に未到達）

## 異常系・不変条件

- 該当する異常系（不正入力）: 必須フィールド欠落・型不一致のイベントを受信した場合に、例外が伝播せず警告ログを出してスキップする。E2E テスト条件で検証
- 関係する不変条件: I4（プロセス境界を越えるデータは境界でランタイム検証する）。本タスクで既知違反を解消する

### 技術的な考慮事項

- `z.infer<typeof schema>` で生成される型は既存の interface と構造的に同一であるため、`handleNotebookChanged(event: NotebookChangedEvent)` 等のメソッドシグネチャは変更不要
- `AiEvent` 基底型（`websocket-client.ts`）は変更しない。検証は `handleEvent` 側で行うため、websocket-client の汎用性を維持する
- `@jupyter/ydoc` は `notebook-updater.ts` で既にインポート済みの推移的依存。`package.json` への明示追加は lock-manager での import が型チェックを通れば不要（通らなければ追加する）
- `fetchSyncState` の戻り値を `SyncStateResponse | null` に変更する場合、呼び出し元 `resync` メソッド（L348）と `setupSaveHook` メソッド（L422）の 2 箇所で null ガードが必要。いずれも同一ファイル内

## リスクと検知方法

- notebook-updater.ts の型エクスポート変更が他ファイルに影響する可能性: `grep -r 'NotebookChangedEvent\|CellExecuteStartEvent\|CellExecuteEndEvent\|LockAcquiredEvent\|LockReleasedEvent' jupyterlab-ai-sync/src/` で確認。これらの型は notebook-updater.ts 内でのみ使用されているため影響なし
- zod バンドルサイズ増加: JupyterLab 拡張はサーバーサイドレンダリングではなくブラウザロードのため、14KB 程度の増加は NF1（100ms 以内の反映）に影響しない
- `fetchSyncState` の戻り値変更: 同一ファイル内の `resync`（L348）と `setupSaveHook`（L422）が呼び出し元。型チェック（手順 5）で検知

# タスク詳細: 8.5 ロック中のセル実行無効化

## 概要

AI 編集モード（ロック中）に、Shift+Enter / Ctrl+Enter 等のキーボードショートカットによるセル実行を無効化する。

現在のロック実装（`lock-manager.ts`）では `editor.setOption('readOnly', true)` によるテキスト編集の無効化のみが実装されており、JupyterLab のコマンドシステム経由のセル実行（`notebook:run-cell-and-advance`、`notebook:run-cell` 等）は無効化されていない。要件定義 F3.1 の「セル実行を無効化する」を満たすために本タスクを実施する。

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyterlab-ai-sync.md`
  - F3.1: ロック開始（L60-63）— 「ユーザーのキーボード入力、セル編集、セル実行を無効化する」
  - F3.2: ロック解除（L65-68）— 「ユーザーの入力を再度有効化する」
  - AC3: ノートブックロック（L236-241）— 「ロック中はキーボード入力・セル編集ができない」

## 実装計画

### 変更するファイル

| ファイル | 内容 |
|----------|------|
| `jupyterlab-ai-sync/src/lock-manager.ts` | ロック/アンロック時にキーダウンイベントリスナーの追加/削除 |

### 実装手順

#### 1. lock-manager.ts にキーダウンイベントハンドラを追加

ロック中のノートブックパネルの `node` に対して、capture フェーズの `keydown` イベントリスナーを追加する。セル実行に関連するキーコンビネーションを検出した場合、`preventDefault()` + `stopPropagation()` でイベントを消費し、JupyterLab のコマンドシステムに到達させない。

**対象キーバインド:**
- `Shift+Enter` — `notebook:run-cell-and-advance`
- `Ctrl+Enter` / `Cmd+Enter` — `notebook:run-cell`
- `Alt+Enter` / `Option+Enter` — `notebook:run-cell-and-insert-below`

#### 2. lockNotebook() にイベントリスナー登録を追加

`setNotebookReadOnly(panel, true)` の後に、パネルの `node` に capture フェーズの `keydown` リスナーを登録する。リスナーのコールバック参照は `LockIndicator` に保持し、アンロック時に削除できるようにする。

#### 3. unlockNotebook() でイベントリスナーを削除

`setNotebookReadOnly(panel, false)` の後に、`LockIndicator` に保持したコールバック参照を使ってイベントリスナーを削除する。

### 技術的な考慮事項

- **capture フェーズで処理する理由**: JupyterLab のキーバインドシステムは `keydown` の bubble フェーズで動作するため、capture フェーズでイベントを消費することで確実にコマンド実行を防げる
- **app.commands による方法を採用しない理由**: JupyterLab 4.x では既存のビルトインコマンドを外部から `isEnabled` で条件付き無効化する公式 API が存在しない。`addKeyBinding` で上書きする方法もあるが、キーバインドの優先度管理が複雑になる。capture フェーズのイベントリスナーが最もシンプルかつ確実
- **ツールバーの Run ボタン**: ツールバーボタンも JupyterLab コマンドシステム経由で `notebook:run-cell` を呼び出すが、ボタンクリックはキーダウンイベントではないため、本実装では対象外。ただし `readOnly` 状態のセルの実行結果はユーザーに混乱を与える可能性があるため、将来的にボタン無効化も検討する価値がある

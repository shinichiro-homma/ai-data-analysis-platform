# タスク詳細: 10.3 画像ファイル永続化の結合テスト

## 概要

Phase 10 で変更した画像ファイル永続化機能（10.1: jupyter-server 側ファイル保存、10.2: jupyter-mcp ImageStore ファイルベース化）の結合テストを作成する。

既存テストの調査結果から、基本的な file_path 形式検証と AI 同期イベント検証は既にカバーされているが、**ワークスペースを使ったファイルシステム永続化の検証**（file_list での実ファイル存在確認、複数回実行でのファイル名衝突回避）が不足している。本タスクではこの不足分を補完する。

### 実装手順

#### ステップ 1: 結合テストファイルの新規作成

`jupyter-mcp/tests/integration/image-file-persistence.test.ts` を作成する。

既存の結合テストパターン（`workspace-isolation.test.ts` を参考）に従い、以下の構成とする：
- `beforeAll`: `checkJupyterConnection()` で疎通確認
- `afterEach`: セッション・ワークスペースのクリーンアップ（`cleanupWorkspace` 使用）
- テストケースごとにワークスペース作成 → セッション作成 → グラフ描画 → 検証

#### ステップ 2: テストケースの実装

以下の 3 テストケースを実装する：

**テスト 1: グラフ描画→ file_list で画像ファイルの存在を確認**
1. ワークスペース作成（`workspace_create`）
2. セッション作成（`session_create` with `workspace_id`）
3. matplotlib グラフ描画コード実行（`execute_code`）
4. レスポンスの `images[0].file_path` に `workspace_id` が含まれることを検証
5. `file_list`（`workspace_id`, `path: "output"`）で output/ ディレクトリのファイル一覧を取得
6. 返却された file_path のファイル名が file_list の結果に含まれることを検証

**テスト 2: 複数回実行でファイル名が衝突しない**
1. ワークスペース・セッション作成
2. 1 回目のグラフ描画 → `exec-{N}-img-001.png` の N を記録
3. 2 回目のグラフ描画 → `exec-{M}-img-001.png` の M を記録（M ≠ N）
4. file_list で 2 つのファイルが両方存在することを検証

**テスト 3: 複数グラフ + file_list で全ファイル存在確認**
1. ワークスペース・セッション作成
2. 1 回の execute_code で 2 つのグラフを描画
3. images 配列の全 file_path について file_list で存在確認
4. 各ファイル名が異なることを検証

#### ステップ 3: テスト実行

```bash
scripts/test.sh jupyter-mcp
```

### 技術的な考慮事項

- **既存テストとの棲み分け**: 既にカバーされている検証（file_path 形式、base64 排除、AI 同期イベント）は新テストに含めない。新テストはファイルシステム永続化の実証（file_list での確認）に特化する
- **ワークスペース必須**: 全テストでワークスペースを作成して使用する。ワークスペースなしだと画像ファイル保存がスキップされるため
- **テスト直列実行**: `vitest.config.integration.ts` で `singleFork: true` が設定されているため、テストは直列実行される
- **クリーンアップ**: `cleanupWorkspace` でワークスペースごと削除すれば output/ のファイルも一緒に削除される
- **タイムアウト**: matplotlib のインポートは初回が遅いため、最初のテストケースは 60 秒タイムアウトを設定する
- **参考実装**: `workspace-isolation.test.ts` のテスト 6（L364-450）が output/ ディレクトリへのファイル書き込み + file_list 確認のパターンとしてそのまま流用可能

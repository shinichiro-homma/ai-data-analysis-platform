# タスク詳細: 17.4 MCPツール追加の結合テスト

## 概要

Phase 17 で実装した3ツール（notebook_reorder_cell, data_preview, file_read）の結合テストを作成する。各ツールがワークスペース内で正しく動作し、ツール間の連携フロー（データ作成→プレビュー→ファイル読み取り等）が機能することを検証する。

- タスク計画: `docs/tasks/jupyter/17.1-cell-reorder.md`、`docs/tasks/jupyter/17.2-data-preview.md`、`docs/tasks/jupyter/17.3-file-read.md`
- 類似テスト: `jupyter-mcp/tests/integration/cell-operations.test.ts`、`jupyter-mcp/tests/integration/export-sql.test.ts`

### 実装手順

1. **テストファイルの作成**
   - `jupyter-mcp/tests/integration/phase17-tools.test.ts` を新規作成
   - 既存の結合テストパターン（`cell-operations.test.ts`, `export-sql.test.ts`）を踏襲
   - `handleToolCall` を使用した MCP ツール直接呼び出し方式

2. **テストヘルパーの作成**
   - `createTestEnvironment` ヘルパー: ワークスペース作成 + セッション作成 + ノートブック作成を一括で行う
   - 既存の `setup.ts` の `checkJupyterConnection`, `cleanupSession`, `cleanupWorkspace`, `parseToolCallResult` を使用

3. **セクション A: notebook_reorder_cell テスト**
   - セル追加（3つ）→ 並び替え → list_cells で順序確認
   - 先頭セルを末尾へ移動、末尾セルを先頭へ移動のパターン
   - 範囲外インデックスでのエラーハンドリング

4. **セクション B: data_preview テスト**
   - execute_code で CSV を data/ に作成 → data_preview でプレビュー取得
   - export_sql で Parquet を data/ に保存 → data_preview でプレビュー取得
   - head_rows パラメータの動作確認
   - 存在しないファイルでのエラーハンドリング
   - パストラバーサル攻撃の拒否

5. **セクション C: file_read テスト**
   - execute_code でテキストファイル（.py, .md）をワークスペースに作成 → file_read で読み取り
   - execute_sql で .sql ファイルが queries/ に保存される → file_read で読み取り
   - .ipynb ファイル指定時のエラー（VALIDATION_ERROR）
   - 存在しないファイルでのエラー
   - パストラバーサル攻撃の拒否

6. **セクション D: ツール連携 E2E フロー**
   - ノートブック作成 → セル追加 → 並び替え → コード実行（CSV出力）→ data_preview → file_read の一連フロー

7. **テスト実行・確認**
   - `scripts/test.sh --integration --rebuild jupyter-mcp` でテスト実行

### 技術的な考慮事項

#### 1. テストデータの作成方法

- CSV/Parquet ファイルは `execute_code` で pandas を使って作成するか、`export_sql` で DB からエクスポートする
- テキストファイルは `execute_code` で Python の `open()` を使って作成する
- これにより、テストが Docker 環境内で完結する

#### 2. ワークスペース分離

- 各 describe ブロックまたはテストごとに独立したワークスペースを作成し、テスト間の状態汚染を防止する
- afterEach でセッションとワークスペースをクリーンアップする

#### 3. data_preview のデータ準備

- data_preview は `workspace_id` + `file_path` でアクセスするため、ファイルがワークスペースの `data/` 配下に存在する必要がある
- `execute_code` で `data/test.csv` に書き込むか、`export_sql` で `data/` に保存する

#### 4. file_read のファイル準備

- file_read は `workspace_id` + `file_path` でアクセスする
- `execute_code` でワークスペース内にテキストファイルを作成する
- `execute_sql` 実行後に `data/queries/` に保存される .sql ファイルも対象

#### 5. タイムアウト設定

- コード実行を伴うテストは `15000`〜`20000` ms のタイムアウトを設定する（既存パターンに倣う）
- DB 接続を伴うテスト（export_sql 経由）はさらに長めに設定する

## テスト計画

### A. notebook_reorder_cell 結合テスト

- A-1: セル3つ追加 → 先頭セル（index=0）を末尾（to_index=2）に移動 → list_cells で順序確認
- A-2: セル3つ追加 → 末尾セル（index=2）を先頭（to_index=0）に移動 → list_cells で順序確認
- A-3: 範囲外 cell_index で reorder → エラー

### B. data_preview 結合テスト

- B-1: execute_code で CSV を data/ に作成 → data_preview でカラム名・型・先頭行を確認
- B-2: export_sql で Parquet を data/ に保存 → data_preview で構造確認
- B-3: head_rows=2 指定で先頭行数が制限されることを確認
- B-4: 存在しないファイルパス → エラー
- B-5: パストラバーサル（`../etc/passwd`）→ VALIDATION_ERROR

### C. file_read 結合テスト

- C-1: execute_code で .py ファイルをワークスペースに作成 → file_read で内容取得
- C-2: execute_sql 後に data/queries/ の .sql ファイルを file_read で読み取り
- C-3: .ipynb ファイル指定 → VALIDATION_ERROR
- C-4: 存在しないファイル → エラー
- C-5: パストラバーサル（`../etc/passwd`）→ VALIDATION_ERROR

### D. ツール連携 E2E フロー

- D-1: ノートブック作成 → セル3つ追加（コメント用 markdown + CSV出力コード + 分析コード）→ reorder でコード順序変更 → execute_code で CSV 作成 → data_preview でプレビュー → file_read で .py ファイル読み取り

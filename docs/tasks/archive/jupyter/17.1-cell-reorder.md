### 実装手順

1. **API仕様の追記**
   - `docs/design/api-contracts.md` の `PATCH /api/custom/contents/{path}/cells` セクションに `reorder` アクションのリクエスト形式を追記
   - リクエスト形式: `{ "action": "reorder", "index": <移動元>, "to_index": <移動先> }`

2. **jupyter-server: reorder アクションの実装**
   - `ContentsCellsHandler.patch` の action 分岐に `reorder` を追加
   - `index`（移動元）と `to_index`（移動先）のバリデーション（0 以上、セル数未満）
   - セルを `index` から取り出し（`pop`）、`to_index` に挿入（`insert`）
   - ノートブックを保存

3. **jupyter-mcp: 型定義の拡張**
   - `types.ts` の `CellAction` に `'reorder'` を追加
   - `CellOperationRequest` に `to_index?: number` フィールドを追加

4. **jupyter-mcp: notebook_reorder_cell ツール実装**
   - `notebook_path`（必須）、`cell_index`（必須、移動元）、`to_index`（必須、移動先）のバリデーション
   - パストラバーサル対策（`normalizeNotebookPath`）
   - `jupyterClient.operateCell()` を `action: 'reorder'` で呼び出し
   - 成功レスポンスに `notebook_path`, `from_index`, `to_index` を含める

5. **jupyter-mcp: ツール登録**
   - `index.ts` に `notebook_reorder_cell` のインポートとツール定義を追加
   - ツール定義: `notebook_path`, `cell_index`, `to_index` の3パラメータ

6. **テスト作成・実行**

### 技術的な考慮事項

#### 1. reorder のアルゴリズム

Python の `list.pop(index)` + `list.insert(to_index, cell)` で実現する。`pop` で要素を取り出した後のリストに対して `insert` するため、`to_index` は取り出し後のリストのインデックスとして解釈される。これは直感的な「移動先の位置」に対応する。

#### 2. to_index のバリデーション範囲

- `index`（移動元）: `0 <= index < len(cells)` — 既存セルの位置
- `to_index`（移動先）: `0 <= to_index < len(cells)` — pop 後のリストへの挿入位置。`len(cells) - 1` が最大値（pop でリストが1つ短くなるため）

#### 3. index == to_index の場合

移動元と移動先が同じ場合はノーオプ（no-op）として正常終了する。エラーにはしない。

#### 4. 既存パターンの踏襲

- バリデーション: `validateStringParameter`, `validateCellIndex` を使用（`notebook-delete-cell.ts` と同一パターン）
- `to_index` のバリデーション: `validateCellIndex` を再利用（0以上の整数チェック）
- パス検証: `normalizeNotebookPath` を使用
- レスポンス: `createSuccessResponse` / `createErrorResponse` を使用
- エラーコード抽出: `extractErrorCode` / `extractErrorMessage` を使用

#### 5. AI同期イベント

本タスクでは REST API でのディスク書き込みを優先する。AI同期イベントの `cell_reordered` タイプの追加は、既存のセル操作イベント（`cell_added` 等）のパターンに倣い、必要に応じてタスク内で判断する。

#### 6. body パラメータ名

API 側のパラメータ名は `to_index` とし、MCP ツール側も `to_index` とする。`index` は移動元（既存の `PATCH` アクションと同じフィールド名）、`to_index` は移動先を表す。

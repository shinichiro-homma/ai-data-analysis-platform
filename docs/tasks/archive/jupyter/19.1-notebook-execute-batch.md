# タスク詳細: 19.1 セル一括実行

## 概要

`notebook_execute_batch` で全セル / ここまで / これ以降の一括実行ができる機能を実装する。jupyter-server に REST API（POST /cells/execute-batch）、jupyter-mcp に MCP ツール（notebook_execute_batch）を追加する。

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyter-server.md` の「F3.3: セル操作」セクション
- 要件定義: `docs/requirements/jupyter-mcp.md` の「F3.2: セル操作」「notebook_execute_batch」セクション
- API仕様: `docs/design/api-contracts.md` の「POST /api/custom/contents/{path}/cells/execute-batch」セクション

### 実装手順

#### 1. jupyter-server: ContentsCellExecuteBatchHandler 実装

`handlers.py` に新規ハンドラクラスを追加する。既存の `ContentsCellExecuteHandler`（888-1053行）をベースとする。

**処理フロー:**
1. `validate_path(path)` でパストラバーサル対策
2. `.ipynb` 拡張子チェック
3. `get_json_body()` で `kernel_id`（必須）、`mode`（必須: all/up_to/from）、`cell_index`（mode が up_to/from の場合に必須）、`timeout`（オプション）を取得
4. mode バリデーション: `all`, `up_to`, `from` のいずれかであること
5. `check_kernel_exists(kernel_id)` でカーネル存在確認
6. `contents_manager.get(path, content=True)` でノートブック読み込み
7. セル一覧取得 + 実行範囲の決定:
   - `all`: 全セル（0 から末尾まで）
   - `up_to`: 0 から cell_index まで（inclusive）
   - `from`: cell_index から末尾まで（inclusive）
8. cell_index の範囲チェック（up_to/from の場合）
9. 実行対象セルをループ:
   - Markdown セルはスキップ
   - コードセルのみ `validate_code()` + `KernelExecutor.execute()` で実行
   - 各セルの `outputs` と `execution_count` を更新
   - エラー発生時は実行を停止し、失敗セルの情報を記録
10. ノートブックを保存（`contents_manager.save()`）
11. レスポンス: `{ executed_cells, success_count, failed_cell }`

**ルーティング登録:**
`get_handlers()` で `/cells/([0-9]+)/execute` の後、`/cells` の前に挿入:
```python
(f"{base_url}/api/custom/contents/(.*)/cells/execute-batch", ContentsCellExecuteBatchHandler),
```

#### 2. jupyter-mcp: 型定義追加

`types.ts` に追加:
- `CellExecuteBatchRequest`: `{ kernel_id: string; mode: 'all' | 'up_to' | 'from'; cell_index?: number; timeout?: number }`
- `CellExecuteBatchResponse`: `{ executed_cells: number; success_count: number; failed_cell: number | null }`

#### 3. jupyter-mcp: クライアントメソッド追加

`client.ts` に `executeBatchCells(path, options)` メソッドを追加。
エンドポイント: `POST /api/custom/contents/${encodeURIComponent(path)}/cells/execute-batch`

#### 4. jupyter-mcp: notebook_execute_batch ツール実装

`notebook-execute-batch.ts` を新規作成。`notebook-execute-cell.ts` をテンプレートとする。

**パラメータ:**
- `notebook_path`（必須）: ノートブックのパス
- `session_id`（必須）: セッションID
- `mode`（必須）: 実行モード（all / up_to / from）
- `cell_index`（オプション）: 基準セルインデックス（up_to/from の場合に必須）
- `timeout`（オプション）: セルあたりのタイムアウト秒数

**処理フロー:**
1. パラメータバリデーション（validateAndNormalizeNotebookPath, validateStringParameter, mode enum チェック, cell_index の条件付き必須チェック）
2. `resolveSession(sessionId)` で kernelId 解決
3. `jupyterClient.executeBatchCells()` で一括実行
4. `createSuccessResponse()` で結果返却

**AI同期イベント:**
- handleToolCall ミドルウェアによる自動ロック制御（NOTEBOOK_EDIT_TOOLS に追加）
- 個別セルの execute_start/output/end イベントは jupyter-server 側での一括実行中にリアルタイム配信されるため、MCP ツール側での個別イベント配信は不要（一括実行は REST API 1回の呼び出しで完結するため）

#### 5. jupyter-mcp: ツール登録

`index.ts` で:
- `executeNotebookExecuteBatch` をインポート
- `toolRegistry` にツール定義を追加
- `NOTEBOOK_EDIT_TOOLS` に `'notebook_execute_batch'` を追加

### 技術的な考慮事項

- **エラー時の停止**: 要件により途中セルでエラー発生時は以降のセルは実行しない。failed_cell にエラーセルのインデックスを返す
- **Markdown セルのスキップ**: `cell_type == "code"` のセルのみ実行対象。スキップしたセルは executed_cells のカウントに含めない
- **ノートブック保存タイミング**: 各セル実行後ではなく、全セル実行完了後（またはエラー停止後）に1回だけ保存する（パフォーマンス考慮）
- **AI同期イベント**: 一括実行は1回の REST API 呼び出しで完結するため、MCP ツール側での個別セルイベント配信は行わない。リアルタイム同期が必要な場合は、jupyter-server 側で各セル実行時にイベントを配信する設計を検討する（Phase 19.7 結合テストで確認）
- **ルーティング順序**: Tornado のルーティングは先頭一致のため、`/cells/execute-batch` を `/cells` より前に登録する

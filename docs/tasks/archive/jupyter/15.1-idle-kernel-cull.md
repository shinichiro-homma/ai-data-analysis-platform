# タスク詳細: 15.1 アイドルカーネル自動停止

## 概要

長時間アイドル状態のカーネルを自動シャットダウンし、メモリ圧迫を防止する。
Jupyter Server 標準の `MappingKernelManager.cull_*` 設定を利用し、独自実装は行わない。

## 背景

- Python カーネルが無期限に生存し続け、メモリを圧迫している（5カーネルで 6.5GB の実績あり）
- 要件定義 NF3 に「30分アイドルシャットダウン」と記載されているが未実装
- `KERNEL_TIMEOUT=1800` は docker-compose.yml に設定済みだが、どこにも参照されていない

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyter-server.md` の「NF3: 可用性」セクション
- 要件定義: `docs/requirements/jupyter-server.md` の「環境変数」テーブル（KERNEL_TIMEOUT 行）

## 安全性の担保

| リスク | 対策 |
|--------|------|
| ブラウザで開いているカーネルが停止 | `cull_connected=False`（デフォルト）: WebSocket 接続中は対象外 |
| 実行中のカーネルが停止 | `cull_busy=False`（デフォルト）: busy 状態は対象外 |
| MCP 経由でアクティブなカーネルが停止 | コード実行時の IOPub メッセージで `last_activity` が自動更新されるため保護される |
| 未保存のノートブック編集が失われる | JupyterLab の autosave（デフォルト120秒）で定期保存済み |

## 実装計画

### 変更するファイル

| ファイル | 内容 |
|----------|------|
| `jupyter-server/jupyter_config/jupyter_server_config.py` | cull 設定を追加（KERNEL_TIMEOUT 環境変数を参照） |
| `jupyter-server/extensions/custom_api/__init__.py` | culler による shutdown_kernel 時のクリーンアップフック追加 |
| `docs/requirements/jupyter-server.md` | NF3 セクションと KERNEL_TIMEOUT 実装状況を更新 |

### 変更しないファイル

| ファイル | 理由 |
|----------|------|
| `docker-compose.yml` | `KERNEL_TIMEOUT=1800` は既に設定済み |
| `handlers.py` / `kernel_executor.py` | IOPub メッセージで `last_activity` は自動更新される |
| `session_handlers.py` | `unregister_kernel` は既に定義済み、変更不要 |

### 実装手順

1. `jupyter_server_config.py` に cull 設定を追加
   - `KERNEL_TIMEOUT` 環境変数を読み取り（デフォルト 1800 秒）
   - `cull_idle_timeout`, `cull_interval` を設定
   - `cull_connected=False`, `cull_busy=False` はデフォルト値のまま（明示的には設定しない）

2. `__init__.py` に culler 時のクリーンアップフックを追加
   - `shutdown_kernel` をラップし、`unregister_kernel()` を呼び出す
   - `unregister_kernel` は冪等（`.pop(key, None)`）なので重複呼び出しに安全

3. `docs/requirements/jupyter-server.md` のドキュメントを更新
   - NF3「Phase未着手」→ 実装済みの内容を記載
   - KERNEL_TIMEOUT 行を「実装済み」に更新

### 技術的な考慮事項

- Jupyter の culler は `shutdown_kernel()` を直接呼ぶため、カスタム API ハンドラー（`KernelHandler.delete`）を経由しない。`_kernel_workspace_map` と `_kernel_image_counters` のクリーンアップが行われないため、`__init__.py` でフックする必要がある
- `unregister_kernel` は既に冪等に実装されているため、通常の DELETE API 経由 + culler 経由の二重呼び出しでも問題ない

## テスト計画

### テスト用設定

- `KERNEL_TIMEOUT=60`（1分）に設定して短時間で cull 動作を確認する

### 注意事項

- **ワークスペースは一切削除しない**。`rebuild.sh` を使い、`jupyter_work` ボリュームを保持する
- `clean-rebuild.sh` は使用しない

### 手順

1. `scripts/test.sh --rebuild jupyter-server` でリビルド＆テスト（既存テストが通ることを確認）
2. `KERNEL_TIMEOUT=60` に一時変更してコンテナを再起動
3. カーネルを作成し、idle 状態で放置 → 約1〜2分後に自動停止されることを確認
4. JupyterLab UI で開いているカーネルが停止されないことを確認
5. 確認後、`KERNEL_TIMEOUT=1800` に戻す

# タスク詳細: 19.6 カーネル中断（AI編集ロック貫通）

## 概要

カーネル中断時に AI エージェントが中断を判別できるようにする。`execute_code` は既に `KeyboardInterrupt` を MCP レスポンスに含めて返すが、`notebook_execute_cell` / `notebook_execute_batch` では KeyboardInterrupt の情報が欠落している可能性がある。これを修正する。

**設計方針**:
- kernel_interrupt MCPツールは作成しない（MCP はリクエスト-レスポンス型のため、AI が実行待機中に別ツールを呼べない）
- 中断はユーザーが JupyterLab UI の中断ボタンから行う（標準の interrupt API 経由）
- AI編集ロック中でも中断ボタンは有効（UI 側で既に実現済み）

## 実装計画

### 変更概要

| コンポーネント | 変更内容 |
|--------------|---------|
| jupyter-server | 変更不要（interrupt API 既存、ロック機構なし） |
| jupyter-mcp | `notebook_execute_cell` / `notebook_execute_batch` で KeyboardInterrupt 情報を MCP レスポンスに含める |
| jupyterlab-ai-sync | 変更不要（ツールバーボタンは無効化されていないため、中断ボタンは既にロック中でも有効） |

### 現状の KeyboardInterrupt 対応状況

| ツール | KeyboardInterrupt が MCP レスポンスに含まれるか |
|--------|------|
| `execute_code` | 含まれる（`error.code: "KeyboardInterrupt"`）— 対応済み |
| `notebook_execute_cell` | 要確認・修正（含まれない可能性あり） |
| `notebook_execute_batch` | 要確認・修正（`failed_cell` として記録されるがエラー種別が欠落する可能性あり） |

### 実装手順

#### 1. 調査フェーズ

1. `notebook_execute_cell` / `notebook_execute_batch` の実装を読み、KeyboardInterrupt 発生時のレスポンス構造を実際に確認
2. 修正が必要な箇所を特定

#### 2. Red フェーズ（テスト作成）

3. `notebook_execute_cell` / `notebook_execute_batch` のテストに KeyboardInterrupt 検知テストケースを追加

#### 3. Green フェーズ（実装）

4. KeyboardInterrupt 情報が MCP レスポンスに含まれるよう修正

### 技術的な考慮事項

- **execute_code との差異**: `execute_code` は `kernel_executor.py` 経由で `error.type: "KeyboardInterrupt"` を受け取るが、`notebook_execute_cell` / `notebook_execute_batch` は異なる API パス（`ContentsCellExecuteHandler`）を使うため、エラー情報の伝搬が異なる可能性
- **AI編集ロックの仕組み**: ロックは UI 側（jupyterlab-ai-sync の LockManager）のみで実現。jupyter-server にはロック機構がない（リクエスト元が AI か ユーザーか判別できないためサーバー側ロックは不可能）

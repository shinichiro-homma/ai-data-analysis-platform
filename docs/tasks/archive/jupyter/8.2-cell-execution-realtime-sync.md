# タスク詳細: 8.2 セル実行のリアルタイム同期

## 概要

AIが `execute_code` ツールを呼んだ際に、ブラウザで開いている JupyterLab 上のノートブックにセル実行結果（stdout/stderr、画像、エラー）がリアルタイムに表示される機能を実装する。

このタスクでは以下の3つのコンポーネントを変更する：

1. **jupyter-server**: コード実行中のIOPubメッセージをリアルタイムでAI同期WebSocketに配信する機能を追加
2. **jupyter-mcp**: `execute_code` ツールからセル実行イベント（start/output/end）を配信する連携を追加
3. **jupyterlab-ai-sync**: `cell_execute_start`/`cell_output`/`cell_execute_end` イベントの処理を追加

これにより「AIがコードを実行 → ブラウザ上のセルに結果がストリーミング表示される」という結合テスト可能な機能が完成する。

## なぜこのタスクが必要か

タスク8.1でセル追加のリアルタイム同期は実現したが、`execute_code` の実行結果はブラウザ上のノートブックには反映されない。ユーザーがブラウザでノートブックを見ていても、AIが実行したコードの出力を確認するにはリロードが必要。本タスクにより、AIの分析操作がブラウザ上でリアルタイムに可視化され、ユーザー体験が大幅に向上する。

### 実装手順

#### Step 1: jupyter-server のコード実行時イベント配信

**目標:** `POST /api/kernels/{id}/execute` の実行中に、カーネルからのIOPubメッセージをリアルタイムでWebSocket経由で配信する。

**設計判断: イベント配信の責務をどこに置くか**

3つの選択肢を検討した結果、**jupyter-mcp 側から配信する方式（Option A）** を採用する。

- **Option A（採用）: jupyter-mcp が配信**: `execute_code` ツール内で、実行の前後にAI同期イベントをPOSTする。ストリーミング出力は、jupyter-serverが実行完了後に返す結果をもとに配信する。
- Option B: jupyter-server のexecuteハンドラー内でIOPubメッセージごとにWebSocket配信する。サーバー側のコードが複雑になる。
- Option C: 新しいストリーミングエンドポイントを作成する。過度な設計変更。

**Option Aの理由:**
- 9.1で確立されたパターン（MCP側からPOST /api/ai/events/broadcast）と一貫性がある
- jupyter-serverの既存コードへの変更が最小限
- ストリーミングは一旦「実行完了後にまとめて配信」で十分。理由：
  - AIの実行は通常数秒で完了する
  - 出力全体をまとめて表示しても体験上の問題は小さい
  - 将来的にストリーミングが必要になった場合、Option Bに移行可能

ただし、実行中であることをユーザーに示すため `cell_execute_start` は実行前に、`cell_execute_end` は実行後に配信する。

1. `kernel_executor.py`: 変更不要
2. `handlers.py`: 変更不要（jupyter-server側はイベント配信に関与しない）

#### Step 3: jupyter-mcp の session-resolver に notebookPath 解決を追加

`session-resolver.ts` に `resolveNotebookPath()` を追加:

```typescript
export async function resolveNotebookPath(sessionId: string): Promise<string | null> {
  try {
    const sessions = await jupyterClient.listSessions();
    const session = sessions.find(s => s.id === sessionId);
    return session?.path ?? null;
  } catch {
    return null;
  }
}
```

**重要:** session_id で作成された場合のみ notebook_path が取得できる。kernel_id のみの場合は null を返す。notebook_path が取得できない場合はイベント配信をスキップする（fire-and-forget の方針）。

#### Step 4: jupyter-mcp の execute-code.ts にイベント配信を追加

`executeExecuteCode()` を以下のように変更:

```typescript
export async function executeExecuteCode(args: Record<string, unknown>): Promise<McpResponse> {
  // ... 既存の入力検証 ...

  try {
    const kernelId = await resolveKernelId(validatedSessionId);

    // notebook_path を解決（イベント配信用）
    const notebookPath = await resolveNotebookPath(validatedSessionId);

    // セルインデックスを特定（ノートブックの末尾セルを対象とする）
    let cellIndex = -1;
    if (notebookPath) {
      cellIndex = await resolveCellIndex(notebookPath);
    }

    // cell_execute_start イベント配信
    if (notebookPath) {
      await jupyterClient.postAiEvent({
        type: 'cell_execute_start',
        notebook_path: notebookPath,
        cell_index: cellIndex,
      });
    }

    // コード実行（既存ロジック）
    const result = await jupyterClient.executeCode(kernelId, { code, timeout });

    // cell_output イベント配信（実行完了後にまとめて配信）
    if (notebookPath) {
      await broadcastOutputEvents(notebookPath, cellIndex, result);
    }

    // cell_execute_end イベント配信
    if (notebookPath) {
      await jupyterClient.postAiEvent({
        type: 'cell_execute_end',
        notebook_path: notebookPath,
        cell_index: cellIndex,
        execution_count: result.execution_count,
        success: result.success,
      });
    }

    // ... 既存のレスポンス生成ロジック ...
  } catch (error) {
    // ... 既存のエラーハンドリング ...
  }
}
```

**`broadcastOutputEvents()` ヘルパー関数:**

実行結果の `outputs`, `images`, `result`, `error` をそれぞれ `cell_output` イベントとして配信する。

```typescript
async function broadcastOutputEvents(
  notebookPath: string,
  cellIndex: number,
  result: ExecuteResult
): Promise<void> {
  // stdout/stderr
  for (const output of result.outputs) {
    await jupyterClient.postAiEvent({
      type: 'cell_output',
      notebook_path: notebookPath,
      cell_index: cellIndex,
      output: {
        output_type: 'stream',
        name: output.type as 'stdout' | 'stderr',
        text: output.text,
      },
    });
  }

  // 画像出力
  for (const image of result.images) {
    await jupyterClient.postAiEvent({
      type: 'cell_output',
      notebook_path: notebookPath,
      cell_index: cellIndex,
      output: {
        output_type: 'display_data',
        data: { [image.mime_type]: image.data },
        metadata: {},
      },
    });
  }

  // 式の評価結果
  if (result.result !== null && result.result !== undefined) {
    await jupyterClient.postAiEvent({
      type: 'cell_output',
      notebook_path: notebookPath,
      cell_index: cellIndex,
      output: {
        output_type: 'execute_result',
        execution_count: result.execution_count,
        data: { 'text/plain': String(result.result) },
        metadata: {},
      },
    });
  }

  // エラー出力
  if (result.error) {
    await jupyterClient.postAiEvent({
      type: 'cell_output',
      notebook_path: notebookPath,
      cell_index: cellIndex,
      output: {
        output_type: 'error',
        ename: result.error.type,
        evalue: result.error.message,
        traceback: result.error.traceback,
      },
    });
  }
}
```

**`resolveCellIndex()` ヘルパー関数:**

ノートブックの末尾のコードセルのインデックスを返す。`execute_code` は特定のセルを指定して実行するわけではないため、通常は最後に追加されたセル（`notebook_add_cell` で追加されたセル）が対象。

```typescript
async function resolveCellIndex(notebookPath: string): Promise<number> {
  try {
    const notebook = await jupyterClient.getNotebook(notebookPath);
    // 末尾のセルのインデックス
    return Math.max(0, notebook.content.cells.length - 1);
  } catch {
    return -1;
  }
}
```

**handleEvent() の switch-case を拡張:**

```typescript
handleEvent(event: AiEvent): void {
  switch (event.type) {
    case 'cell_added':
      this.handleCellAdded(event as CellAddedEvent);
      break;
    case 'cell_execute_start':
      this.handleCellExecuteStart(event as CellExecuteStartEvent);
      break;
    case 'cell_output':
      this.handleCellOutput(event as CellOutputEvent);
      break;
    case 'cell_execute_end':
      this.handleCellExecuteEnd(event as CellExecuteEndEvent);
      break;
    default:
      console.log('[NotebookUpdater] Unknown event type:', event.type);
  }
```

**handleCellExecuteStart():**

対象セルのoutputsをクリアし、実行中状態（`executionCount = null`、`trusted = true`）を設定する。

JupyterLab 4.x の SharedModel API を使用:

```typescript
private handleCellExecuteStart(event: CellExecuteStartEvent): void {
  const notebookPanel = this.findNotebookByPath(event.notebook_path);
  if (!notebookPanel) return;

  const model = notebookPanel.content.model;
  if (!model) return;

  const cellIndex = event.cell_index;
  const cell = model.sharedModel.getCell(cellIndex);
  if (!cell) return;

  // outputs をクリア（新しい実行の開始）
  if (cell.cell_type === 'code') {
    cell.setOutputs([]);
    // execution_count を null に設定（実行中を表す [*]）
    cell.execution_count = null;
  }

  // 対象セルにスクロール
  notebookPanel.content.activeCellIndex = cellIndex;
  notebookPanel.content.scrollToItem(cellIndex);
}
```

**handleCellOutput():**

受信した出力をセルに追加する。JupyterLab の SharedModel API で `IOutput` 形式に変換して追加。

```typescript
private handleCellOutput(event: CellOutputEvent): void {
  const notebookPanel = this.findNotebookByPath(event.notebook_path);
  if (!notebookPanel) return;

  const model = notebookPanel.content.model;
  if (!model) return;

  const cell = model.sharedModel.getCell(event.cell_index);
  if (!cell || cell.cell_type !== 'code') return;

  // output を nbformat の IOutput 形式に変換して追加
  const output = this.convertToNbformatOutput(event.output);
  if (output) {
    const currentOutputs = cell.getOutputs();
    cell.setOutputs([...currentOutputs, output]);
  }
}

private convertToNbformatOutput(output: CellOutputEvent['output']): object | null {
  switch (output.output_type) {
    case 'stream':
      return { output_type: 'stream', name: output.name, text: output.text };
    case 'display_data':
      return { output_type: 'display_data', data: output.data, metadata: output.metadata || {} };
    case 'execute_result':
      return { output_type: 'execute_result', execution_count: output.execution_count, data: output.data, metadata: output.metadata || {} };
    case 'error':
      return { output_type: 'error', ename: output.ename, evalue: output.evalue, traceback: output.traceback };
    default:
      return null;
  }
}
```

**handleCellExecuteEnd():**

実行カウントを設定し、実行完了状態にする。

```typescript
private handleCellExecuteEnd(event: CellExecuteEndEvent): void {
  const notebookPanel = this.findNotebookByPath(event.notebook_path);
  if (!notebookPanel) return;

  const model = notebookPanel.content.model;
  if (!model) return;

  const cell = model.sharedModel.getCell(event.cell_index);
  if (!cell || cell.cell_type !== 'code') return;

  // execution_count を設定
  cell.execution_count = event.execution_count;
}
```

### 技術的な考慮事項

#### セルインデックスの特定方法

`execute_code` ツールは `session_id` と `code` を受け取るが、どのセルで実行するかの情報がない。実運用では `notebook_add_cell` でセルを追加してから `execute_code` でそのセルのコードを実行する、という流れが基本。

そのため、セルインデックスはノートブックの末尾コードセルとして推定する。これは「AIが先行してセッション準備」フロー（`notebook_add_cell` → `execute_code`）で正しく動作する。

将来的に `execute_code` に `cell_index` パラメータを追加することも検討できるが、本タスクでは最小限の変更に留める。

#### notebook_path が取得できない場合

`session_create` で `notebook_path` なしにセッション作成した場合、イベント配信対象のノートブックを特定できない。この場合はイベント配信をスキップする。ブラウザ上でリアルタイム表示するには `notebook_path` 付きでセッションを作成する必要がある。これは要件定義のユースケース（「AIが先行してセッション準備」フロー）と整合している。

#### JupyterLab SharedModel API の出力操作

JupyterLab 4.x では `ISharedCodeCell` の `setOutputs()` と `getOutputs()` メソッドで出力を操作する。`IOutput` は `@jupyterlab/nbformat` で定義されたインターフェースで、`output_type` フィールドで種類を区別する。API仕様で定義したイベントの `output` フィールドは、このnbformat仕様に沿った形式にしている。

#### イベント配信の順序とタイミング

- `cell_execute_start`: 実行APIコール前に配信。ブラウザ側で実行中インジケータ（`[*]`）を即座に表示。
- `cell_output`: 実行完了後にまとめて配信。将来的にストリーミング対応が必要になった場合はjupyter-server側でIOPubメッセージごとに配信する方式に変更可能。
- `cell_execute_end`: 実行完了後、出力配信後に配信。execution_countを確定し、実行完了を通知。

#### 後続タスクとの境界

- **9.3（ロック制御）**: 本タスクとは独立。`ai_edit_start`/`ai_edit_end` イベントのハンドリングを追加。
- 本タスクの完了後、「`ai_edit_start` → `notebook_add_cell` → `execute_code` → `ai_edit_end`」の全フローがブラウザ上でリアルタイムに確認可能になる（ロック制御を除く）。

# タスク詳細: 7.2 画像ファイルの MCP リソース公開（再定義）

## 概要

コード実行で生成された画像ファイルを MCP リソース（`resources/list`, `resources/read`）として公開し、AI クライアントがビジョン機能で画像を分析できるようにする。

Phase 10 で画像はファイルベース化済み。`execute_code` のテキストレスポンスには `file_path` のみを含めるが（コンテキストウィンドウ節約）、AI クライアントが画像を視覚的に確認したい場合に MCP リソース経由で**オンデマンドで**取得可能にする。

### なぜこのタスクが必要か

- 現在、AI は `execute_code` で `file_path` を受け取るが、画像の中身を確認する手段がない
- MCP リソースを使えば、AI クライアント（Claude Desktop 等）がビジョン機能で画像を分析し、グラフの傾向読み取りや異常値検出が可能になる
- `execute_code` のテキストレスポンスに base64 を含めないため、コンテキストウィンドウは圧迫しない

### 前提条件: 要件変更（完了）

要件定義（`docs/requirements/jupyter-mcp.md`）の「MCPリソースAPIは提供しない」を「MCPリソースで画像をオンデマンド公開する」に変更済み。F7.3 追加、MCPリソース定義追加、AC5 更新済み。

### 実装手順

#### ステップ 1: 画像レジストリの実装

`src/resources/image-registry.ts` を作成。インメモリで画像ファイルのメタデータのみを管理する（画像データ自体は保持しない）。

```typescript
import type { ImageOutput } from '../jupyter-client/types.js';

interface RegisteredImage {
  uri: string;           // jupyter://images/{workspace_id}/{filename}
  file_path: string;     // workspaces/{workspace_id}/output/exec-N-img-NNN.png
  mime_type: string;
  description: string;
  workspace_id: string;
}

class ImageRegistry {
  private images: Map<string, RegisteredImage> = new Map();

  /**
   * execute_code で生成された画像をレジストリに登録する。
   * URI を生成して返す。
   */
  register(image: ImageOutput, workspaceId: string): RegisteredImage {
    const filename = image.file_path.split('/').pop()!;
    const uri = `jupyter://images/${workspaceId}/${filename}`;
    const entry: RegisteredImage = {
      uri,
      file_path: image.file_path,
      mime_type: image.mime_type,
      description: image.description,
      workspace_id: workspaceId,
    };
    this.images.set(uri, entry);
    return entry;
  }

  /** 全画像を一覧 */
  list(): RegisteredImage[] {
    return Array.from(this.images.values());
  }

  /** URI で画像を検索 */
  get(uri: string): RegisteredImage | undefined {
    return this.images.get(uri);
  }

  /** ワークスペース別に一覧 */
  listByWorkspace(workspaceId: string): RegisteredImage[] {
    return this.list().filter(img => img.workspace_id === workspaceId);
  }

  /** 全クリア */
  clear(): void {
    this.images.clear();
  }
}

export const imageRegistry = new ImageRegistry();
```

#### ステップ 2: jupyter-client にファイル取得メソッドを追加

`src/jupyter-client/client.ts` に `getFileContent()` を追加。Jupyter Contents API を使って画像ファイルの base64 データを取得する。

```typescript
/**
 * ファイル内容を取得する（バイナリファイルは base64 エンコードで返却）。
 * Jupyter Contents API: GET /api/contents/{path}?content=1&type=file
 */
async getFileContent(path: string): Promise<{ content: string; mimetype: string }> {
  const response = await this.client.get(`/api/contents/${path}`, {
    params: { content: 1, type: 'file' },
  });
  return {
    content: response.data.content,   // base64 encoded
    mimetype: response.data.mimetype,
  };
}
```

`src/jupyter-client/types.ts` に `FileContent` 型を追加：

```typescript
export interface FileContent {
  content: string;   // base64 encoded for binary files
  mimetype: string;
}
```

#### ステップ 3: リソースハンドラの実装

`src/resources/images.ts` を作成。

```typescript
import type { Resource } from '@modelcontextprotocol/sdk/types.js';
import { imageRegistry } from './image-registry.js';
import { jupyterClient } from '../jupyter-client/index.js';

/**
 * MCP resources/list ハンドラ。
 * レジストリに登録された全画像をリソースとして返却。
 */
export async function listImageResources(): Promise<{ resources: Resource[] }> {
  const images = imageRegistry.list();
  return {
    resources: images.map(img => ({
      uri: img.uri,
      name: img.description,
      mimeType: img.mime_type,
      description: `${img.description} (${img.file_path})`,
    })),
  };
}

/**
 * MCP resources/read ハンドラ。
 * URI に対応する画像ファイルを Jupyter Contents API 経由で取得し、
 * BlobResourceContents として返却。
 */
export async function readImageResource(uri: string): Promise<{
  contents: Array<{ uri: string; mimeType: string; blob: string }>;
}> {
  const image = imageRegistry.get(uri);
  if (!image) {
    throw new Error(`Image not found: ${uri}`);
  }

  const file = await jupyterClient.getFileContent(image.file_path);

  return {
    contents: [
      {
        uri,
        mimeType: image.mime_type,
        blob: file.content,  // base64 encoded by Jupyter API
      },
    ],
  };
}
```

#### ステップ 4: server.ts の修正

```typescript
import {
  ListResourcesRequestSchema,
  ReadResourceRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
import { listImageResources, readImageResource } from './resources/images.js';

export function createServer(): Server {
  const server = new Server(
    { name: 'jupyter-mcp', version: '1.0.0' },
    {
      capabilities: {
        tools: {},
        resources: {},  // 追加
      },
    }
  );

  // 既存のツールハンドラ...

  // リソースハンドラ
  server.setRequestHandler(ListResourcesRequestSchema, async () => {
    return listImageResources();
  });

  server.setRequestHandler(ReadResourceRequestSchema, async (request) => {
    return readImageResource(request.params.uri);
  });

  return server;
}
```

### 技術的な考慮事項

1. **base64 はオンデマンドのみ**
   - `execute_code` のテキストレスポンスには含めない（Phase 10 の方針維持）
   - `resources/read` でのみ base64 を返却（AI クライアントが明示的に要求した場合のみ）
   - コンテキストウィンドウの圧迫は発生しない

2. **URI 形式**
   - `jupyter://images/{workspace_id}/{filename}`
   - 例: `jupyter://images/ws-abc123/exec-1-img-001.png`
   - ファイルパスとの対応が明確で、デバッグしやすい

3. **レジストリの揮発性**
   - MCP サーバー再起動でレジストリはクリアされる
   - 画像ファイル自体はワークスペースに永続化されているため、データは失われない
   - 再起動後に resources/list が空になるのは許容（file_list で output/ を確認すればファイルは存在する）

4. **ファイル取得のパフォーマンス**
   - `resources/read` は Jupyter Contents API 経由でファイルを読む
   - 画像ファイルは通常 数十KB〜数百KB のため、レイテンシは許容範囲

5. **既存の execute_code レスポンスへの影響なし**
   - レジストリ登録は副作用として行うが、レスポンス形式は変更しない
   - file_path / mime_type / description のみが返される（従来通り）

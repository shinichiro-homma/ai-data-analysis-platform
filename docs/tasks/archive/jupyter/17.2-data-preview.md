# タスク詳細: 17.2 データプレビュー

## 概要

ワークスペース内のCSV/Parquetファイルの構造（カラム名・型・先頭行）をカーネルなしで取得できる `data_preview` MCPツールを新規実装する。jupyter-server 側では新規 REST API エンドポイント `GET /api/custom/contents/{path}/preview` を追加し、サーバーサイドで pandas を使ってファイルを読み込みメタデータと先頭行を返す。jupyter-mcp 側では新規MCPツール `data_preview` を作成する。

### 実装手順

1. **API仕様の追記**
   - `docs/design/api-contracts.md` に `GET /api/custom/contents/{path}/preview` の仕様を追記
   - クエリパラメータ: `head_rows`（先頭行数、デフォルト5、最大50）
   - レスポンス: `{ data: { path, format, columns: [{name, dtype}], row_count, head: [{...}], file_size_bytes } }`

2. **jupyter-server: ContentsPreviewHandler の実装**
   - `handlers.py` に `ContentsPreviewHandler` クラスを追加
   - `GET /api/custom/contents/{path}/preview` エンドポイント
   - パストラバーサル対策（既存の `validate_path` を使用）
   - 対応形式: `.csv`, `.parquet`（拡張子で判定）
   - pandas で読み込み、カラム名・型・先頭行・行数・ファイルサイズを返却
   - CSV: `pd.read_csv(nrows=head_rows)` で先頭行のみ読み込み、`pd.read_csv()` の結果から行数を推定（全件読み込みを避けるため、ファイルサイズと先頭行から推定、または行カウントのみ実施）
   - Parquet: `pd.read_parquet()` で schema 取得、`head()` で先頭行取得
   - 非対応形式の場合は 400 エラー
   - `get_handlers` にルーティング追加（`ContentsCellsHandler` よりも前に配置して優先マッチさせる）

3. **jupyter-mcp: 型定義の追加**
   - `types.ts` に `DataPreviewResponse` 型を追加
     - `path: string`
     - `format: 'csv' | 'parquet'`
     - `columns: Array<{ name: string; dtype: string }>`
     - `row_count: number`
     - `head: Array<Record<string, unknown>>`
     - `file_size_bytes: number`

4. **jupyter-mcp: クライアントメソッドの追加**
   - `client.ts` に `previewContents(path: string, headRows?: number)` メソッドを追加
   - `GET /api/custom/contents/{path}/preview?head_rows={N}` を呼び出す

5. **jupyter-mcp: data_preview ツール実装**
   - `workspace_id`（必須）、`file_path`（必須、ワークスペース内の相対パス）、`head_rows`（任意、デフォルト5）のバリデーション
   - パストラバーサル対策（`normalizePath` を使用）
   - ワークスペースパスの解決（`resolveWorkspacePath` を使用）
   - `jupyterClient.previewContents()` を呼び出し
   - レスポンスにカラム情報・先頭行・行数を含める

6. **jupyter-mcp: ツール登録**
   - `index.ts` に `data_preview` のインポートとツール定義を追加
   - ツール定義: `workspace_id`, `file_path`, `head_rows` の3パラメータ

7. **テスト作成・実行**

### 技術的な考慮事項

#### 1. カーネル不要の設計

`data_preview` はカーネル（セッション）を起動せずにファイル構造を取得できることが重要。jupyter-server 側で直接 pandas を使ってファイルを読み込む。これにより、セッション作成前のデータ確認や、カーネルリソースを消費せずにファイル構造を把握できる。

#### 2. CSV の行数取得

CSV ファイルの正確な行数を取得するには全件読み込みが必要だが、大きなファイルではコストが高い。以下の方針で対応する:
- Parquet: `pyarrow.parquet.ParquetFile.metadata.num_rows` で正確な行数を O(1) で取得
- CSV: ファイル全体をカウントする（`sum(1 for _ in open(file))` でヘッダーを除く行数）。ただし、ファイルサイズが閾値（例: 100MB）を超える場合は `row_count: null` を返し、推定行数は返さない

#### 3. 対応フォーマット

要件定義では「CSV, Excel, Parquet等に対応」とあるが、E2Eテストの記載は「CSV/Parquetファイルの構造」のみ。本タスクでは CSV と Parquet に限定する。Excel 対応は将来の拡張とする。

#### 4. ファイルパスの解決

`file_list` ツールと同じパターンで、ワークスペースID + 相対パスからContents APIパスを解決する。`resolveWorkspacePath` と `normalizePath` を組み合わせて使用する。

#### 5. head 行のシリアライズ

pandas DataFrame の `head()` を `to_dict(orient='records')` でシリアライズする。NaN 値は `null` に変換する。日時型は ISO 8601 文字列に変換する。

#### 6. ルーティングの優先順位

`GET /api/custom/contents/{path}/preview` のルーティングは、`ContentsCellsHandler`（`/api/custom/contents/(.*)/cells`）と同様に、`ContentsHandler`（`/api/custom/contents/(.*)`）よりも前に配置する必要がある。Tornado はルーティングを上から順にマッチさせるため、`/preview` サフィックスを持つパスが汎用パスにキャッチされないようにする。

#### 7. 既存パターンの踏襲

- バリデーション: `validateStringParameter`, `validateWorkspaceId` を使用（`file-list.ts` と同一パターン）
- パス検証: `normalizePath`, `resolveWorkspacePath` を使用
- レスポンス: `createSuccessResponse` / `createErrorResponse` を使用
- エラーコード抽出: `extractErrorCode` / `extractErrorMessage` を使用

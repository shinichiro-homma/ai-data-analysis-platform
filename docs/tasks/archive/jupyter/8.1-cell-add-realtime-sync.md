# タスク詳細: 8.1 セル追加のリアルタイム同期

## 概要

AIが `notebook_add_cell` ツールを呼んだ際に、ブラウザで開いている JupyterLab 上のノートブックにセルが即座に追加される機能を実装する。

このタスクでは以下の3つを一体的に実装する：

1. **jupyter-server**: AI同期WebSocketエンドポイント（`WS /api/ai/events` + `POST /api/ai/events`）
2. **jupyterlab-ai-sync**: JupyterLab拡張の基盤 + `cell_added` イベント処理
3. **jupyter-mcp**: `notebook_add_cell` ツールからセル追加イベントを配信する連携

これにより「AIがセルを追加 → ブラウザに即座に反映」という、結合テスト可能な1つの機能が完成する。

## なぜこのタスクが必要か

現状、AIが `notebook_add_cell` でノートブックにセルを追加しても、JupyterLab のブラウザUIには自動的に反映されない。ユーザーはノートブックをリロードしないと変更を確認できない。本タスクによりリアルタイム同期の基盤が確立され、Phase 8 の後続タスク（8.2 実行同期、8.3 ロック制御）の土台となる。

### 実装手順

#### Step 1: jupyter-server に WebSocket/REST エンドポイント実装

1. `ai_events.py` を新規作成:
   - `AiEventsWebSocketHandler`: Tornado の `WebSocketHandler` を継承
     - `open()`: クライアント接続を登録（グローバルリストに追加）。クエリパラメータ `token` で認証
     - `on_close()`: クライアント接続を解除
     - `on_message()`: 不要（サーバーからクライアントへの一方向配信）
   - `AiEventsPostHandler`: `BaseCustomHandler` を継承
     - `post()`: JSON ボディを受け取り、接続中の全 WebSocket クライアントにブロードキャスト
     - レスポンス: `{ "data": { "broadcasted": true, "clients": N } }`
   - グローバルなクライアント管理: `set()` でWebSocket接続を管理

2. `handlers.py` の `get_handlers()` に2つのルートを追加:
   - `(f"{base_url}/api/ai/events", AiEventsWebSocketHandler)`
   - `(f"{base_url}/api/ai/events/broadcast", AiEventsPostHandler)` — POSTは `/broadcast` サブパスで分離（WebSocketとルートが競合するため）

#### Step 2: jupyterlab-ai-sync 拡張の基盤実装

1. `package.json` を作成:
   - JupyterLab 4.x 対応の拡張パッケージ構成
   - 依存: `@jupyterlab/application`, `@jupyterlab/notebook`, `@jupyterlab/cells`, `@jupyterlab/nbformat`
   - ビルド: `tsc` → JupyterLab 拡張としてバンドル

2. `src/index.ts`: 拡張エントリーポイント（`plugin.ts` を re-export）

3. `src/plugin.ts`: JupyterLab プラグイン定義
   - `INotebookTracker` を require して、現在開いているノートブックを追跡
   - 起動時に `WebSocketClient` を初期化・接続
   - イベント受信時に `NotebookUpdater` にルーティング

4. `src/websocket-client.ts`: WebSocket クライアント
   - `ws://localhost:8888/api/ai/events?token={token}` に接続
   - JupyterLab の `ServerConnection.makeSettings()` からベースURLとトークンを取得
   - 自動再接続（5秒間隔）
   - メッセージ受信時にコールバック関数を呼び出し

5. `src/notebook-updater.ts`: ノートブック UI 更新
   - `handleCellAdded(event)`:
     - `event.notebook_path` と開いているノートブックのパスを照合
     - 一致するノートブックが見つかったら、指定位置にセルを挿入
     - `@jupyterlab/notebook` の `NotebookModel` API を使用してセルを追加
     - 追加されたセルにスクロール

#### Step 3: jupyter-mcp から AI イベントを配信

1. `client.ts` に `postAiEvent()` メソッドを追加:
   - `POST /api/ai/events/broadcast` に JSON を送信
   - エラーは警告ログ出力のみ（メイン処理をブロックしない）

2. `types.ts` に `AiEvent` 型を追加:
   - `CellAddedEvent`: `{ type: "cell_added", notebook_path, cell, index }`

3. `notebook-add-cell.ts` を変更:
   - セル追加成功後に `jupyterClient.postAiEvent()` を呼び出し
   - `cell_added` イベントを配信（notebook_path, cell_type, source, index）
   - イベント配信失敗時もメイン処理は成功として返却（fire-and-forget）

#### Step 4: Docker統合

1. `Dockerfile` を更新:
   - `jupyterlab-ai-sync` ディレクトリを COPY
   - `pip install /home/jovyan/jupyterlab-ai-sync` でJupyterLabにインストール

### 技術的な考慮事項

#### WebSocketエンドポイントのルーティング

Tornado では同一パスで WebSocketHandler と通常の RequestHandler を共存させることが困難。そのため以下の設計を採用:

- `WS /api/ai/events` → WebSocket 接続用（`AiEventsWebSocketHandler`）
- `POST /api/ai/events/broadcast` → イベント送信用（`AiEventsPostHandler`）

**代替案:** `/api/ai/events` で GET/WebSocket と POST の両方を処理する単一ハンドラー。ただし Tornado の WebSocketHandler は HTTP メソッドのオーバーライドに制約があるため、分離する方が安全。

#### JupyterLab 拡張のセル追加方法

JupyterLab 4.x では、`NotebookModel` の `sharedModel`（`YNotebook`）を通じてセルを操作する:

```typescript
const notebook = notebookPanel.content.model;
const cell = notebook.sharedModel.insertCell(index, {
  cell_type: 'code',
  source: 'print("hello")',
});
```

この方法は JupyterLab の CRDT ベースの共同編集モデルと整合性がある。

#### JupyterLab 拡張の認証

JupyterLab 拡張は `ServerConnection.makeSettings()` を通じて自動的にトークンを取得できる。`PageConfig.getToken()` でクエリパラメータ用のトークンを取得する。

#### イベント配信の信頼性

`notebook_add_cell` のメイン処理（セルの追加とノートブック保存）とイベント配信は独立させる。イベント配信が失敗しても、セル追加自体は成功として扱う。ブラウザでリロードすればセルは反映されるため、イベント配信はベストエフォートで十分。

## テスト計画

### 手動テスト（E2Eテスト）

1. **WebSocket接続テスト**:
   - Docker でjupyter-serverを起動
   - `wscat` や Python の `websockets` ライブラリで `ws://localhost:8888/api/ai/events?token=...` に接続
   - `POST /api/ai/events/broadcast` でイベントを送信し、WebSocketクライアントで受信できることを確認

2. **JupyterLab拡張ロードテスト**:
   - Docker でjupyter-serverを起動（拡張インストール済み）
   - ブラウザで JupyterLab を開く
   - ブラウザの開発者コンソールに拡張のロードログが出力されることを確認

3. **セル追加の統合テスト**:
   - ブラウザで JupyterLab を開き、ノートブックを開く
   - MCP Inspector で jupyter-mcp に接続
   - `notebook_add_cell` ツールを実行
   - ブラウザ上のノートブックにセルが即座に追加されることを確認

4. **境界ケース**:
   - ノートブックが開かれていない状態で `notebook_add_cell` を実行 → エラーにならないこと
   - WebSocket 接続がない状態で `notebook_add_cell` を実行 → セル追加自体は成功すること
   - 複数のノートブックが開かれている場合、正しいノートブックにだけセルが追加されること

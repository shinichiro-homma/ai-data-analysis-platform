# タスク詳細: 24.4 ファイルブラウザカスタマイズの DOM 依存削減

## 概要

`file-browser-customizer.ts` のフォルダシングルクリック展開・ダブルクリック移動機能（F5.1/F5.2）において、JupyterLab 非公開の DOM クラス名・data 属性への依存を削減する。モデル（`Contents.IManager`）ベースのアイテム解決に移行し、想定外の DOM 構造では標準動作にフォールバックする防御的設計とする。

- 類似タスク: `docs/tasks/archive/jupyter/24.3-lock-control-official-api.md`（同 Phase の公式 API 化パターン）

## 調査したファイル

- `jupyterlab-ai-sync/src/file-browser-customizer.ts`: 対象ファイル（344行）。JupyterLab 非公開 DOM 依存は3種類: `.jp-DirListing-itemText`（L22）、`.jp-DirListing-item`（L54）、`data-isdir`（L37）。自作 DOM（`.jp-fb-tree-*`）は独自 UI のため対象外。`browser.model.cd()` は既に公式 API 使用済み
- `jupyterlab-ai-sync/src/index.ts`: `fileBrowserPlugin` を export するエントリポイント

## 検討した代替案

| 案 | 概要 | 利点 | 欠点 |
|----|------|------|------|
| A（採用） | モデルキャッシュによる DOM 依存削減 | `data-isdir` と `.jp-DirListing-itemText` の2つの非公開依存を排除。`.jp-DirListing-item` は残すが防御的フォールバック付き。純粋関数の抽出でテスト可能 | `.jp-DirListing-item` セレクタは完全排除不可（キャプチャフェーズでのクリック対象特定に必要） |
| B | `DirListing` シグナル（選択変更）ベースに全面移行 | DOM 依存ゼロ | `DirListing` はシングルクリックで即フォルダ移動するため、「シングルクリックで展開」の要件と根本的に矛盾。クリックを先にキャプチャして標準動作を抑制する設計が必須であり、この案では F5.1 を実現できない |

採用理由: 案 B は F5.1（シングルクリック展開）の要件を満たせない。キャプチャフェーズでのクリック横取りは設計上不可避であり、案 A はその制約の中で `.jp-DirListing-item` 1つを残し他の非公開依存を排除する現実的なアプローチ

ADR 要否: 不要。コンポーネント内部のリファクタリングであり、コンポーネント間契約・状態の所有権に変更なし

### 実装手順

1. **ディレクトリアイテムキャッシュの導入**: `activate` 内に `currentItems: Map<string, Contents.IModel>` を追加。`browser.model.refreshed` シグナルのハンドラ内で `browser.model.items()` を走査してキャッシュを構築する（`pathChanged` はキャッシュ構築に使わない — `pathChanged` は `refreshed` より先に発火し、その時点ではモデルにアイテムが格納されていないため）。`buildItemsCache` は `Iterable<Contents.IModel>` を受け取り `Map<string, Contents.IModel>` を返す純粋関数として export する。検証: テストで `buildItemsCache` の返り値が name → model のマップになることを確認

2. **`resolveClickedItem` 関数の抽出**: クリックターゲットから `{ name, path, isDir }` を返す純粋関数を export する。以下の優先順で解決:
   (a) `.jp-DirListing-item` を `closest` で特定（残存する唯一の非公開セレクタ）
   (b) アイテム名はまず `textContent` から取得を試み（`.jp-DirListing-itemText` セレクタを廃止）、失敗時は `null`
   (c) `isDir` はキャッシュの `Contents.IModel.type === 'directory'` で判定（`data-isdir` 属性参照を廃止）
   (d) いずれかのステップで `null` なら `null` を返す（= フォールバックで標準動作）
   検証: テストで `resolveClickedItem` が正常ケース・null ケースを正しく返すことを確認

3. **`clickHandler` / `dblclickHandler` のリファクタリング**: `resolveClickedItem` を使うように書き換え。戻り値が `null` のときは `return`（`preventDefault/stopPropagation` を呼ばない = 標準動作にフォールバック）。検証: `scripts/test.sh --quiet jupyterlab-ai-sync` で型チェック + テスト PASS

4. **`isDirectory` 関数の廃止**: トップレベルの `isDirectory(itemEl)` を削除し、すべてのフォルダ判定を `resolveClickedItem` 経由のモデルベースに統一。ツリー内部の子要素（自作 `.jp-fb-tree-item`）での `data-isdir` 参照はそのまま維持（自作属性のため）。検証: `grep 'data-isdir' jupyterlab-ai-sync/src/file-browser-customizer.ts` の結果が `createTreeItemEl` 内と自作ツリーイベントハンドラ内のみに限定

5. **`getItemName` 関数のリファクタリング**: `.jp-DirListing-itemText` セレクタを廃止。代わりに `itemEl` の直接の `textContent` から名前を抽出する。JupyterLab 4.x の `DirListing-item` は子要素にアイコン・名前・更新日時等を持つため、最初のテキストノード（or 特定パターン）からの名前抽出ロジックを実装し、失敗時は `null` を返す。検証: テストで各種入力パターンの抽出結果を確認

6. **DOM セレクタの定数化と防御的ラッパー**: 残存する `.jp-DirListing-item` セレクタを `LISTING_ITEM_SELECTOR` 定数として定義。`findListingItem` にコメントで JupyterLab 4.x 依存であることを明示。検証: `grep 'jp-DirListing' jupyterlab-ai-sync/src/file-browser-customizer.ts` の結果が定数定義の1箇所のみ

7. **ユニットテストの作成**: `resolveClickedItem`、`buildItemPath`、`buildItemsCache`、ソートロジックの純粋関数テスト。検証: `scripts/test.sh --quiet --test --no-lint jupyterlab-ai-sync -- tests/unit/file-browser-customizer.test.ts` が PASS

### 技術的な考慮事項

- `textContent` からアイテム名を抽出する場合、JupyterLab 4.x の `DirListing-item` は更新日時やファイルサイズも含むため、直接 `textContent` では名前のみを取得できない可能性がある。その場合は `firstElementChild` の `textContent` や、最初の意味のあるテキストノードを走査する方式に切り替える。最終手段として `.jp-DirListing-itemText` を定数化して残す（ただしフォールバック付き）
- `browser.model.refreshed` シグナルはアイテム格納後に発火するため、ハンドラ内で `browser.model.items()` を走査すればネットワークリクエスト不要でキャッシュを構築できる。ただしプラグイン起動直後の初回 `refreshed` 発火前にクリックが来る可能性があるため、キャッシュ未構築時は `resolveClickedItem` が `null` を返し標準動作にフォールバックする
- ツリー内部の自作 DOM（`.jp-fb-tree-item`, `data-path`, `data-isdir`）は自作属性であり、本タスクの DOM 依存削減対象ではない

## リスクと検知方法

- シングルクリック展開・ダブルクリック移動が壊れる: ブラウザでの手動テスト（`docs/guides/browser-automation.md`）で AC5 の各条件を確認
- ファイルのクリック選択・ダブルクリックオープンへの副作用: フォルダではないファイルをクリック・ダブルクリックして正常に動作することを確認
- キャッシュと実際のファイルシステムの不整合: `refreshed` シグナルでキャッシュを更新するため、通常操作では発生しない。ファイル操作直後のクリックでキャッシュが古い場合はフォールバック

# タスク詳細: 9.4 初回セットアップスクリプト（uv 検知 + bootstrap）

## 概要

リポジトリクローン直後の開発者が、1 行の `bash scripts/bootstrap.sh` だけで以下を一括セットアップできるようにする。

1. **uv 検知**: PATH 上で `uv` を探し、未検出なら `~/.local/bin/uv` の存在を確認して PATH 反映手順（`~/.bashrc` に `. "$HOME/.local/bin/env"` を追記 / シェル再起動）を案内し、それでもない場合は公式インストールコマンドを提示して exit 1
2. **依存同期**: `uv sync` を実行してルート `.venv/` を再現
3. **git 設定**: `git config core.hooksPath .githooks` / `git config fetch.prune true` を適用
4. **`.env` 初期化**: `.env` が無ければ `.env.example` をコピーし、「デフォルト値で作成したので本番利用時はパスワードを変更すること」を警告。既存は上書きしない

uv の自動インストールはリポジトリから行わない（`curl | sh` 同梱禁止）。CLAUDE.md / README.md のセットアップ節は `bash scripts/bootstrap.sh` 一行＋補足に集約する。

`tmp/9.4-plan-notes.md` に 9.3 完了時の実地観測（PATH 反映失敗で `scripts/check-freshness.sh --rebuild` が exit 127 / `.env` 不在で `scripts/rebuild.sh --verify` が postgres TCP 接続待機で失敗）が記録されており、上記 1 と 4 はその再発防止として本タスクに追加されたスコープ。

### `scripts/bootstrap.sh` の挙動詳細

```
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"
source scripts/lib/common.sh

# 1. uv 検知
if ! command -v uv >/dev/null 2>&1; then
    if [ -x "$HOME/.local/bin/uv" ]; then
        # インストール済みだが PATH 未反映
        log_error "uv が ~/.local/bin/uv に存在するが PATH に含まれていない"
        cat <<'MSG'
次のいずれかを実行してから bootstrap.sh を再実行してください:
  1) 一時的に反映:   . "$HOME/.local/bin/env"
  2) 恒久的に反映:   echo '. "$HOME/.local/bin/env"' >> ~/.bashrc && exec bash
MSG
        exit 1
    fi
    log_error "uv が未インストール"
    cat <<'MSG'
公式インストールコマンド:
  curl -LsSf https://astral.sh/uv/install.sh | sh
インストール後にシェルを開き直してから bootstrap.sh を再実行してください。
MSG
    exit 1
fi
log_info "uv $(uv --version) を検出"

# 2. uv sync
log_info "ルート .venv を同期中..."
uv sync

# 3. git 設定（冪等）
log_info "git hooks パスと fetch.prune を設定"
git config core.hooksPath .githooks
git config fetch.prune true

# 4. .env 初期化（既存は保護）
if [ -f .env ]; then
    log_info ".env は既に存在するためスキップ"
else
    cp .env.example .env
    log_warn ".env を .env.example からコピーしました"
    log_warn "本番利用時は POSTGRES_PASSWORD / JUPYTER_TOKEN / DOCUMENT_SERVER_TOKEN を必ず変更してください"
fi

log_info "bootstrap 完了"
```

※上記は計画用の擬似コード。実装時は既存 `common.sh` の関数名・色制御を確認して合わせる。

### 技術的な考慮事項

- **冪等性**: すべてのステップが再実行しても壊れない（`uv sync` は idempotent、`git config` は上書き、`.env` は存在時スキップ）。テスト途中で任意に中断・再開できる
- **PATH 反映問題のカバレッジ**: `command -v uv` による検知なので、ログインシェル / 非ログインシェル / Claude Code の Bash ツール（WSL2 非対話）すべてで同じ判定結果になる。Claude Code Bash ツールから `scripts/bootstrap.sh` を実行した場合、親プロセスの PATH を引き継ぐため `~/.local/bin/env` を source しない限り再現する想定（これが 9.3 実行時に exit 127 を引いたパターン）
- **`~/.local/bin/env` を自動 source しない理由**: 現在のシェルから呼び出しただけでは親シェルの PATH を恒久変更できず、ユーザーを誤解させる。明示的な案内のみに留める
- **`.env` 自動コピーのセキュリティ**: `.env.example` のデフォルト値はローカル開発用のダミーであり、動作確認は可能だがパスワード強度は無い。ログで警告を出すことと、CLAUDE.md / README.md にも注意書きを残すことで担保
- **`git config` はリポジトリローカル**: `--global` ではなくローカル設定（`.git/config`）に書かれるため、他のクローンへの副作用はない
- **`git rev-parse --show-toplevel` への `cd`**: 任意のカレントディレクトリから叩ける利便性。bootstrap.sh は必ずリポジトリルート内で動く前提
- **非 interactive**: AskUserQuestion 的な対話は一切挟まず、標準入力を要求しない（CI からも将来呼べる構造にしておく）
- **実行権限**: `chmod +x scripts/bootstrap.sh` を忘れないこと。`bash scripts/bootstrap.sh` 経由なら実行権限不要だが、CLAUDE.md の案内は `bash` を前置する形で統一して権限依存を避ける

## テスト計画

Python/TS ユニットテストは対象外（シェルスクリプトのみ）。以下を手動 E2E で確認する。

### E2E ケース（tmp/ 下の作業ディレクトリを使うかバックアップを取って実施）

1. **uv 検出成功 + `.env` 新規作成パス**
   - 事前: `rm -f .env`、`command -v uv` が通る状態
   - 実行: `bash scripts/bootstrap.sh`
   - 期待: `uv sync` が走り、`.venv/` が更新される / `git config --local core.hooksPath` が `.githooks` を返す / `.env` が `.env.example` と同内容で作成される / 警告ログが出る / exit 0
2. **uv 検出成功 + `.env` 既存パス**
   - 事前: `.env` を何らかの値で作成済み
   - 実行: `bash scripts/bootstrap.sh`
   - 期待: `.env` の内容が変わらない / スキップログが出る / exit 0
3. **uv が PATH 未反映パス**
   - 事前: `~/.local/bin/uv` が存在するが、PATH から `~/.local/bin` を外した subshell（`PATH=/usr/bin:/bin bash scripts/bootstrap.sh`）を用意
   - 期待: PATH 反映手順（`. "$HOME/.local/bin/env"` / `~/.bashrc` 追記）の案内が stderr に出て exit 1
4. **uv 未インストールパス**
   - 事前: `mv ~/.local/bin/uv ~/.local/bin/uv.bak && PATH=/usr/bin:/bin bash scripts/bootstrap.sh`
   - 期待: 公式インストールコマンドが案内されて exit 1
   - 事後: `mv ~/.local/bin/uv.bak ~/.local/bin/uv` で復元
5. **冪等性**
   - 上記 1 実行直後に再度 `bash scripts/bootstrap.sh` を実行
   - 期待: すべてのステップがエラーなく再実行され、`.env` はスキップされる / exit 0

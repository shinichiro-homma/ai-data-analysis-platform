# タスク詳細: 7.2 generate-init-scripts.sh の .py 生成対応

## 概要

`scripts/lib/generate_init.py` の `generate_load_data()` 関数を書き換え、シェルスクリプト（`load-data.sh`）ではなく Python スクリプト（`load-data.py`）を生成するようにする。

生成される `load-data.py` は、Parquet ファイルを pyarrow で読み込み、psycopg2 の `copy_expert()` + `COPY FROM STDIN` で PostgreSQL にデータをロードする。ホスト側から実行する前提（postgres コンテナ内に Python は不要）。

**なぜ必要か**: Infrastructure Phase 7 で CSV → Parquet 移行を進めており、27.1 で変換スクリプトが完成済み。本タスクで init スクリプト生成を Parquet 対応に切り替え、後続の 27.3 で実行フローを変更する。

### 実装手順

#### 1. `read_csv_headers()` → `read_parquet_columns()` に書き換え

現在は CSV の先頭行からカラム名を取得しているが、Parquet のスキーマからカラム名を取得するように変更する。

```python
def read_parquet_columns(data_dir, tables):
    """Read Parquet schema to determine COPY column lists."""
    import pyarrow.parquet as pq

    columns = {}
    for table in tables:
        pg_table = table["data_source"]["table"]
        parquet_path = os.path.join(data_dir, f"{pg_table}.parquet")
        if os.path.exists(parquet_path):
            schema = pq.read_schema(parquet_path)
            columns[pg_table] = schema.names
        else:
            columns[pg_table] = None
    return columns
```

#### 2. `generate_load_data()` を Python スクリプト生成に書き換え

生成される `load-data.py` の処理フロー:

1. 環境変数（`PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`）または引数から DB 接続情報を取得
2. Parquet ファイルのパスは引数 `--data-dir` で指定（デフォルト: `postgres/data/{env}/`）
3. 各テーブルについて:
   - pyarrow で Parquet を読み込み
   - pandas DataFrame に変換
   - `io.StringIO` に CSV 形式で書き出し
   - `cursor.copy_expert("COPY table(cols) FROM STDIN CSV HEADER", buffer)` で PostgreSQL にロード

#### 3. `main()` の出力パス変更

- `sh_path` → `py_path`
- ファイル名: `load-data.sh` → `load-data.py`
- `os.chmod(py_path, 0o755)` で実行権限付与

#### 4. `generate-init-scripts.sh` のコメント更新

Usage コメント内の出力ファイル一覧を更新。

### 生成される load-data.py のイメージ

```python
#!/usr/bin/env python3
# Auto-generated from catalog YAML. DO NOT EDIT MANUALLY.
# Generated at: {timestamp}

import io
import os
import sys

import psycopg2
import pyarrow.parquet as pq

DATA_DIR = os.environ.get("DATA_DIR", "/path/to/postgres/data/{env}")

TABLES = [
    {
        "name": "customer_master",
        "columns": ['"customer_id"', '"name"', ...],
    },
    ...
]

def main():
    conn = psycopg2.connect(
        host=os.environ.get("PGHOST", "localhost"),
        port=os.environ.get("PGPORT", "5432"),
        user=os.environ.get("PGUSER", "postgres"),
        password=os.environ.get("PGPASSWORD", "postgres"),
        dbname=os.environ.get("PGDATABASE", "analysis"),
    )
    conn.autocommit = False

    try:
        cur = conn.cursor()
        for table in TABLES:
            load_table(cur, table)
        conn.commit()
        print("All tables loaded successfully.")
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()


def load_table(cur, table_def):
    name = table_def["name"]
    columns = table_def["columns"]
    parquet_path = os.path.join(DATA_DIR, f"{name}.parquet")

    if not os.path.exists(parquet_path):
        print(f"ERROR: {parquet_path} not found", file=sys.stderr)
        sys.exit(1)

    tbl = pq.read_table(parquet_path, columns=[c.strip('"') for c in columns])
    df = tbl.to_pandas()

    buf = io.StringIO()
    df.to_csv(buf, index=False, header=True)
    buf.seek(0)

    cols_str = ", ".join(columns)
    copy_sql = f"COPY {name}({cols_str}) FROM STDIN CSV HEADER"
    cur.copy_expert(copy_sql, buf)
    print(f"  Loaded {name}: {len(df)} rows")


if __name__ == "__main__":
    main()
```

### 技術的な考慮事項

- **依存ライブラリ**: 生成された `load-data.py` はホスト側で実行されるため、ホストに `pyarrow`（インストール済み v23.0.1）と `psycopg2-binary`（要インストール）が必要。`generate_init.py` 自体も pyarrow を使う（スキーマ読み取り）。psql パイプ方式（Parquet → CSV → psql COPY）は CSV に戻すことになり不採用
- **カラム名のクォート**: 日本語カラム名があるため、既存の `quote_ident()` でダブルクォートする方式を継続
- **SERIAL カラムの除外**: `COPY FROM STDIN` では SERIAL カラムは含めない。既存の `read_csv_headers` → カラムフィルタリングロジック（`main()` 内）はそのまま活用
- **エラーハンドリング**: トランザクション内で実行し、途中でエラーが出たらロールバック
- **DATA_DIR のデフォルト値**: 生成時に env に基づいた相対パスを埋め込む（ホスト側のプロジェクトルートからの相対パス）
- **後続タスク 7.3 との分担**: 本タスクは「生成」のみ。`01-init-db.sh` の変更、`rebuild.sh` / `switch-env.sh` からの呼び出し方変更は 7.3 で対応

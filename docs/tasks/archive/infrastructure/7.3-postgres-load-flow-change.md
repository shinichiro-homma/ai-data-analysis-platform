# タスク詳細: 7.3 postgres init スクリプトと DB ロードフローの変更

## 概要

PostgreSQL のデータロードを Docker コンテナ内実行（`01-init-db.sh` → `load-data.sh`）から、ホスト側実行（`load-data.py`）に切り替える。

**理由**: Parquet ファイルのロードには `pyarrow` + `psycopg2` が必要だが、postgres コンテナに Python を入れるのは非効率。ホスト側にはすでにこれらがインストール済みのため、ホスト側から `COPY FROM STDIN` でロードする方式に変更する。

**変更の流れ**:
- Before: Docker 起動 → `01-init-db.sh`（テーブル作成 + データロード）
- After: Docker 起動 → `01-init-db.sh`（テーブル作成のみ） → ホスト側 `load-data.py`（データロード）

## 実装計画

### 変更するファイル

| ファイル | 変更内容 |
|----------|------|
| `postgres/init/01-init-db.sh` | `load-data.sh` の存在確認・実行を削除。`create-tables.sql` の実行のみに簡素化 |
| `scripts/rebuild.sh` | `reinitialize_postgres()` 後にホスト側 `load-data.py` を実行する処理を追加 |
| `scripts/switch-env.sh` | テーブル作成確認後にホスト側 `load-data.py` を実行する処理を追加 |
| `docker-compose.yml` | postgres サービスのデータマウント（`postgres/data/${DATA_ENV}` → `/tmp/data/${DATA_ENV}`）を削除 |
| `postgres/init/production/load-data.sh` | 削除（`generate-init-scripts.sh` が `load-data.py` を生成するため不要） |

### 実装手順

#### Step 1: `01-init-db.sh` の簡素化

`load-data.sh` の存在確認と実行を削除し、`create-tables.sql` の実行のみにする。

```bash
# Before (現在)
echo "=== Step 1: Create tables ==="
psql ... -f "${INIT_DIR}/create-tables.sql"
echo "=== Step 2: Load data ==="
bash "${INIT_DIR}/load-data.sh"

# After (変更後)
echo "=== Creating tables ==="
psql ... -f "${INIT_DIR}/create-tables.sql"
echo "=== Tables created. Data will be loaded from host. ==="
```

#### Step 2: ホスト側ロード関数の共通化

`rebuild.sh` と `switch-env.sh` の両方で使う `load-data.py` 実行処理を、各スクリプト内に関数として実装する。

```bash
run_load_data() {
  local env="${1:-$DATA_ENV}"
  local load_script="postgres/init/${env}/load-data.py"

  if [[ ! -f "$load_script" ]]; then
    echo "ERROR: $load_script not found. Run: scripts/generate-init-scripts.sh $env"
    return 1
  fi

  # .env の POSTGRES_* から PG* 環境変数を設定（ホスト → localhost:5432）
  export PGHOST=localhost
  export PGPORT=5432
  export PGUSER="${POSTGRES_USER:-jupyter}"
  export PGPASSWORD="${POSTGRES_PASSWORD}"
  export PGDATABASE="${POSTGRES_DB:-analysis_db}"

  echo "Loading data from host via $load_script ..."
  python3 "$load_script" || {
    echo "ERROR: Data load failed"
    return 1
  }
  echo "Data loaded successfully."
}
```

#### Step 3: `rebuild.sh` の修正

`reinitialize_postgres()` 関数内で、コンテナ起動・テーブル作成完了後に `load-data.py` を実行する。

現在の `reinitialize_postgres()` は:
1. コンテナ停止 → ボリューム削除 → `docker compose up -d postgres`
2. ヘルスチェック待機

変更後:
1. コンテナ停止 → ボリューム削除 → `docker compose up -d postgres`
2. ヘルスチェック待機（テーブル作成完了を確認）
3. `run_load_data` でホスト側からデータロード

**注意**: 現在の `switch-env.sh` のテーブル数確認ポーリングは、`01-init-db.sh` がテーブル作成のみ行うため引き続き有効。テーブルが存在することを確認してからデータロードを実行する。

#### Step 4: `switch-env.sh` の修正

テーブル作成完了確認後に `load-data.py` を実行する処理を追加する。

現在のフロー:
1. `.env` 書き換え → コンテナ停止 → ボリューム削除 → `docker compose up -d postgres`
2. `pg_isready` 待機 → テーブル数ポーリング → 完了

変更後:
1. `.env` 書き換え → コンテナ停止 → ボリューム削除 → `docker compose up -d postgres`
2. `pg_isready` 待機 → テーブル作成完了確認
3. `run_load_data` でホスト側からデータロード

#### Step 5: production の旧 `load-data.sh` 削除

`postgres/init/production/load-data.sh` を削除する。`generate-init-scripts.sh production` を実行すれば `load-data.py` が生成される。

### 技術的な考慮事項

- **テーブル作成完了の判定方法**: `switch-env.sh` は現在テーブル数 > 0 でポーリングしている。`01-init-db.sh` がテーブル作成のみ行うため、この判定はそのまま使える。テーブルが存在 = `create-tables.sql` 完了 = データロード可能。
- **`load-data.py` の接続情報**: 生成される `load-data.py` は `PGHOST`, `PGPORT` 等の環境変数を参照する。ホスト側から実行するため、`.env` の `POSTGRES_*` 変数を `PG*` 変数にマッピングして設定する（`PGHOST=localhost`, `PGPORT=5432`, `PGUSER=${POSTGRES_USER}`, `PGPASSWORD=${POSTGRES_PASSWORD}`, `PGDATABASE=${POSTGRES_DB}`）。
- **docker-compose.yml のデータマウント削除**: `postgres/data/{DATA_ENV}` → `/tmp/data/{DATA_ENV}` のマウントを削除する。データロードがホスト側に移行するため、コンテナ内にデータファイルをマウントする必要がなくなった。
- **`clean-rebuild.sh` への影響**: `clean-rebuild.sh` は `rebuild.sh` を呼び出すため、`rebuild.sh` の変更が自動的に反映される。
- **`psycopg2-binary` の前提**: ホスト側に `psycopg2-binary` がインストールされている前提（タスク 7.2 で確認済み）。

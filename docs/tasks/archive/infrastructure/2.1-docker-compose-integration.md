# タスク詳細: 2.1 docker-compose 統合

## 概要

プロジェクトルートに統合 docker-compose.yml を作成し、全バックエンドサービス（jupyter-server, document-server, PostgreSQL）を `docker-compose up -d` で一括起動できるようにする。

### なぜこのタスクが必要か

現在の開発環境では以下の問題がある：

1. **docker-compose.yml が jupyter-server/ 配下にあり**、postgres と jupyter-server の 2 サービスのみ定義
2. **document-server は手動起動が必要**（`uvicorn src.main:app --reload --port 3002`）
3. **MCP サーバーの接続先 URL が環境によって異なる**（ローカル vs Docker ネットワーク）

これを解消し、`docker-compose up -d` 一発で分析環境が整う状態にする。

### MCPサーバーの扱い

jupyter-mcp と document-mcp は **stdio トランスポート** を使用する MCP サーバーであり、Claude Desktop / Claude Code がプロセスを直接起動する。Docker コンテナとしての常時起動は不要（MCP クライアントが必要時に spawn する仕組み）。

そのため docker-compose には含めず、接続先の環境変数設定のみ整備する。

### 実装手順

#### ステップ 1: document-server/Dockerfile の作成

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY document-server/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY document-server/src ./src
COPY document-server/data ./data

EXPOSE 3002

CMD ["uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "3002"]
```

- ベースイメージ: `python:3.11-slim`（FastAPI + PyYAML のみなので軽量イメージで十分）
- data/ ディレクトリ（YAML カタログファイル）をコンテナに COPY
- ヘルスチェックは `/health` エンドポイントを使用

#### ステップ 2: プロジェクトルートに docker-compose.yml を作成

サービス定義（3 サービス + 1 DB）：

```yaml
services:
  postgres:
    image: postgres:16
    # ... (既存設定を移植)

  jupyter-server:
    build:
      context: .
      dockerfile: jupyter-server/Dockerfile
    depends_on:
      postgres:
        condition: service_healthy
    # ... (既存設定を移植、パス調整)

  document-server:
    build:
      context: .
      dockerfile: document-server/Dockerfile
    ports:
      - "3002:3002"
    environment:
      - DATA_DIR=/app/data
      - PORT=3002
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3002/health"]
      interval: 10s
      timeout: 5s
      retries: 3
    restart: unless-stopped
```

**ポイント:**
- `build.context` はすべてプロジェクトルート（`.`）を指定
- postgres のボリュームパスを `./postgres/init` に変更（ルートからの相対パス）
- jupyter-server のボリュームパスも同様に調整
- サービス間通信は Docker ネットワークのサービス名で行う

#### ステップ 3: 環境変数の統合

プロジェクトルートに `.env.example` を作成：

```env
# PostgreSQL
POSTGRES_DB=analysis_db
POSTGRES_USER=jupyter
POSTGRES_PASSWORD=your-postgres-password-here

# Jupyter Server
JUPYTER_TOKEN=your-secret-token-here

# MCP Servers (ローカル実行時の接続先)
JUPYTER_SERVER_URL=http://localhost:8888
DOCUMENT_SERVER_URL=http://localhost:3002
```

#### ステップ 4: 既存 docker-compose.yml の廃止

- `jupyter-server/docker-compose.yml` を削除
- `jupyter-server/.env.example` を削除（ルートに統合）
- `jupyter-server/.env` の内容をルート `.env` に移行するよう README 等で案内

#### ステップ 5: ヘルスチェックの確認・追加

| サービス | ヘルスチェック | 状態 |
|----------|--------------|------|
| postgres | `pg_isready -U jupyter -d analysis_db` | 既存 |
| jupyter-server | `/usr/local/bin/healthcheck.sh` | 既存 |
| document-server | `curl -f http://localhost:3002/health` | 新規追加 |

#### ステップ 6: 動作確認

1. `docker-compose up -d` で全サービスが起動すること
2. `docker-compose ps` で全サービスが healthy 状態になること
3. 各サービスへのアクセス確認：
   - http://localhost:8888 (JupyterLab UI)
   - http://localhost:3002/health (document-server)
   - PostgreSQL 接続（port 5432）
4. MCP サーバーがローカルから Docker サービスに接続できること

### 技術的な考慮事項

#### 1. build context の統一

jupyter-server の Dockerfile は `COPY jupyterlab-ai-sync /tmp/jupyterlab-ai-sync` でプロジェクトルート相対のパスを使用している。`build.context: .` を指定することで、プロジェクトルートを build context として渡す。document-server も同様のパターンにする。

#### 2. document-server の data/ ディレクトリ

document-server は YAML ファイル（カタログ、用語集、ロジック定義）を `data/` ディレクトリから読み込む。以下の 2 つの方式がある：

- **COPY 方式**（採用）: Dockerfile で `COPY document-server/data ./data` としてイメージに含める。YAML データは頻繁に変更されないため、イメージに含めて問題ない。
- **バインドマウント方式**: docker-compose で `volumes: - ./document-server/data:/app/data` とする。開発時にホスト側で YAML を編集して即反映したい場合に有用。

→ 本番向けには COPY 方式を採用し、開発利便性のためにバインドマウントも docker-compose に追記する（COPY 内容をオーバーライド）。

#### 3. MCP サーバーの接続先

MCP サーバー（jupyter-mcp, document-mcp）はローカルで実行され、Docker サービスのポートフォワーディング経由で接続する：

- `jupyter-mcp` → `http://localhost:8888`（jupyter-server の公開ポート）
- `document-mcp` → `http://localhost:3002`（document-server の公開ポート）

既存の `.env` 設定のデフォルト値がそのまま使えるため、MCP サーバー側のコード変更は不要。

#### 4. Docker ネットワーク

Docker Compose のデフォルトネットワークを使用する。明示的なネットワーク定義は不要（サービス名でのDNS解決はデフォルトで有効）。

jupyter-server コンテナ内の Jupyter カーネルが PostgreSQL に接続する際は `DATABASE_URL=postgresql://jupyter:password@postgres:5432/analysis_db` のようにサービス名 `postgres` を使用する（既存の設定を維持）。

## テスト計画

### 手動テスト

1. **起動テスト**: `docker-compose up -d` → 全コンテナが起動 → `docker-compose ps` で healthy 確認
2. **JupyterLab アクセス**: ブラウザで http://localhost:8888 を開き、トークン認証後にノートブックを操作
3. **document-server API**: `curl http://localhost:3002/health` → 正常応答
4. **PostgreSQL 接続**: JupyterLab からノートブックで `SELECT count(*) FROM customer_master` を実行して結果確認
5. **MCP 接続テスト**: jupyter-mcp をローカルで起動し、Docker 上の jupyter-server にツール実行
6. **停止テスト**: `docker-compose down` → 全コンテナが停止 → ボリュームは永続化

### スクリプトによる確認

```bash
# 起動
docker-compose up -d

# 全サービスの健全性確認
docker-compose ps --format json | jq -r '.[] | .Name + ": " + .Health'

# document-server API 確認
curl -s http://localhost:3002/health | jq .

# JupyterLab 確認
curl -s -H "Authorization: token ${JUPYTER_TOKEN}" http://localhost:8888/api/status | jq .

# PostgreSQL 確認
docker-compose exec postgres psql -U jupyter -d analysis_db -c "SELECT count(*) FROM customer_master;"

# 停止
docker-compose down
```

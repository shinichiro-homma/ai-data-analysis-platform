# タスク詳細: 5.1 postgres/init 環境別分離 + ディスパッチャー

## 概要

postgres/init/ ディレクトリを環境別（sample/production）に分離し、`DATA_ENV` 環境変数に応じて適切な環境のスクリプトを実行するディスパッチャー（`01-init-db.sh`）を作成する。

現在は `postgres/init/01-create-tables.sql` と `postgres/init/02-load-data.sh` がフラットに配置されており、sample 環境のテーブル定義がハードコードされている。これをタスク 5.2（init スクリプト自動生成）の前提として、環境別ディレクトリに分離する。

## 関連ドキュメント

- テーブル追加ガイド: `docs/guides/add-table.md`（initスクリプトの環境別管理について既に記載済み）
- 開発プラン: `docs/plan/04-infrastructure.md` Phase 5

## 実装計画

### 作成・変更するファイル

| ファイル | 内容 |
|----------|------|
| `postgres/init/01-init-db.sh` | ディスパッチャー。`DATA_ENV` に応じて `postgres/init/{ENV}/` 配下のスクリプトを実行 |
| `postgres/init/sample/create-tables.sql` | 既存の `01-create-tables.sql` を移動 |
| `postgres/init/sample/load-data.sh` | 既存の `02-load-data.sh` を移動（`DATA_ENV` 参照を削除し、固定パスに変更） |
| `postgres/init/01-create-tables.sql` | **削除** |
| `postgres/init/02-load-data.sh` | **削除** |
| `docker-compose.yml` | 変更なし（`./postgres/init:/docker-entrypoint-initdb.d` のままで動作する） |
| `.gitignore` | 変更なし（`postgres/init/production/` は既に登録済み） |

### 実装手順

1. **`postgres/init/sample/` ディレクトリ作成**
   - `mkdir -p postgres/init/sample`

2. **既存スクリプトを sample/ に移動**
   - `postgres/init/01-create-tables.sql` → `postgres/init/sample/create-tables.sql`
   - `postgres/init/02-load-data.sh` → `postgres/init/sample/load-data.sh`
   - `load-data.sh` 内の `DATA_ENV` 参照を削除し、`/tmp/data/sample` を固定パスとする（環境切り替えはディスパッチャーが担当するため）

3. **`postgres/init/production/` ディレクトリ作成**
   - `mkdir -p postgres/init/production`
   - `.gitkeep` を配置（production スクリプトは自動生成されるため、初期状態は空）

4. **ディスパッチャー `postgres/init/01-init-db.sh` を作成**
   - `DATA_ENV` 環境変数を読み取り（デフォルト: `sample`）
   - バリデーション（`sample` | `production` のみ許可）
   - `/docker-entrypoint-initdb.d/{ENV}/create-tables.sql` を `psql` で実行
   - `/docker-entrypoint-initdb.d/{ENV}/load-data.sh` を `bash` で実行
   - スクリプトが存在しない場合はエラーメッセージを出して終了

5. **動作確認**
   - `docker-compose down -v` → `docker-compose up -d postgres` で sample 環境が正常に初期化されることを確認

### 技術的な考慮事項

- **docker-entrypoint-initdb.d の実行順序**: PostgreSQL の公式イメージは `/docker-entrypoint-initdb.d/` 配下の `.sh` と `.sql` をアルファベット順に実行する。`01-init-db.sh` がディスパッチャーとして最初に実行され、サブディレクトリの `create-tables.sql` と `load-data.sh` はディスパッチャーから明示的に呼び出す。サブディレクトリ内のファイルは `.sql`/`.sh` 拡張子だが、ディスパッチャーが明示的に実行するため、PostgreSQL の自動実行とは重複しない（サブディレクトリ内のファイルは自動実行の対象外）。
- **load-data.sh の DATA_ENV 参照**: 現在の `02-load-data.sh` は `DATA_ENV` を参照して `/tmp/data/{ENV}` パスを構築している。環境別ディレクトリに分離後は、各 `load-data.sh` が固定パス（`/tmp/data/sample` or `/tmp/data/production`）を参照するように変更する。
- **production ディレクトリ**: `.gitignore` に `postgres/init/production/` が既に登録済み。タスク 5.2 の自動生成スクリプトが production 用のスクリプトを生成する。

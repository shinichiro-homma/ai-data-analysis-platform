# タスク詳細: 2.3 パフォーマンス確認

## 概要

全コンポーネントの応答時間が要件定義の非機能要件（NF1）を満たしていることを検証するパフォーマンステストを実装・実行する。

各コンポーネントのパフォーマンス要件：

| コンポーネント | 要件 | 出典 |
|---|---|---|
| document-server | API応答時間 200ms以内 | NF1 |
| document-server | 起動時間 5秒以内（100テーブル規模） | NF1 |
| document-mcp | document-server応答 + 50ms以内 | NF1 |
| jupyter-mcp | jupyter-server応答 + 100ms以内 | NF1 |

### 実装手順

#### ステップ 1: パフォーマンステストファイルの作成

`tests/e2e/performance.test.ts` を新規作成する。既存の `tests/e2e/helpers/api-client.ts` と `vitest` 基盤をそのまま再利用する。

#### ステップ 2: document-server API 応答時間テスト

各エンドポイントに対してリクエストを送り、応答時間が 200ms 以内であることを検証する。

対象エンドポイント（計7つ）：
- `GET /catalog/index`
- `POST /catalog/tables`（テーブル名指定）
- `GET /glossary/index`
- `POST /glossary/terms`（用語名指定）
- `GET /logic/index`
- `POST /logic/meta`（ロジック名指定）
- `GET /logic/code/{logic_name}`

**測定方法:**
```typescript
const start = performance.now();
const result = await getTableIndex();
const elapsed = performance.now() - start;
expect(elapsed).toBeLessThan(200);
```

安定性のため、各エンドポイントを複数回（5回）呼び出し、全回が200ms以内であることを確認する。初回はウォームアップとして除外する。

#### ステップ 3: document-server 起動時間テスト

`docker-compose` のヘルスチェック通過までの時間、または `/health` エンドポイントの応答で起動完了を確認する。

ただし、テスト実行時点ではサービスは起動済みのため、この項目は docker-compose ログから手動確認とする。テストファイル内にはコメントとして記載する。

#### ステップ 4: MCP オーバーヘッド計測（document-mcp）

document-mcp のオーバーヘッド（document-server応答 + 50ms以内）を検証する。

E2Eテストは REST API を直接呼び出すため、MCP 層のオーバーヘッドは直接測定できない。代わりに以下の方針で対応する：

- document-mcp の統合テスト（`document-mcp/tests/integration/`）に計測ロジックを追加
- MCP ツール呼び出し時間と、同等の REST API 直接呼び出し時間を比較
- 差分が 50ms 以内であることを検証

**ファイル:** `document-mcp/tests/integration/performance.test.ts` を新規作成

#### ステップ 5: MCP オーバーヘッド計測（jupyter-mcp）

jupyter-mcp のオーバーヘッド（jupyter-server応答 + 100ms以内）を検証する。

ステップ4と同様の方針で対応する：

- jupyter-mcp の統合テスト（`jupyter-mcp/tests/integration/`）に計測ロジックを追加
- MCP ツール呼び出し時間と、同等の REST API 直接呼び出し時間を比較
- 差分が 100ms 以内であることを検証

**ファイル:** `jupyter-mcp/tests/integration/performance.test.ts` を新規作成

#### ステップ 6: テスト実行と結果確認

```bash
# 全サービス起動
docker-compose up -d

# E2Eパフォーマンステスト
cd tests/e2e && npx vitest run performance.test.ts

# document-mcp オーバーヘッドテスト
cd document-mcp && npx vitest run --config vitest.config.integration.ts tests/integration/performance.test.ts

# jupyter-mcp オーバーヘッドテスト
cd jupyter-mcp && npx vitest run --config vitest.config.integration.ts tests/integration/performance.test.ts
```

### 技術的な考慮事項

- **ウォームアップ**: 初回リクエストはJIT・キャッシュ等の影響で遅くなるため、ウォームアップ1回を含め、2回目以降の結果で判定する
- **計測方法**: `performance.now()` を使用（ミリ秒精度）
- **環境依存**: CI環境やDockerのリソース制限で結果が変わる可能性がある。閾値は要件定義の値をそのまま使うが、環境差を考慮してテスト失敗時のメッセージに計測値を含める
- **MCP オーバーヘッド計測**: MCP サーバーはstdio通信のため、E2Eテスト（REST API直接）では測定できない。各コンポーネントの統合テストレベルで、MCPクライアントを経由した呼び出しと REST 直接呼び出しを比較する
- **既存テストとの棲み分け**: 12.2 のE2Eテストは機能正常性の検証、12.3 は応答時間の検証。テストファイルを分離し独立して実行可能にする

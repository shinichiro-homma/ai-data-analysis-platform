# タスク詳細: 7.5 既存データの Parquet 移行と動作確認

## 概要

Infrastructure Phase 7（CSV → Parquet 移行）のタスク 7.1〜7.4 で構築した仕組みを使い、実際のデータを Parquet に移行して動作確認を行う。

現状:
- `postgres/data/sample/` に CSV と Parquet が**両方**存在している（CSV は不要だが残ったまま）
- `postgres/data/csv/sample/` に CSV のコピーが配置済み（27.1 で実施）
- `postgres/data/production/` に CSV のみが存在（Parquet 未生成、`csv/` への移動も未実施）
- `postgres/init/production/` に `load-data.py` が存在しない

このタスクで以下を実施する:
1. `generate_init.py` を修正し、カタログ YAML とデータファイルの整合性ルールを実装する
2. sample / production 両環境のデータを Parquet に移行し、DB ロード → スモークテストで正常動作を確認する

### データ整合性ルール

| カタログ YAML | Parquet ファイル | 動作 |
|---------------|-----------------|------|
| あり | あり | CREATE TABLE + データロード（通常動作） |
| あり | なし | **CREATE TABLE もデータロードもスキップ**（YAML は保持） |
| なし | あり | **スキップ**（カタログに定義がないデータはロードしない） |

### 実装手順

#### Step 1: `generate_init.py` の修正

`generate_create_tables()` を修正し、Parquet が存在しないテーブルの CREATE TABLE 文を生成しないようにする。

**現在の動作:**
- `generate_create_tables()` は全テーブルの CREATE TABLE を生成する
- `generate_load_data()` は Parquet があるテーブルのみロード対象にする（既に実装済み）

**修正後の動作:**
- `generate_create_tables()` も Parquet があるテーブルのみ CREATE TABLE を生成する
- Parquet がないテーブルは INFO ログを出して CREATE TABLE をスキップする
- カタログ YAML はそのまま残る（document-server からは引き続き参照可能）

なお「カタログ YAML なし + Parquet あり」のケースは、`generate_init.py` が `index.yaml` のエントリのみを処理するため、既にスキップされている（追加対応不要）。

#### Step 2: sample 環境の CSV 削除

`postgres/data/sample/` から不要な CSV ファイルを削除する。Parquet と `csv/sample/` のコピーが存在するため、安全に削除可能。

```bash
git rm postgres/data/sample/customer_master.csv
git rm postgres/data/sample/product_master.csv
git rm postgres/data/sample/purchase_history.csv
```

#### Step 3: sample 環境の init スクリプト再生成 + DB ロード確認

```bash
# init スクリプト再生成 → クリーンリビルド
scripts/clean-rebuild.sh --env sample -y
```

#### Step 4: sample 環境のスモークテスト

```bash
scripts/smoke-test.sh
```

#### Step 5: production 環境の CSV 移動

production の CSV ファイルを `postgres/data/csv/production/` に移動する。production データは `.gitignore` 対象のため手動操作。

```bash
mv postgres/data/production/*.csv postgres/data/csv/production/
```

#### Step 6: production 環境の Parquet 変換

```bash
scripts/convert-csv-to-parquet.py production
```

#### Step 7: production 環境の init スクリプト生成

```bash
# カタログ YAML から create-tables.sql + load-data.py を生成
# Parquet がないテーブルは CREATE TABLE もスキップされる
scripts/generate-init-scripts.sh production
```

#### Step 8: production 環境の DB ロード確認

```bash
scripts/switch-env.sh production
```

#### Step 9: production 環境のスモークテスト

```bash
scripts/smoke-test.sh
```

#### Step 10: sample 環境に戻す

```bash
scripts/switch-env.sh sample
```

### 技術的な考慮事項

- **generate_init.py の修正範囲**: `generate_create_tables()` のみ。`generate_load_data()` は既に Parquet 存在チェック済み
- **カタログ YAML の扱い**: Parquet がないテーブルのカタログ YAML は削除しない。document-server からは引き続きテーブル定義（スキーマ情報）を参照できる。DB にテーブルが存在しないだけ
- **sample CSV の git 管理**: `postgres/data/sample/*.csv` は git にコミットされている。`git rm` で追跡を停止し、`postgres/data/csv/sample/` の CSV のみを保持する
- **production データ**: `.gitignore` 対象のため、移動は手動操作。CSV ファイルが大量（dm_*, dwh_* 等）にある可能性がある
- **鮮度チェックとの整合**: `rebuild.sh` の鮮度チェックが `*.csv` と `*.parquet` の両方を見るため、`data/sample/` から CSV を削除しないと不要な再初期化が発生する
- **csv/ ディレクトリの位置づけ**: `postgres/data/csv/` は Parquet 変換の入力元として保持する仮置きディレクトリ。Parquet 変換後も残しておく（再変換の `--force` オプションで使用可能）

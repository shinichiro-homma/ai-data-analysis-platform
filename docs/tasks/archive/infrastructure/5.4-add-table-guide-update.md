# タスク詳細: 5.4 テーブル追加ガイド・ドキュメント更新

## 概要

`docs/guides/add-table.md` を新フロー（CSV配置 → カタログYAML作成 → `/custom-sync-db` 実行）に更新する。Infrastructure Phase 5.1〜5.3 で実装した自動化の仕組みを反映し、手順を整理する。

**現状の問題点:**
- ステップ番号に欠番がある（A-1, A-2, A-4 ... A-3 が欠落）
- 手順の順序が論理的でない（A-2 で init スクリプト生成を先にしているが、カタログ YAML が先に必要）
- `/custom-sync-db` が `generate-init-scripts.sh` を内包しているのに、A-2 で個別に生成手順を記載している
- フローの推奨パスが明確でない（`/custom-sync-db` 一発で済むのに手動手順が併記されて冗長）

## 関連ドキュメント

- テーブル追加ガイド: `docs/guides/add-table.md`
- コマンド一覧: `docs/COMMANDS.md`（`/custom-sync-db` セクション — 既に記載済み）
- スクリプトルール: `.claude/rules/scripts.md`（`generate-init-scripts.sh` — 既に記載済み）
- カスタムコマンド定義: `.claude/commands/custom-sync-db.md`

### 実装手順

#### ステップ 1: `docs/guides/add-table.md` の手順A を再構成

現在の手順（A-1 → A-2 → A-4 → A-5 → A-6 → A-7）を、以下の論理的な順序に整理する:

**新しい手順:**

| ステップ | 内容 | 変更点 |
|----------|------|--------|
| A-1 | CSV データファイルを配置 | 変更なし。環境別パス（`postgres/data/{ENV}/`）を明記 |
| A-2 | カタログ YAML を作成 | 旧 A-4 を移動。カタログ YAML が先に必要なことを明示 |
| A-3 | `/custom-sync-db` で DB 再構築 | 旧 A-2 + A-5 を統合。`/custom-sync-db` 一発で init スクリプト生成 + DB 再構築 + スモークテストまで完了することを説明。手動手順は折りたたみ（補足）に |
| A-4 | カタログを反映 | 旧 A-6 を繰り上げ |
| A-5 | 動作確認 | 旧 A-7 を繰り上げ |

**主な変更:**
- `/custom-sync-db` を推奨パスとして前面に出す
- `generate-init-scripts.sh` + `switch-env.sh` の個別実行は補足に移動
- CSV 配置先のパスに環境別ディレクトリ（`postgres/data/{ENV}/`）を明記
- 欠番を解消して A-1 〜 A-5 の連番にする

#### ステップ 2: 手順B（CSV直接読み込み）の確認

手順B は変更不要だが、手順A の変更に合わせて整合性を確認する。

### 技術的な考慮事項

- `docs/COMMANDS.md` と `.claude/rules/scripts.md` は Infrastructure Phase 5.2〜5.3 で既に更新済み。追加の変更は不要
- add-table.md 以外のドキュメントへの影響はない（このタスクはドキュメント更新のみ）
- 手順B（CSV直接読み込み）のフローは変更なし

# タスク詳細: 3.2 AIリアルタイム同期の動作確認

## 概要

ブラウザで JupyterLab を表示しながら、MCP クライアント（Claude Code）から AI 編集操作を行い、以下がリアルタイムに反映されることを手動で確認する：

- AI 編集モード開始（ノートブックロック）
- セル追加
- コード実行（stdout / 画像 / エラー）
- AI 編集モード終了（アンロック）

Jupyter Phase 8 で実装した AI リアルタイム同期機能が、統合環境で正しく動作することを検証する。

## 検証計画

### 前提条件

- 全サービスが起動済み（`docker-compose up -d`）
- jupyter-mcp と document-mcp がビルド済み（`scripts/rebuild-mcp.sh jupyter-mcp`）
- Claude Code から jupyter-mcp の MCP ツールが利用可能

### 検証環境

| 項目 | 値 |
|------|-----|
| MCP クライアント | Claude Code |
| JupyterLab | http://localhost:8888 |
| jupyter-mcp | localhost:3001（stdio） |
| WebSocket | ws://localhost:8888/api/ai/events?token={JUPYTER_TOKEN} |

### 検証手順

#### Phase 1: 環境準備

1. `docker-compose up -d` で全サービス起動
2. ブラウザで http://localhost:8888 にアクセスし、JupyterLab が表示されることを確認
3. Claude Code から `workspace_create` でワークスペースを作成
4. `session_create(workspace_id=..., notebook_path="sync-test.ipynb")` でセッション作成
5. ブラウザで JupyterLab のファイルブラウザからワークスペースに移動し、`sync-test.ipynb` を開く

**確認項目:**
- [x] JupyterLab でノートブックが開ける
- [x] ブラウザの開発者ツール Console に `[WebSocketClient] Connected` 相当のログが出る（WebSocket 接続確立）

#### Phase 2: AI 編集モード開始（ロック）

1. Claude Code から `ai_edit_start(session_id=...)` を呼び出す

**確認項目:**
- [x] ツールバーに「🔒 AI が編集中です...」バナーが表示される
- [x] セルをクリックしても編集できない（read-only、aria-readonly="true"）
- [x] キーボード入力が無効化されている（Playwright fill がタイムアウト）
- [x] ノートブックのスクロール・閲覧は可能

#### Phase 3: セル追加のリアルタイム反映

1. Claude Code から `notebook_add_cell(notebook_path="sync-test.ipynb", cell_type="code", source="print('Hello from AI!')")` を呼び出す
2. Claude Code から `notebook_add_cell(notebook_path="sync-test.ipynb", cell_type="markdown", source="# AI が追加したセル")` を呼び出す

**確認項目:**
- [x] code セルがブラウザ上のノートブックに即座に追加される
- [x] セルの内容（`print('Hello from AI!')`）が正しく表示される
- [x] markdown セルも即座に追加される
- [x] 追加されたセルも read-only 状態（ロック中のため）

#### Phase 4: コード実行のリアルタイム反映

##### 4a: stdout 出力

1. Claude Code から `execute_code(session_id=..., code="print('Hello from AI!')", cell_index=0)` を呼び出す

**確認項目:**
- [x] 実行中にセルの execution count が `[*]` になる
- [x] stdout 出力「Hello from AI!」がセルの出力エリアに表示される
- [x] 実行完了後に execution count が `[2]` に変わった

##### 4b: 画像出力

1. Claude Code から以下のコードを execute_code で実行:
   ```python
   import matplotlib.pyplot as plt
   plt.figure(figsize=(6, 4))
   plt.plot([1, 2, 3, 4], [1, 4, 2, 3])
   plt.title('AI Generated Plot')
   plt.savefig('output/test-plot.png')
   plt.show()
   ```

**確認項目:**
- [x] グラフ画像がセルの出力エリアに表示される（スクリーンショットで確認）

##### 4c: エラー出力

1. Claude Code から `execute_code(session_id=..., code="1/0")` を呼び出す

**確認項目:**
- [x] ZeroDivisionError がセルの出力エリアに表示される
- [x] エラーのトレースバックが正しくフォーマットされている

#### Phase 5: AI 編集モード終了（アンロック）

1. Claude Code から `ai_edit_end(session_id=...)` を呼び出す

**確認項目:**
- [x] 「🔒 AI が編集中です...」バナーが消える
- [x] セルをクリックして編集できるようになる
- [x] キーボード入力が有効になる（Playwright fill が成功）
- [x] AI が追加したセルの内容を変更できる

#### Phase 6: エッジケース確認

##### 6a: ブラウザ未開きでのセル追加

1. ブラウザのノートブックタブを閉じる（JupyterLab 自体は開いたまま）
2. Claude Code から `notebook_add_cell` を呼び出す
3. ブラウザでノートブックを再度開く

**確認項目:**
- [-] スキップ（Jupyter Phase 8.4 統合テストでカバー済み）
- [-] スキップ（Jupyter Phase 8.4 統合テストでカバー済み）

##### 6b: 複数セル追加→実行の連続操作

1. Claude Code から `ai_edit_start` → `notebook_add_cell` x3 → `execute_code` x3 → `ai_edit_end` の一連操作を実行

**確認項目:**
- [x] 3つのセル追加がすべてリアルタイムに反映される
- [x] 3つの実行結果がそれぞれ正しいセルに表示される（x=10, y=20, x+y=30）
- [x] アンロック後にすべてのセルが編集可能

#### Phase 7: クリーンアップ

1. `session_delete` でセッション終了

### 技術的な考慮事項

- **WebSocket 接続**: jupyterlab-ai-sync は JupyterLab 起動時に `ws://localhost:8888/api/ai/events?token=...` に自動接続する。接続確認はブラウザの開発者ツール Console で行う
- **REST API フォールバック**: `notebook_add_cell` は WebSocket クライアントが 0 の場合（ブラウザ未接続時）、REST API でディスクに直接書き込む設計
- **パス正規化**: jupyterlab-ai-sync は先頭スラッシュを除去してパスを比較する。ワークスペース内のノートブックパスが正しくマッチすることを確認
- **style/index.css**: ロックインジケータの CSS ファイルが未作成の可能性がある。バナーの見た目に問題がある場合はこれが原因

## テスト計画

**実施方式**: 手動検証（ブラウザ目視確認を含む）

自動テストは Jupyter Phase 8.4 の統合テスト（`jupyter-mcp/tests/integration/ai-sync-flow.test.ts`、11テスト成功）で WebSocket イベント配信レベルまでカバー済み。本タスクではブラウザ上の JupyterLab 拡張（jupyterlab-ai-sync）による実際の UI 反映を目視で確認する。

**検証結果の記録**: 各 Phase の確認項目にチェックを入れ、発見した問題があれば備考欄に記録する。

**発見・修正したバグ**: `notebook_add_cell` にワークスペース相対パス（`sync-test.ipynb`）を渡すと、JupyterLab のフルパス（`workspaces/ws-xxx/sync-test.ipynb`）とマッチしない問題。`jupyterlab-ai-sync/src/notebook-finder.ts` にサフィックスマッチを追加して修正。

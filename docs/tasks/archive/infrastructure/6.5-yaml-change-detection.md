# タスク詳細: 6.5 YAML データ変更の自動検出・反映

## 概要

`check-freshness.sh` に document-server の YAML データ鮮度チェックを追加し、`--rebuild` オプションで自動反映を可能にする。また postgres-init が STALE の場合の `--rebuild` 処理を改善し、`generate-init-scripts.sh` だけでなく `switch-env.sh` も連鎖実行するようにする。

## 実装計画

|----------|----------|

### 実装手順

#### 1. document-server YAML データの鮮度チェック追加

document-server の YAML データは bind mount でコンテナ内にマウントされているが、uvicorn が `--reload` なしで起動しているため、コンテナ再起動が必要。

```bash
check_document_data() {
  local data_env
  data_env=$(grep -E '^DATA_ENV=' .env 2>/dev/null | cut -d= -f2 || echo "sample")
  data_env="${data_env:-sample}"

  local data_dir="document-server/data/${data_env}"

  if [[ ! -d "$data_dir" ]]; then
    echo "  document-server (data): SKIP (data dir not found)"
    return
  fi

  local ds_epoch
  ds_epoch=$(container_epoch "document-server")

  if [[ -z "$ds_epoch" ]]; then
    echo "  document-server (data): SKIP (container not found)"
    return
  fi

  local newest_yaml
  newest_yaml=$(newest_file_epoch "$data_dir" "*.yaml" "*.yml")

  if [[ -z "$newest_yaml" ]]; then
    echo "  document-server (data): SKIP (no YAML files)"
    return
  fi

  if [[ "$newest_yaml" -gt "$ds_epoch" ]]; then
    echo "  document-server (data): STALE (YAML updated after container start, run: docker compose restart document-server)"
    STALE+=("document-server-data")
  else
    echo "  document-server (data): OK"
  fi
}
```

#### 2. postgres-init の --rebuild 改善

現在の `--rebuild` 処理では `postgres-init` が STALE の場合に `generate-init-scripts.sh` のみを実行するが、生成した init スクリプトを DB に反映するには `switch-env.sh` も必要。

```bash
# 現在
postgres-init)
  scripts/generate-init-scripts.sh "$CURRENT_DATA_ENV"
  ;;

# 改善: generate + DB 再初期化
postgres-init)
  scripts/generate-init-scripts.sh "$CURRENT_DATA_ENV"
  # init スクリプトを再生成したら DB も再初期化する
  scripts/switch-env.sh "$CURRENT_DATA_ENV" -y
  ;;
```

#### 3. document-server-data の --rebuild 処理追加

```bash
document-server-data)
  echo "  Restarting document-server to reload YAML data"
  docker compose restart document-server
  ;;
```

### 技術的な考慮事項

- document-server は `POST /admin/reload` エンドポイントでもデータ再読み込みが可能だが、`docker compose restart` の方が確実（Python コードの変更も含めて反映される）
- `switch-env.sh` は postgres_data ボリュームを削除して再作成するため、データベースの内容が完全にリセットされる
- `postgres-init` と `postgres-data` が同時に STALE の場合、`switch-env.sh` が 2 回実行されないよう順序を制御する

## テスト計画

```bash
# 1. YAML を変更して STALE を検出
touch document-server/data/sample/catalog/tables/some.yaml
scripts/check-freshness.sh  # → document-server (data): STALE

# 2. --rebuild で自動再起動
scripts/check-freshness.sh --rebuild  # → document-server restart
scripts/check-freshness.sh  # → document-server (data): OK

# 3. カタログ YAML を変更して postgres-init STALE
touch document-server/data/sample/catalog/tables/some.yaml
scripts/check-freshness.sh  # → postgres (init): STALE

# 4. --rebuild で generate + switch-env が連鎖実行
scripts/check-freshness.sh --rebuild
scripts/check-freshness.sh  # → postgres (init): OK, postgres (data): OK
```

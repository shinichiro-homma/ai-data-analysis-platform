# タスク詳細: 6.4 test.sh の --rebuild 改善

## 概要

`test.sh --rebuild` が MCP + Docker の両方を自動リビルドするよう改善する。現在 `--rebuild` は統合テスト（`--integration`）時のみ有効で、通常テストでは無視される。また MCP コンポーネントのリビルドには `rebuild-mcp.sh` ではなくインラインの `npm run build` を使っている。

タスク 6.1（check-freshness.sh バグ修正）の完了後に実施する。

## 関連ドキュメント

- ルール: `.claude/rules/scripts.md` — スクリプト利用ルール
- ルール: `.claude/rules/rebuild-before-test.md` — リビルド必須ルール

## 実装計画

### 修正するファイル

| ファイル | 修正内容 |
|----------|----------|
| `scripts/test.sh` | `--rebuild` を通常テストでも有効にし、コンポーネント種別に応じて `rebuild-mcp.sh` / `rebuild.sh` を呼び出す |

### 実装手順

1. `--rebuild` フラグのパース処理を確認（現在は `--integration` と結合している箇所を分離）
2. リビルド処理をコンポーネント種別で分岐：
   - MCP コンポーネント（jupyter-mcp, document-mcp）→ `scripts/rebuild-mcp.sh "$TARGET"`
   - Docker コンポーネント（jupyter-server, document-server）→ `scripts/rebuild.sh "$TARGET"`
   - 全コンポーネント指定なし → `scripts/rebuild-mcp.sh && scripts/rebuild.sh`
3. リビルド前に `check-freshness.sh` で鮮度確認し、FRESH ならスキップ（オプション）
4. 既存の `--integration --rebuild` 動作との互換性を維持

### 修正イメージ

```bash
# --rebuild 時の処理（コンポーネント種別に応じて分岐）
if [[ "$REBUILD" == "true" ]]; then
  case "$TARGET" in
    jupyter-mcp|document-mcp)
      scripts/rebuild-mcp.sh "$TARGET"
      ;;
    jupyter-server|document-server)
      scripts/rebuild.sh "$TARGET"
      ;;
    *)
      # 全コンポーネント
      scripts/rebuild-mcp.sh
      scripts/rebuild.sh
      ;;
  esac
fi
```

### 技術的な考慮事項

- `rebuild-mcp.sh` は引数なしで全 MCP サーバーをビルドする
- `rebuild.sh` は引数なしで全 Docker サービスをリビルドする
- リビルドに失敗した場合は `set -e` によりテストまで進まない
- 既存のインライン `npm run build`（統合テスト前処理）を `rebuild-mcp.sh` 呼び出しに統一する

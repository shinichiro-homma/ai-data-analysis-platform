# タスク詳細: 7.4 鮮度チェックの Parquet 対応

## 概要

`check-freshness.sh` の postgres 鮮度チェックが Parquet ファイル（`*.parquet`）と Python ロードスクリプト（`*.py`）を検出できるように修正する。

タスク 7.1〜7.3 でデータロード形式を CSV → Parquet、load-data.sh → load-data.py に変更したが、`check-freshness.sh` の glob パターンが旧形式のままであり、Parquet ファイルや Python スクリプトの更新を検出できない。`rebuild.sh` は既に対応済み。

## 関連ドキュメント

- ルール: `.claude/rules/freshness-check.md` — 鮮度チェックの仕様
- ルール: `.claude/rules/scripts.md` — スクリプト利用ルール
- タスク計画: `docs/tasks/infrastructure/7.3-postgres-load-flow-change.md` — DB ロードフロー変更の詳細

## 実装計画

### 修正するファイル

| ファイル | 修正内容 |
|----------|----------|
| `scripts/check-freshness.sh` | glob パターンに `*.py` と `*.parquet` を追加 |

### 修正箇所の詳細

#### 1. `check_postgres_init` 関数（行 233 付近）

```bash
# Before
newest_init=$(newest_file_epoch "$init_dir" "*.sql" "*.sh")

# After
newest_init=$(newest_file_epoch "$init_dir" "*.sql" "*.sh" "*.py")
```

#### 2. `check_postgres_data` 関数 — init 鮮度チェック（行 271 付近）

```bash
# Before
init_epoch=$(newest_file_epoch "$init_dir" "*.sql" "*.sh")

# After
init_epoch=$(newest_file_epoch "$init_dir" "*.sql" "*.sh" "*.py")
```

#### 3. `check_postgres_data` 関数 — データ鮮度チェック（行 280 付近）

```bash
# Before
newest_csv=$(newest_file_epoch "$csv_dir" "*.csv")

# After
newest_csv=$(newest_file_epoch "$csv_dir" "*.csv" "*.parquet")
```

#### 4. ヘルプテキスト（行 26 付近）

```
# Before
postgres (data): init スクリプト + CSV vs postgres コンテナ

# After
postgres (data): init スクリプト + CSV/Parquet vs postgres コンテナ
```

### 技術的な考慮事項

- `rebuild.sh` は既に `*.py` と `*.parquet` を glob パターンに含んでおり、修正不要
- `switch-env.sh` は `common.sh` の `run_load_data()` を呼んでおり、既に `load-data.py` を参照しているため修正不要
- 変数名 `newest_csv` は実態と合わなくなるが、動作に影響しないため変更しない（過剰なリファクタリングを避ける）
- `*.sh` パターンは残す（後方互換性。旧 load-data.sh が存在する環境でも動作するように）

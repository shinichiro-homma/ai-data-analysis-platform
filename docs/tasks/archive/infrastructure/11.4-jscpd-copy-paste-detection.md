# タスク詳細: 11.4 コピペ検出（jscpd・informational）

## 概要

jscpd を CI の informational ジョブとして導入し、コードの重複率を可視化する。不変条件 I8（rule of three）の違反候補を PR 単位で検出するが、誤検知の切り分け期間として CI はブロックしない。

## 関連ドキュメント

- 不変条件: `docs/design/invariants.md` の I8（同種の実装の3回目のコピーは共通化する）
- 類似タスク: `docs/tasks/archive/infrastructure/11.3-file-size-budget-ci.md`（同 Phase の fitness function）

## 調査したファイル

- `.github/workflows/ci.yml`: fitness-functions ジョブは常時実行・ブロッキング。informational ジョブは `continue-on-error: true` をジョブレベルで付与し、名前に `(informational)` を付ける既存パターン（npm-audit L355-371、performance-test L376-473）
- `scripts/check-file-size.py`: 11.3 のラチェットスクリプト。標準ライブラリのみ、evaluate() 純粋関数、errors/hints 分類、exit 0/1
- `scripts/file-size-baseline.json`: JSON ベースライン形式（パス→行数のマップ、sort_keys=True）
- `scripts/tests/test_check_file_size.py`: importlib ロード、純粋関数テスト中心、pytest のみ依存
- `.claude/rules/lint.md`: ファイルサイズ予算ゲートの対処方針が記載。jscpd は新規セクション追加の対象

## 検討した代替案

| 案 | 概要 | 利点 | 欠点 |
|----|------|------|------|
| A（採用） | jscpd を CI で直接実行 + `.jscpd.json` で設定 | 最小コード（設定ファイル + CI ジョブのみ）。jscpd の CLI・レポーター機能をそのまま活用。カスタムロジック不要でテスト不要 | Node.js 依存が CI に追加（npx でダウンロード）。出力形式のカスタマイズは制限 |
| B | Python ラッパースクリプト（check-file-size.py パターン踏襲） | 11.3 と一貫したパターン。出力形式・ベースライン管理を完全制御 | 過剰な複雑さ（Python から Node ツールを subprocess 呼び出し）。informational フェーズでは不要な作り込み。保守対象が増加 |

採用理由: jscpd は成熟した CLI ツールで、閾値判定・レポート出力・exit code 制御を組み込みで備える。informational フェーズでは生出力で十分であり、カスタムラッパーは YAGNI。将来 blocking に昇格する際にラッパーを検討すればよい

ADR 要否: 不要。既存の informational ジョブパターン（npm-audit）に従うだけで、新たな方式選定はない

## 参考にする既存実装

- コピー元: `.github/workflows/ci.yml` の npm-audit ジョブ（L355-371）。informational ジョブの構成パターン（`continue-on-error: true`、ジョブ名サフィックス、理由コメント）を踏襲。同種の informational ジョブとしては 2 個目（npm-audit に次ぐ）なので I8 には該当しない

## 異常系・不変条件

- 該当する異常系: jscpd のインストール失敗（npx ダウンロードエラー）→ `continue-on-error: true` により CI 全体は PASS。完了条件 4 で検証
- 関係する不変条件: I8（本タスクはその可視化手段）、I7（jscpd バージョンを固定して再現性を担保 — npx jscpd@{version} で指定）

### 実装手順

1. **現状の重複率を計測する**: `npx jscpd --reporters console .` をローカルで実行し、現在のコードベースの重複率を把握する。結果に基づき `.jscpd.json` の閾値を設定する（現状値の直上または妥当な初期値）
   - 検証: `npx jscpd` が正常終了し、重複レポートが stdout に出力される

2. **`.jscpd.json` を作成する**: 計測結果に基づき、以下を設定する
   - `threshold`: 重複率の閾値（%）。計測結果に基づいて決定
   - `reporters`: `["console"]`
   - `ignore`: `["**/node_modules/**", "**/dist/**", "**/.venv/**", "**/build/**", "**/__pycache__/**", "**/coverage/**", "**/*.lock"]`
   - `format`: `["typescript", "python"]`（プロジェクトの主要言語）
   - `minLines` / `minTokens`: 意味のあるクローンのみを検出する最小サイズ
   - 検証: `npx jscpd` が `.jscpd.json` を読み込んで動作する

3. **CI ジョブを追加する**: `.github/workflows/ci.yml` に `jscpd (informational)` ジョブを追加する
   - npm-audit ジョブの直後に配置
   - `continue-on-error: true` をジョブレベルで設定
   - `actions/setup-node` で Node.js をセットアップ
   - `npx jscpd@{version}` でバージョン固定実行（I7）
   - コメントブロックで「なぜブロックしないか」を明記
   - 検証: `act` またはプッシュ後の CI で jscpd ジョブが実行される

4. **ドキュメントを更新する**: `.claude/rules/lint.md` に jscpd の方針セクションを追加する（jscpd が赤くなったときの対処、informational である理由）
   - 検証: `.claude/rules/lint.md` を Read し、jscpd セクションに (a) 赤時の対処方針、(b) informational である理由が記載されていることを確認

### 技術的な考慮事項

- jscpd のバージョンは `npx jscpd@X.Y.Z` の形で CI 上で固定する（I7: ビルドの入力はバージョン固定）
- `continue-on-error: true` はジョブレベルで設定する（ステップレベルではなく。npm-audit パターンに従う）
- jscpd は `actions/setup-node` が必要（fitness-functions の Python-only 環境とは異なる）
- npx は初回ダウンロードが必要だが、informational ジョブのため CI 速度への影響は許容

## リスクと検知方法

- jscpd バージョンの非互換な更新で設定が壊れる: バージョン固定（npx jscpd@X.Y.Z）で防止。更新は意図的な PR で行う
- 閾値が低すぎて常に赤: informational なので CI はブロックしない。閾値は初期計測で妥当な値を設定し、運用後に調整
- npx ダウンロードの一時的なネットワーク障害: `continue-on-error: true` で CI は PASS

# タスク詳細: 6.2 スクリプト間の重複排除・統合

## 概要

`clean-rebuild.sh` が `rebuild-mcp.sh` のロジックをインラインで複製しており、片方を修正しても他方に反映されない問題を解消する。`clean-rebuild.sh` の MCP ビルド処理を `rebuild-mcp.sh` の呼び出しに置換する。

### 現状の問題

`clean-rebuild.sh` の Step 3（L207-247）に MCP ビルドのインライン実装がある:

```bash
# clean-rebuild.sh のインライン実装
for server in "${MCP_SERVERS[@]}"; do
  rm -rf "$server/dist"
  rm -rf "$server/node_modules"
  (cd "$server" && npm install)
  (cd "$server" && npm run build)
done
```

これは `rebuild-mcp.sh` と同じ処理を重複して実装しており、以下の問題がある:
1. `rebuild-mcp.sh` にバグ修正やオプション追加をしても `clean-rebuild.sh` に反映されない
2. エラーハンドリングの実装が微妙に異なる

### `rebuild-mcp.sh` との差分

| 処理 | `clean-rebuild.sh` (現状) | `rebuild-mcp.sh --clean --install` |
|------|--------------------------|-----------------------------------|
| `rm -rf dist/` | あり | あり (`--clean`) |
| `rm -rf node_modules/` | **あり** | **なし** |
| `npm install` | あり | あり (`--install`) |
| `npm run build` | あり | あり |

`rebuild-mcp.sh --clean` は `dist/` のみ削除し `node_modules/` は削除しない。`clean-rebuild.sh` は完全クリーンビルドのため `node_modules/` も削除する。

## 実装計画

### 修正するファイル

| ファイル | 修正内容 |
|----------|----------|
| `scripts/rebuild-mcp.sh` | `--clean` オプションの動作を変更: `dist/` に加えて `node_modules/` も削除し、`npm install` を自動実行する |
| `scripts/clean-rebuild.sh` | Step 3 の MCP ビルドインライン実装（L207-247）を `scripts/rebuild-mcp.sh --clean` の呼び出しに置換 |

### 実装手順

#### Step 1: `rebuild-mcp.sh` の `--clean` を完全クリーンビルドに拡張

`--clean` 指定時に `node_modules/` も削除し、`npm install` を自動実行するように変更する。

**変更前:**
```bash
if $INSTALL; then
    echo "  npm install..."
    (cd "$server" && npm install) || ...
fi

if $CLEAN; then
    echo "  Cleaning dist/..."
    rm -rf "$server/dist"
fi
```

**変更後:**
```bash
if $CLEAN; then
    echo "  Cleaning dist/ and node_modules/..."
    rm -rf "$server/dist"
    rm -rf "$server/node_modules"
    INSTALL=true   # --clean 時は npm install を強制
fi

if $INSTALL; then
    echo "  npm install..."
    (cd "$server" && npm install) || ...
fi
```

これにより:
- `rebuild-mcp.sh` = ビルドのみ（インクリメンタル）
- `rebuild-mcp.sh --install` = npm install + ビルド
- `rebuild-mcp.sh --clean` = dist/ + node_modules/ 削除 + npm install + ビルド（完全クリーン）

#### Step 2: `clean-rebuild.sh` のインライン MCP ビルドを置換

**変更前（L207-247）:**
```bash
if ! $SKIP_MCP; then
  step "MCP サーバーのクリーンビルド"
  MCP_SERVERS=(jupyter-mcp document-mcp)
  MCP_FAILED=()
  for server in "${MCP_SERVERS[@]}"; do
    # ... 30行のインライン実装 ...
  done
fi
```

**変更後:**
```bash
if ! $SKIP_MCP; then
  step "MCP サーバーのクリーンビルド"
  scripts/rebuild-mcp.sh --clean
fi
```

#### Step 3: 動作確認

```bash
# rebuild-mcp.sh --clean が正しく動作することを確認
scripts/rebuild-mcp.sh --clean

# clean-rebuild.sh 全体が正常に完了することを確認
scripts/clean-rebuild.sh --env sample -y
```

### 技術的な考慮事項

- **`set -euo pipefail` の伝播**: `clean-rebuild.sh` は `set -euo pipefail` で動作する。`rebuild-mcp.sh` も同じ設定のため、失敗時は即座に `clean-rebuild.sh` も異常終了する。これは期待通りの動作
- **出力フォーマット**: `rebuild-mcp.sh` は独自のヘッダー（`=== MCP Server Rebuild ===`）を出力する。`clean-rebuild.sh` の step 番号表示と混在するが、情報として有用なため許容する
- **`--clean` の意味の変更**: `--clean` が `node_modules/` も削除するようになる。これは破壊的変更だが、「クリーン」の意味としてはより直感的。通常のビルドはフラグなしで行うため影響は限定的
- **`--install` フラグとの関係**: `--clean` は内部で `INSTALL=true` を設定するため、`--clean --install` と `--clean` は同じ動作になる。`--install` 単独は引き続き「`npm install` + ビルド」（`node_modules/` 削除なし）として機能する

# タスク詳細: 6.3 カスタムコマンドへのリビルド強制組み込み

## 概要

テストを実行するカスタムコマンド（`start-task`, `start-fix`, `refactor`, `complete-task`）にリビルド手順が含まれておらず、ルール（`rebuild-before-test.md`）が存在するだけで強制力がない問題を解消する。各コマンドのテスト実行ステップに `--rebuild` フラグを明示的に組み込む。

タスク 6.4（`test.sh --rebuild` 改善）の完了後に実施する。

## 関連ドキュメント

- ルール: `.claude/rules/rebuild-before-test.md` — リビルド必須ルール
- コマンド: `.claude/commands/custom-start-task.md`
- コマンド: `.claude/commands/custom-complete-task.md`
- コマンド: `.claude/commands/custom-start-fix.md`
- コマンド: `.claude/commands/custom-refactor.md`

## 実装計画

### 修正するファイル

| ファイル | 修正内容 |
|----------|----------|
| `.claude/commands/custom-start-task.md` | 実装完了後のテスト手順に `--rebuild` フラグを追加 |
| `.claude/commands/custom-start-fix.md` | テスト実行を `scripts/test.sh --rebuild` に変更 |
| `.claude/commands/custom-refactor.md` | テスト実行を `scripts/test.sh --rebuild` に変更 |
| `.claude/commands/custom-complete-task.md` | 完了検証にリビルド付きテスト再実行ステップを追加 |

### 実装手順

1. 各コマンドのテスト実行箇所を特定
2. `scripts/test.sh` → `scripts/test.sh --rebuild` に変更
3. `/custom-complete-task` にはテスト実行ステップ自体を追加（現在は「実装中に実行済み」としてスキップしている）
4. `/custom-start-task` には実装手順内にリビルド付きテストの指示を明示

### 修正方針

**`/custom-start-task`**: 実装手順の中に以下を明示：
```
テスト実行時は必ず --rebuild フラグを付けること：
scripts/test.sh --rebuild {コンポーネント名}
```

**`/custom-start-fix`**: テスト実行コマンドを変更：
```
# Before
scripts/test.sh {コンポーネント名}
# After
scripts/test.sh --rebuild {コンポーネント名}
```

**`/custom-refactor`**: 同上。

**`/custom-complete-task`**: 完了検証にテスト再実行を追加：
```
# 完了前の最終検証（リビルド付き）
scripts/test.sh --rebuild {コンポーネント名}
```

### 技術的な考慮事項

- `--rebuild` は鮮度チェックを行い、FRESH ならリビルドをスキップするため、不要なリビルドは発生しない
- カスタムコマンドはプロンプトテンプレートであり、テストコードではないためユニットテストは不要

# タスク詳細: 2.3 環境切り替えスクリプト実装

## 概要

`scripts/switch-env.sh` を新規作成し、サンプル・本番データ環境の切り替えをワンコマンドで実行できるようにする。

スクリプトは以下を一括実行する：
1. `.env` の `DATA_ENV` を書き換え
2. `postgres_data` ボリュームのみ削除（`jupyter_work` は保持）
3. PostgreSQL を本番/サンプルデータで再構築
4. document-server を再起動
5. 各サービスのヘルスチェック待機

## 関連ドキュメント

- 要件定義: `docs/requirements/document-server.md` の「F1.2 リロード」「NF3 運用性」「環境変数」セクション
- 類似タスク: `docs/tasks/workspace/2.1-document-server-data-dir-separation.md`（DATA_ENV 解決ロジック）
- 類似タスク: `docs/tasks/workspace/2.2-postgres-data-separation.md`（02-load-data.sh の DATA_ENV 対応）
- PLAN.md 2.4:  docker-compose.yml への DATA_ENV 追加は本タスクの前提

## 前提条件

- 2.1 完了: document-server が `DATA_ENV` に基づくデータディレクトリ解決に対応済み
- 2.2 完了: `postgres/init/02-load-data.sh` が `DATA_ENV` で環境別 CSV をロード可能
- **2.4 の docker-compose.yml 変更を本タスクに含める**: `docker-compose.yml` に `DATA_ENV` 環境変数を追加しないとスクリプトが動作しないため、docker-compose.yml の修正は本タスクで実施する。2.4 は `.env.example` 更新のみに範囲を縮小する。

### 実装手順

#### ステップ 1: docker-compose.yml に DATA_ENV 環境変数を追加

postgres サービスと document-server サービスの `environment` セクションを変更：

```yaml
# postgres サービス
environment:
  - DATA_ENV=${DATA_ENV:-sample}     # ← 追加
  - POSTGRES_DB=${POSTGRES_DB:-analysis_db}
  - POSTGRES_USER=${POSTGRES_USER:-jupyter}
  - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}

# document-server サービス
environment:
  - DATA_ENV=${DATA_ENV:-sample}     # ← 追加
  # - DATA_DIR=/app/data             # ← 削除（DATA_ENV と競合するため）
  - PORT=3002
```

**重要**: document-server の `DATA_DIR=/app/data` を削除すること。2.1 の config.py では `DATA_DIR` が明示指定されると `DATA_ENV` が無視される仕様のため、`DATA_DIR` が残っていると環境切り替えが動作しない。`DATA_ENV=sample` の場合、config.py が `./data/sample`（= コンテナ内 `/app/data/sample`）に自動解決する。

#### ステップ 2: .env に DATA_ENV のデフォルト値を追加

```
DATA_ENV=sample
```

#### ステップ 3: scripts/switch-env.sh を作成

既存スクリプト（`rebuild.sh`, `rebuild-mcp.sh`）のスタイルに準拠する。

```bash
#!/bin/bash
set -euo pipefail

cd "$(dirname "$0")/.."

# --- 定数 ---
VALID_ENVS=("sample" "production")

# --- usage ---
usage() {
  cat <<EOF
Usage: $(basename "$0") <ENV>

環境を切り替えます（PostgreSQLボリューム削除→再構築→document-server再起動）。

ENV:
  sample       サンプルデータ環境（デフォルト）
  production   本番データ環境

Options:
  -h, --help   このヘルプを表示
  -y, --yes    確認プロンプトをスキップ

Examples:
  $(basename "$0") production
  $(basename "$0") sample
EOF
}

# --- 引数パース ---
SKIP_CONFIRM=false
ENV=""

while [[ $# -gt 0 ]]; do
  case "$1" in
    -h|--help) usage; exit 0 ;;
    -y|--yes)  SKIP_CONFIRM=true; shift ;;
    -*)        echo "Error: unknown option '$1'"; usage; exit 1 ;;
    *)
      if [[ -n "$ENV" ]]; then
        echo "Error: multiple environments specified"; usage; exit 1
      fi
      # バリデーション
      found=false
      for v in "${VALID_ENVS[@]}"; do
        if [[ "$1" == "$v" ]]; then found=true; break; fi
      done
      if ! $found; then
        echo "Error: invalid environment '$1' (available: ${VALID_ENVS[*]})"
        exit 1
      fi
      ENV="$1"; shift ;;
  esac
done

if [[ -z "$ENV" ]]; then
  echo "Error: environment is required"
  usage
  exit 1
fi

# --- .env の DATA_ENV を書き換え ---
echo "=== Updating .env ==="
if grep -q "^DATA_ENV=" .env 2>/dev/null; then
  sed -i '' "s/^DATA_ENV=.*/DATA_ENV=${ENV}/" .env
else
  echo "DATA_ENV=${ENV}" >> .env
fi
echo "  DATA_ENV=${ENV}"

# --- 確認プロンプト ---
if ! $SKIP_CONFIRM; then
  echo ""
  echo "以下の操作を実行します:"
  echo "  1. PostgreSQL データボリュームを削除"
  echo "  2. PostgreSQL を ${ENV} データで再構築"
  echo "  3. document-server を再起動"
  echo ""
  echo "※ jupyter_work ボリューム（ワークスペース）は保持されます"
  read -p "続行しますか? [y/N] " confirm
  if [[ "${confirm}" != "y" && "${confirm}" != "Y" ]]; then
    echo "中止しました。"
    exit 0
  fi
fi

# --- postgres, document-server を停止 ---
echo ""
echo "=== Stopping services ==="
docker compose stop postgres document-server

# --- postgres_data ボリュームを削除 ---
echo ""
echo "=== Removing postgres_data volume ==="
VOLUME_NAME=$(docker volume ls --filter "name=postgres_data" -q | head -1)
if [[ -n "$VOLUME_NAME" ]]; then
  docker volume rm "$VOLUME_NAME"
  echo "  Removed: $VOLUME_NAME"
else
  echo "  Volume not found (will be created on startup)"
fi

# --- postgres を起動（ボリューム再作成 + 初期化スクリプト実行）---
echo ""
echo "=== Starting PostgreSQL (${ENV}) ==="
docker compose up -d postgres

# --- postgres ヘルスチェック待機 ---
echo "  Waiting for PostgreSQL..."
for i in $(seq 1 30); do
  if docker compose exec -T postgres pg_isready -U "${POSTGRES_USER:-jupyter}" > /dev/null 2>&1; then
    echo "  PostgreSQL is ready."
    break
  fi
  if [[ $i -eq 30 ]]; then
    echo "  ERROR: PostgreSQL failed to start within 30 seconds"
    exit 1
  fi
  sleep 1
done

# --- document-server を起動 ---
echo ""
echo "=== Starting document-server (${ENV}) ==="
docker compose up -d document-server

# --- document-server ヘルスチェック待機 ---
echo "  Waiting for document-server..."
for i in $(seq 1 30); do
  if curl -sf http://localhost:3002/health > /dev/null 2>&1; then
    echo "  document-server is ready."
    break
  fi
  if [[ $i -eq 30 ]]; then
    echo "  ERROR: document-server failed to start within 30 seconds"
    exit 1
  fi
  sleep 1
done

# --- 完了メッセージ ---
echo ""
echo "=== Done ==="
echo "環境を '${ENV}' に切り替えました。"
```

### 技術的な考慮事項

#### 1. ボリューム名の特定

docker compose のプロジェクト名によりボリューム名にプレフィックスが付く（例: `ai-data-analysis-platform_postgres_data`）。`docker compose down -v` は全ボリュームを削除してしまうので使わない。

`docker volume ls --filter name=postgres_data -q` でフィルタして正確なボリューム名を取得する。この方法はプロジェクト名に依存せず堅牢。

#### 2. .env の DATA_ENV 書き換え

`DATA_ENV` 行が存在する場合は置換、存在しない場合は追記する：

```bash
if grep -q "^DATA_ENV=" .env 2>/dev/null; then
  sed -i '' "s/^DATA_ENV=.*/DATA_ENV=${ENV}/" .env
else
  echo "DATA_ENV=${ENV}" >> .env
fi
```

macOS の `sed -i` は `sed -i ''` が必要な点に注意。本プロジェクトは macOS 環境（darwin）を前提とする。

#### 3. 確認プロンプトとスキップオプション

`-y` / `--yes` オプションで確認プロンプトをスキップできるようにする。CI 環境やスクリプトからの呼び出し時に便利。デフォルトは確認あり（`[y/N]` で N がデフォルト）。

#### 4. ヘルスチェック

- PostgreSQL: `docker compose exec -T postgres pg_isready` でポーリング（最大30秒）
- document-server: `curl -sf http://localhost:3002/health` でポーリング（最大30秒）
- タイムアウト時は `exit 1` でエラー終了（スクリプト本体に実装済み）

#### 5. 2.4 との範囲調整

本タスクで docker-compose.yml に `DATA_ENV` を追加するため、2.4 のスコープは `.env.example` 更新と確認テストのみに縮小される。

# タスク詳細: 4.4 Terminals API 無効化

## 概要

`jupyter_server_config.py` に `c.ServerApp.terminals_enabled = False` を追加し、Jupyter Server の Terminals API（`/api/terminals`）を完全に無効化する。これはシェルコマンド実行阻止の多層防御におけるレイヤー2（API レベル）の対策であり、ターミナル経由でのシェルアクセスを遮断する。

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyter-server.md` の「NF2.1: シェルコマンド実行の阻止」セクション（レイヤー2: Terminals API 無効化）
- 要件定義: `docs/requirements/jupyter-server.md` の「AC8: シェルコマンド実行阻止」（`Jupyter Terminals API（/api/terminals）へのリクエストが拒否される` の項目）

## 背景

Jupyter Server はデフォルトで Terminals API を提供し、`POST /api/terminals` でサーバー上にターミナルセッションを作成できる。ターミナルからは任意のシェルコマンドを実行可能であるため、AI の誤用やプロンプトインジェクションによるシェルアクセスのリスクがある。`c.ServerApp.terminals_enabled = False` を設定することで、Terminals API のエンドポイント自体が登録されなくなり、リクエストが 404 で拒否される。

### 実装手順

#### Step 1: `jupyter_server_config.py` に設定を追加

`jupyter-server/jupyter_config/jupyter_server_config.py` のネットワーク設定セクションの後（ワークスペース設定セクションの前）に、セキュリティ設定セクションを追加する。

```python
# =============================================================================
# セキュリティ設定
# =============================================================================
# Terminals API を無効化（NF2.1 レイヤー2: ターミナル経由のシェルアクセスを遮断）
c.ServerApp.terminals_enabled = False
```

**設定キーの根拠:** `c.ServerApp.terminals_enabled` は Jupyter Server の公式設定であり、`False` に設定すると以下の動作となる:
- Terminals API のハンドラが登録されない
- `GET /api/terminals`、`POST /api/terminals` 等のエンドポイントが 404 を返す
- JupyterLab UI からもターミナルメニューが非表示になる

#### Step 2: テスト作成（`test_terminals_disabled.py`）

設定ファイルの内容を検証するテストを作成する。

**テスト戦略:**

設定ファイルレベルでの検証（設定値が正しく記述されているか）を行う。統合テスト（実際に HTTP リクエストを送信して 404 が返ることの検証）は将来タスク 31.x で Docker 環境を使って実施する。

テスト内容:
1. `jupyter_server_config.py` の内容に `terminals_enabled = False` が含まれることを文字列検査で確認
2. 設定ファイルを `exec()` で実行し、`terminals_enabled` が `False` に設定されていることをプログラム的に確認

### 技術的な考慮事項

- **設定キー**: `c.ServerApp.terminals_enabled` は Jupyter Server 2.x 系の公式設定。`jupyter_server.serverapp.ServerApp` の traitlet として定義されている。
- **JupyterLab UI への影響**: `terminals_enabled = False` により、JupyterLab の Launcher からターミナルアイコンが非表示になり、File メニューの「New Terminal」も消える。本プラットフォームではターミナル機能は不要であるため、UI への影響は問題ない。
- **他のレイヤーとの関係**: レイヤー2 は API レベルでの遮断であり、レイヤー1（AST 検査）、レイヤー3（sandbox）、レイヤー4（IPython マジック無効化）とは独立して機能する。ターミナル API は `POST /api/kernels/{id}/execute` とは別のエンドポイントであるため、コード実行 API には影響しない。
- **変更の小ささ**: 設定ファイルに1行追加するのみ。既存機能への影響リスクは極めて低い。

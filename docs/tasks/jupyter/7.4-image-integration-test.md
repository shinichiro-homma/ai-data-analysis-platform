# タスク詳細: 7.4 画像リソース結合テスト

## 概要

Phase 7（画像リソース）の結合テストを全面書き換えする。Issue #20 により MCP リソース（resources/list, resources/read）が廃止され、`get_image` ツール（MCP image content type 返却）に一本化されたため、旧テスト計画は無効。

新しいテストでは「グラフ描画 → 画像ファイル保存 → execute_code で file_path 取得 → get_image で MCP image content type 取得」の一連フローを検証する。

### テストケース詳細

#### テスト1: グラフ描画 → get_image の完全フロー

```
1. workspace_create でワークスペース作成
2. session_create でセッション作成
3. execute_code で matplotlib グラフを描画
4. レスポンスの images 配列を検証:
   - images.length >= 1
   - images[0].file_path が workspaces/{ws_id}/output/exec-{N}-img-{NNN}.{ext} 形式
   - images[0].mime_type === "image/png"
   - images[0].description が存在する
5. get_image に images[0].file_path を渡す
6. get_image のレスポンスを検証:
   - content[0].type === "image"
   - content[0].mimeType === "image/png"
   - content[0].data が有効な base64 文字列（PNG ヘッダ iVBORw0KGgo で始まる）
   - isError が undefined（エラーなし）
7. クリーンアップ
```

#### テスト2: execute_code のレスポンスに base64 データが含まれないことの検証

```
1. ワークスペース・セッション作成
2. execute_code で matplotlib グラフを描画
3. レスポンス全体を文字列化し、base64 画像データ（長大な文字列）が含まれないことを検証:
   - images[].file_path のみ存在
   - images に data / content / base64 キーが存在しない
4. クリーンアップ
```

#### テスト3: 複数画像の描画 → 各画像を get_image で取得

```
1. ワークスペース・セッション作成
2. execute_code で複数の matplotlib グラフを描画（plt.figure() を複数回）
3. images 配列に 2 枚以上の画像が含まれることを検証
4. 各 file_path に対して get_image を呼び出し、すべて MCP image content type で取得できることを検証
5. クリーンアップ
```

#### テスト4: get_image に存在しないパスを指定 → エラー

```
1. get_image に存在しないパス（workspaces/ws-nonexistent/output/fake.png）を渡す
2. レスポンスを検証:
   - isError === true
   - content[0].type === "text"
   - content[0].text を JSON パースし success === false を確認
3. （ワークスペース不要）
```

#### テスト5: get_image に不正なパス（workspaces/ 外）を指定 → バリデーションエラー

```
1. get_image に "../../etc/passwd" などの不正パスを渡す
2. レスポンスを検証:
   - isError === true
   - バリデーションエラーが返ること
```

### 技術的な考慮事項

- **テスト方式**: `handleToolCall()` 直接呼び出し（InMemoryTransport / MCP プロトコル経由は不要）。既存の結合テストと同じパターンを踏襲。
- **タイムアウト**: matplotlib 初回インポートが遅いため、グラフ描画を含むテストは 30000ms のタイムアウトを設定。
- **テスト間の独立性**: 各テストでワークスペース・セッションを作成・削除し、状態リークを防ぐ。afterEach でクリーンアップ。
- **get_image の戻り値型**: `McpToolResult` 型。成功時は `content[0].type === "image"`、エラー時は `content[0].type === "text"` + `isError: true`。`parseToolCallResult()` は text 型の JSON パース用なので、image 型の結果には使わず直接 content[0] を検証する。

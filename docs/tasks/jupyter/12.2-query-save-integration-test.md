# タスク詳細: 12.2 クエリ保存の結合テスト

## 概要

execute_sql で実装されたクエリ保存機能（タスク 12.1）の結合テストを作成する。execute_sql を複数回実行し、`file_list` で `data/queries/` 配下に連番の `.sql` ファイルが確認でき、各ファイルにメタデータとクエリ本文が含まれることを検証する。

### 実装手順

1. **テストファイル作成** — `tests/integration/query-save.test.ts` を新規作成
2. **テスト構造の実装** — 既存パターン（`external-data-e2e.test.ts`）に従い以下を実装:
   - `beforeAll`: `checkJupyterConnection()` でサーバー接続確認
   - `afterEach`: `cleanupSession` / `cleanupWorkspace` でクリーンアップ
   - `createTestEnvironment`: `withNotebook: true` でワークスペース+セッション作成
3. **テストケース実装** — 以下の 5 テストケースを実装

### テストケース

| # | テストケース | 検証内容 |
|---|------------|----------|
| 1 | execute_sql 成功時にレスポンスに query_file_path が含まれる | `query_file_path` が `data/queries/001_*.sql` 形式で返る |
| 2 | file_list で data/queries/ 配下にクエリファイルが確認できる | `file_list(path: 'data/queries')` で `.sql` ファイルが存在する |
| 3 | クエリファイルにメタデータとSQL本文が含まれる | `execute_code` で `.sql` ファイルを読み込み、`-- executed_at:`、`-- result_file:`、`-- row_count:`、`-- execution_time_ms:` のメタデータ行と元のSQL文が含まれることを検証 |
| 4 | 複数回実行で連番がインクリメントされる | 2回 execute_sql を実行し、`001_*.sql` と `002_*.sql` が生成される |
| 5 | エラー時にはクエリファイルが保存されない | 不正SQL実行後、`file_list` で `data/queries/` が空またはファイルが増えていないことを確認 |

### 技術的な考慮事項

- **テスト方式**: `handleToolCall` を直接呼び出す方式（既存結合テストと同じパターン）
- **クエリファイルの内容検証**: `execute_code` で Python の `open()` を使って `.sql` ファイルを読み込み、内容を検証する。Jupyter Contents API ではファイル内容を取得できないため
- **DB 依存**: PostgreSQL に接続して SELECT を実行するため、`docker-compose up -d` が前提。テーブルは sample データの既存テーブルを使用
- **クリーンアップ**: テストごとにワークスペースを新規作成するため、テスト間の干渉なし

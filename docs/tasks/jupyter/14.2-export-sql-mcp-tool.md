# タスク詳細: 14.2 jupyter-mcp export_sql ツール実装

## 概要

jupyter-mcp に `export_sql` MCPツールを実装する。jupyter-server の `POST /api/sql/export` API（タスク 14.1 で実装）をラップし、SQLクエリ結果をワークスペースの `data/` ディレクトリに Parquet/CSV ファイルとしてエクスポートする。既存の `execute_sql` ツール実装パターン（`execute-sql.ts`）を踏襲し、セッションIDからワークスペースを特定してAPIを呼び出す。

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyter-mcp.md` の「F11: SQLデータエクスポート」「AC12: SQLデータエクスポート」セクション
- API仕様: `docs/design/api-contracts.md` の「POST /api/sql/export」セクション
- サーバー側タスク: `docs/tasks/jupyter/14.1-sql-export-api.md`

### 実装手順

#### 1. 型定義の追加（`types.ts`）

`SqlExecuteRequest` / `SqlExecuteResponse` の直後に以下を追加:

```typescript
export interface SqlExportRequest {
  sql: string;
  workspace_id: string;
  file_path: string;
  format?: 'parquet' | 'csv';
  timeout?: number;
}

export interface SqlExportResponse {
  success: boolean;
  file_path: string;
  row_count: number;
  file_size_bytes: number;
  format: 'parquet' | 'csv';
  execution_time_ms: number;
}
```

#### 2. クライアントメソッドの追加（`client.ts`）

既存の `executeSql()` メソッドをパターンとして、SQL実行セクションに `exportSql()` を追加:

```typescript
async exportSql(params: SqlExportRequest): Promise<SqlExportResponse> {
  const requestTimeoutMs = this.calculateRequestTimeout(params.timeout);
  const response = await this.request<ApiResponse<SqlExportResponse>>(
    'POST',
    '/api/sql/export',
    params,
    undefined,
    requestTimeoutMs,
  );
  return response.data;
}
```

**ポイント:**
- `executeSql()` と同じパターン（`calculateRequestTimeout` でHTTPタイムアウト設定）
- エラーハンドリングは既存の `handleError()` で自動処理される

#### 3. ツール実装（`export-sql.ts` 新規作成）

既存の `execute-sql.ts` をベースに作成。主な違い:

- パラメータ: `filename` → `file_path`、`max_rows` なし、`format` 追加
- タイムアウト上限: 300 → 600
- クエリ保存（`saveQueryFile`）は行わない（export はデータセット作成用のため）
- `jupyterClient.exportSql()` を呼び出す

```typescript
interface ExportSqlArgs {
  session_id: string;
  sql: string;
  file_path: string;
  format?: 'parquet' | 'csv';
  timeout?: number;
}
```

**バリデーション:**
- `session_id`: 必須、文字列（既存パターン）
- `sql`: 必須、文字列、最大100万文字（既存パターン）
- `file_path`: 必須、パストラバーサル防止（`validateFilename` を流用）
- `format`: オプション、`"parquet"` または `"csv"` のみ許可
- `timeout`: オプション、最大600秒（`validateNumberParameter` で `max: 600`）

**処理フロー:**
1. 入力バリデーション
2. `resolveSession()` でセッション情報取得
3. `extractWorkspaceIdFromPath()` でワークスペースID抽出
4. `jupyterClient.exportSql()` でAPIを呼び出し
5. レスポンスから `success` を除外し `createSuccessResponse()` で返却

#### 4. ツール定義・ルーティング登録（`index.ts`）

**ツール定義:**
要件定義 `docs/requirements/jupyter-mcp.md` の `export_sql` ツール定義をそのまま使用。description は以下:

```
SQLクエリの結果をデータセットとしてワークスペースにファイル保存します。...（要件定義の通り）
```

**ルーティング:**
- `import { executeExportSql } from './export-sql.js';`
- `case 'export_sql': return executeExportSql(args);`

#### 5. 単体テスト（`export-sql.test.ts`）

既存の `execute-sql.test.ts` のパターンを踏襲。モック対象:
- `jupyterClient.exportSql`
- `resolveSession`
- `workspace-path-store`（`extractWorkspaceIdFromPath`, `resolveWorkspacePath`）

**テストケース:**

正常系:
- Parquet エクスポート成功（format 未指定 → デフォルト parquet）
- CSV エクスポート成功（format: "csv" 指定）
- timeout オプション指定が正しく渡される
- レスポンスに file_path, row_count, file_size_bytes, format, execution_time_ms が含まれる

バリデーションエラー:
- `session_id` 未指定 → VALIDATION_ERROR
- `sql` 未指定 → VALIDATION_ERROR
- `file_path` 未指定 → VALIDATION_ERROR
- `session_id` 空文字 → VALIDATION_ERROR
- `format` に不正値（"xlsx" 等）→ VALIDATION_ERROR
- `timeout` が 600 超 → VALIDATION_ERROR

APIエラー:
- `SQL_NOT_ALLOWED`（非SELECT文）→ エラー返却
- `SQL_EXECUTION_ERROR` → エラー返却
- `DATABASE_CONNECTION_ERROR` → エラー返却 + isError flag
- `SQL_TIMEOUT` → エラー返却
- `FILE_WRITE_ERROR` → エラー返却
- `WORKSPACE_NOT_FOUND`（ワークスペースID抽出失敗）→ エラー返却
- セッション解決失敗 → エラー返却

### 技術的な考慮事項

- **`execute_sql` との差異を明確に:** `export_sql` はデータセット作成用。`max_rows` なし、クエリ保存なし、デフォルト形式は Parquet。
- **`file_path` パラメータ名:** API仕様では `file_path`（`execute_sql` の `filename` とは異なる）。ただし実際にはファイル名のみを受け付け、`data/` ディレクトリ内に保存される。`validateFilename` でパストラバーサルを防止する。
- **タイムアウト上限 600 秒:** `execute_sql` の 300 秒より長い。大規模データのエクスポートに対応するため。
- **`format` バリデーション:** MCP ツールの `enum` 定義に加え、ツール実装側でも `"parquet"` / `"csv"` のみ許可する防御的バリデーションを行う。

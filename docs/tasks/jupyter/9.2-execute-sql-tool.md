# タスク詳細: 9.2 execute_sql ツール — 非SELECT SQL命令句対応

## 概要

既存の execute_sql MCPツール（SELECT のみ対応）を拡張し、DELETE 以外の全 SQL 命令句を許可する。jupyter-server 側の `POST /api/sql/execute` API 拡張（タスク 9.1）に追従する。

**方針: MCP 側では SELECT/非SELECT を区別しない。** サーバーが返すレスポンスをそのまま返却する。DELETE のみサーバー側で拒否される。

## 実装計画

### 変更するファイル

| ファイル | 変更内容 |
|----------|----------|
| `jupyter-mcp/src/jupyter-client/types.ts` | `SqlExecuteResponse` に `affected_rows` 追加、SELECT 固有フィールドをオプショナル化 |
| `jupyter-mcp/src/tools/execute-sql.ts` | レスポンスをそのまま返すように変更、クエリ保存メタデータの微調整 |
| `jupyter-mcp/src/tools/index.ts` | `sql` パラメータの description から「SELECT文のみ」を削除 |

### 実装手順

#### ステップ1: 型定義の更新（types.ts）

`SqlExecuteResponse` の SELECT 固有フィールドをオプショナルに、`affected_rows` を追加する。

```typescript
export interface SqlExecuteResponse {
  success: boolean;
  execution_time_ms: number;
  // SELECT 時のみ
  file_path?: string;
  row_count?: number;
  columns?: string[];
  file_size_bytes?: number;
  truncated?: boolean;
  // 非SELECT 時のみ
  affected_rows?: number;
}
```

#### ステップ2: ツール実装の更新（execute-sql.ts）

サーバーのレスポンスをそのまま返す。分岐は最小限。

**変更点:**
- `result` のフィールドをスプレッドで返却（`file_path` があればそれも含まれるし、`affected_rows` があればそれも含まれる）
- `saveQueryFile` のメタデータ: `row_count` がなければ `affected_rows` を使う

```typescript
// API呼び出し後
const { success, ...resultData } = result;

// クエリ保存
const queryFilePath = await saveQueryFile({
  workspacePath,
  sql: validatedSql,
  filename: validatedFilename,
  rowCount: result.row_count ?? result.affected_rows ?? 0,
  executionTimeMs: result.execution_time_ms,
});

return createSuccessResponse({
  ...resultData,
  query_file_path: queryFilePath,
});
```

#### ステップ3: ツール定義の更新（tools/index.ts）

`sql` パラメータの description のみ変更（「SELECT文のみ」→「DELETEは禁止」）。ツールレベルの description は変更しない。

```typescript
sql: {
  type: "string",
  description: "実行するSQL文（DELETEは禁止）",
},
```

#### ステップ4: テストの更新（execute-sql.test.ts）

| 変更 | 内容 |
|------|------|
| **追加** | 非SELECT（INSERT INTO）実行成功 → `affected_rows` 返却、`file_path` なし |
| **修正** | SQL_NOT_ALLOWED テスト: 「SELECT 以外のクエリ」→「DELETE クエリ」 |

#### ステップ5: テスト実行

```bash
scripts/test.sh jupyter-mcp
```

### 技術的な考慮事項

1. **SELECT/非SELECT を MCP 側で区別しない**: SQL の種別判定はサーバー側の責務。MCP はレスポンスをパススルーするだけ。
2. **`filename` は引き続き required**: 非SELECT 時もクエリファイル命名（`{連番}_{filename}.sql`）に使用される。
3. **`client.ts` の変更不要**: レスポンスをそのまま返すだけなので型定義の変更で対応可能。

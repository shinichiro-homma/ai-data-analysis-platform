# タスク詳細: 17.3 ファイル読み取り

## 概要

ワークスペース内のテキストファイル（.sql, .py, .md 等）の内容を取得できる `file_read` MCPツールを新規実装する。jupyter-server 側の既存 `GET /api/custom/contents/{path}` がテキストファイルの内容を返却できるため、新規 REST API の追加は不要。jupyter-mcp 側で新規MCPツール `file_read` を作成し、既存の Contents API を呼び出す。ノートブック（.ipynb）は対象外とし、バリデーションで拒否する。

### 実装手順

1. **jupyter-mcp: 型定義の追加**
   - `types.ts` に `TextFileResponse` 型を追加
     - `path: string`
     - `type: 'file'`
     - `content: string`（テキストファイルの内容）
     - `modified_at: string`

2. **jupyter-mcp: クライアントメソッドの追加**
   - `client.ts` に `getTextFileContent(path: string): Promise<TextFileResponse>` メソッドを追加
   - 既存の `GET /api/custom/contents/{path}` を呼び出す（`getContents` と同じエンドポイントだが戻り型が異なる）
   - レスポンスの `type` が `'notebook'` の場合はエラーとする

3. **jupyter-mcp: file_read ツール実装**
   - `workspace_id`（必須）と `file_path`（必須、ワークスペース内の相対パス）のバリデーション
   - パストラバーサル対策（`normalizePath` を使用）
   - ワークスペースパスの解決（`resolveWorkspacePath` を使用）
   - ファイル拡張子が `.ipynb` の場合はバリデーションエラーを返す（ノートブックは `notebook_list_cells` を使用するよう案内）
   - `jupyterClient.getTextFileContent()` を呼び出し
   - レスポンスにファイルパス・内容を含める

4. **jupyter-mcp: ツール登録**
   - `index.ts` に `file_read` のインポートとツール定義を追加
   - ツール定義: `workspace_id`, `file_path` の2パラメータ

5. **テスト作成・実行**

### 技術的な考慮事項

#### 1. 既存 API の活用（jupyter-server 側の変更不要）

既存の `GET /api/custom/contents/{path}` は `ContentsHandler.get()` で、テキストファイルの場合は `type: "file"` で `content` をそのまま返却する。Jupyter Contents Manager がテキストファイルの内容を文字列として返すため、新規エンドポイントは不要。

#### 2. ノートブックの除外

要件定義の「ノートブック以外」の制約に従い、`.ipynb` ファイルは `file_read` の対象外とする。ノートブックの内容は `notebook_list_cells` で構造化された形式で取得する。ツール側でファイル拡張子を検証し、`.ipynb` の場合はバリデーションエラーとする。

#### 3. バイナリファイルの扱い

Jupyter Contents API はバイナリファイルの場合 base64 エンコードした内容を返す。`file_read` はテキストファイルを対象とするため、`type: "file"` のレスポンスをそのまま返す。画像等のバイナリファイルは `get_image` ツールで取得する。サーバー側がテキストとして返却できるファイルはそのまま返し、特にフィルタリングは行わない。

#### 4. ファイルサイズの考慮

大きなテキストファイルの場合、全内容を返すとMCPのレスポンスが大きくなる。ただし、対象ファイル（.sql, .py, .md 等）は通常小さいため、本タスクではファイルサイズ制限は設けない。将来必要であれば追加する。

#### 5. 既存パターンの踏襲

- バリデーション: `validateWorkspaceId`, `validateStringParameter` を使用（`data-preview.ts` と同一パターン）
- パス検証: `normalizePath`, `resolveWorkspacePath` を使用
- レスポンス: `createSuccessResponse` / `createErrorResponse` を使用
- エラーコード抽出: `extractErrorCode` / `extractErrorMessage` を使用

#### 6. getContents vs getTextFileContent

既存の `getContents` は戻り型が `NotebookResponse`（`type: 'notebook'`）に固定されている。テキストファイルは `type: 'file'` で返るため、別メソッド `getTextFileContent` を追加して `TextFileResponse` 型を返す。同じ API エンドポイントを呼ぶが、型安全性を確保する。

# タスク詳細: 7.3 get_image ツール実装

## 概要

`execute_code` のレスポンスに含まれる画像ファイルパス（`file_path`）を指定して、画像データを MCP の image content type で取得するツールを実装する。

Issue #20 により、旧 MCP リソース方式（`resources/list`, `resources/read`）は廃止され、画像取得は `get_image` ツール経由に一本化される。`resources/read` が base64 テキストをコンテキストに載せてしまう問題を、MCP image content type（`{ type: "image", data, mimeType }`）で返すことにより解消する。

併せて、廃止対象となった MCP リソース関連コード（`image-registry.ts`, `images.ts`, `server.ts` のリソースハンドラ）を削除する。

### 実装手順

#### ステップ1: get_image ツール実装（`src/tools/get-image.ts`）

既存ツールパターン（`execute-sql.ts` 等）に従い、以下の構造で実装する。

```typescript
interface GetImageArgs {
  file_path: string;  // workspaces/{workspace_id}/output/exec-{N}-img-{NNN}.{ext}
}

export async function executeGetImage(
  args: Record<string, unknown>
): Promise<{ content: Array<{ type: string; data?: string; mimeType?: string; text?: string }> }> {
  // 1. file_path のバリデーション（validateStringParameter）
  // 2. jupyterClient.getFileContent(file_path) で Jupyter Contents API 経由でファイル取得
  // 3. MCP image content type で返却:
  //    { content: [{ type: "image", data: base64Data, mimeType: "image/png" }] }
  // 4. エラー時は createErrorResponse で { success: false, error: "..." } を返す
}
```

**重要**: 戻り値は既存の `McpResponse` 型（`content[].text` 固定）ではなく、MCP image content type（`content[].type: "image"`, `content[].data`, `content[].mimeType`）を直接返す。`createSuccessResponse` は使わず、独自にレスポンスを組み立てる。エラー時のみ `createErrorResponse` を使用する。

#### ステップ2: ツール定義とルーティング追加（`src/tools/index.ts`）

```typescript
// tools 配列に追加
{

  inputSchema: {
    type: "object",
    properties: {
      file_path: {

      },
    },
    required: ["file_path"],
  },
}

// handleToolCall の switch 文に追加
case "get_image":
  return executeGetImage(args);
```

### 技術的な考慮事項

#### McpResponse 型との不整合

現在の `McpResponse` 型（`src/utils/response-formatter.ts`）は `content: Array<{ type: string; text: string }>` と `text` 固定。MCP image content type は `{ type: "image", data: string, mimeType: string }` であり、`text` プロパティを持たない。

**方針**: `get_image` ツールは `McpResponse` 型を使わず、MCP SDK が受け付ける content 形式を直接返す。`handleToolCall` の戻り値型を `McpResponse` から MCP SDK の `CallToolResult` 型（またはその互換型）に広げる必要がある場合は、最小限の型修正で対応する。

#### 画像取得の流れ

```
get_image(file_path)
  → jupyterClient.getFileContent(file_path)
  → Jupyter Contents API: GET /api/contents/{path}?content=1
  → FileContent { content: base64, mimetype: string }
  → { content: [{ type: "image", data: base64, mimeType: mimetype }] }
```

#### image-registry の execute-code からの参照

`execute-code.ts` が `imageRegistry.register()` を呼んでいる場合、この呼び出しも削除する。`get_image` は `file_path` を直接 Jupyter Contents API に渡すため、レジストリは不要。

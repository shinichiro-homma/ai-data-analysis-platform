# タスク詳細: 8.3 AI編集モード（自動ロック制御）

## 概要

ノートブック編集系ツールの実行時に、`handleToolCall` ミドルウェアが自動的に `ai_edit_start`/`ai_edit_end` イベントを配信し、ノートブックのロック/アンロックを制御する機能を実装する。

既存の MCP ツール `ai_edit_start`/`ai_edit_end` を廃止し、ミドルウェアによる自動制御に置き換える。これにより、今後ノートブック操作ツールを追加した際も `NOTEBOOK_EDIT_TOOLS` Set に追加するだけで自動対応される。

### なぜこのタスクが必要か

8.1（セル追加同期）と8.2（セル実行同期）ではAI操作のリアルタイム反映を実装したが、AI操作中にユーザーが同時にノートブックを編集するとセルインデックスがずれるなどの不整合が発生する。ロック制御により、AI操作中はユーザー操作を安全に無効化し、操作完了後に編集権を返す。

### 旧実装（MCPツール方式）からの変更点

- `ai_edit_start`/`ai_edit_end` を独立した MCP ツールとして提供する方式を廃止
- `handleToolCall` のミドルウェア層で、ノートブック編集系ツール実行の前後に自動的にイベントを配信する方式に変更
- 対象ツールは `NOTEBOOK_EDIT_TOOLS` Set で管理（ハードコード不要）

### 実装手順

#### ステップ1: ミドルウェア層の実装（jupyter-mcp/src/tools/index.ts）

`handleToolCall` にミドルウェア層を追加し、`NOTEBOOK_EDIT_TOOLS` Set に含まれるツール実行時に自動で `ai_edit_start`/`ai_edit_end` イベントを配信する。

```typescript
const NOTEBOOK_EDIT_TOOLS = new Set([
  'execute_code', 'notebook_add_cell', 'notebook_edit_cell',
  'notebook_delete_cell', 'notebook_execute_cell', 'notebook_reorder_cell',
]);

export async function handleToolCall(name: string, args: Record<string, unknown>) {
  if (NOTEBOOK_EDIT_TOOLS.has(name)) {
    await emitAiEditStart(args);
    try {
      return await sharedHandleToolCall(toolRegistry, name, args);
    } finally {
      await emitAiEditEnd(args);
    }
  }
  return sharedHandleToolCall(toolRegistry, name, args);
}
```

#### ステップ2: 内部ヘルパーの追加（jupyter-mcp/src/utils/ai-edit-helpers.ts）

既存の `validateAndResolveNotebookPath` を活用し、`emitAiEditStart`/`emitAiEditEnd` を内部ヘルパーとして実装する。

#### ステップ3: ツール定義・インポートの削除（jupyter-mcp/src/tools/index.ts）

- `ai_edit_start`/`ai_edit_end` のインポートとツール定義を削除
- ツールファイル自体を削除

#### ステップ4: テストの更新

### 技術的な考慮事項

#### session_id / notebook_path の解決

ミドルウェアでは `args` から `session_id` または `notebook_path` を取得し、`ai_edit_start`/`ai_edit_end` イベント用の `notebook_path` を解決する必要がある。既存の `validateAndResolveNotebookPath` ヘルパーを活用する。

#### エラー時のロック解除

`try...finally` パターンにより、ツール実行がエラーで失敗した場合でも `ai_edit_end` が確実に配信される。

#### 既存の jupyterlab-ai-sync との互換性

イベントのペイロード形式は変更しないため、jupyterlab-ai-sync 側のコード変更は不要。

# タスク詳細: 10.2 jupyter-mcp ImageStore のファイルベース化

## 概要

jupyter-mcp の画像処理をインメモリ（base64）方式からファイルベース方式に移行する。

タスク 10.1 で jupyter-server が画像をワークスペースの `output/` にファイルとして保存し、API レスポンスで `file_path` を返すようになった。本タスクでは jupyter-mcp 側をこの変更に追従させる。

具体的には：
- `ImageStore`（インメモリ base64 保持）を廃止し、jupyter-server が返す `file_path` をそのまま AI に返却する
- `ImageReference` の `resource_uri` を `file_path` に置き換える
- `uri-utils.ts`（`jupyter://sessions/...` URI 生成）を廃止する
- `get_image_resource` ツール・MCP リソース（resources/list, resources/read）は現時点で未実装のため、コード削除は不要

**なぜ必要か:** タスク 10.1 で jupyter-server 側がファイルベースに移行済みだが、jupyter-mcp 側は旧来のインメモリ ImageStore を介しているため、API レスポンスの `file_path` を活用できていない。本タスクで整合させることにより、AI へのレスポンスから base64 データを完全に排除する。

### 実装手順

#### ステップ 1: 型定義の更新

**1a. `jupyter-client/types.ts` の `ImageOutput` 型を更新**

```typescript
// Before
export interface ImageOutput {
  id: string;
  mime_type: string;
  data: string;      // base64
  width?: number;
  height?: number;
}

// After
export interface ImageOutput {
  file_path: string;  // workspaces/{workspace_id}/output/exec-{N}-img-{NNN}.{ext}
  mime_type: string;
  description: string;
}
```

jupyter-server が 18.1 で返すレスポンス形式に合わせる。`id`, `data`, `width`, `height` は不要になる。

**1b. `image-store/types.ts` の更新**

```typescript
// Before
export interface ImageReference {
  resource_uri: string;
  mime_type: string;
  description: string;
}

export interface StoredImage {
  id: string;
  sessionId: string;
  mimeType: string;
  data: string;       // base64
  width?: number;
  height?: number;
  createdAt: Date;
  description: string;
}

// After
export interface ImageReference {
  file_path: string;   // workspaces/{workspace_id}/output/exec-{N}-img-{NNN}.{ext}
  mime_type: string;
  description: string;
}

// StoredImage は削除（インメモリ保持が不要になるため）
```

#### ステップ 2: ImageStore の廃止

**2a. `image-store/index.ts` を書き換え**

ImageStore クラス（シングルトン、Map による base64 保持）を廃止し、`ImageOutput` → `ImageReference` のマッピング関数に置き換える。

```typescript
import type { ImageReference } from './types.js';
import type { ImageOutput } from '../jupyter-client/types.js';

/**
 * jupyter-server が返す ImageOutput を MCP レスポンス用の ImageReference に変換する。
 * 画像ファイル自体は jupyter-server 側でワークスペースの output/ に保存済み。
 */
export function toImageReference(image: ImageOutput): ImageReference {
  return {
    file_path: image.file_path,
    mime_type: image.mime_type,
    description: image.description,
  };
}
```

**2b. `image-store/uri-utils.ts` を削除**

`buildResourceUri`, `extractImageIdFromUri`, `getExtensionFromMimeType` 等の関数は不要になる。

#### ステップ 3: execute-code ツールの更新

`src/tools/execute-code.ts` の画像処理部分を変更。

```typescript
// Before (行 199-208)
const imageReferences = result.images.map((img) => {
  return imageStore.store(kernelId, img);
});

// After
const imageReferences = result.images.map(toImageReference);
```

`imageStore` の import を `toImageReference` の import に変更する。

#### ステップ 4: テストの更新

**4a. `tests/unit/image-store/image-store.test.ts` → マッピング関数テストに書き換え**

- `toImageReference` が `ImageOutput` を正しく `ImageReference` に変換することをテスト
- フィールドの正確な転写を検証

**4b. `tests/unit/image-store/uri-utils.test.ts` → 削除**

**4c. `tests/unit/tools/execute-code.test.ts` の画像関連テストを更新**

- モック: `imageStore.store()` → `toImageReference()` に変更
- アサーション: `resource_uri` → `file_path` に変更

**4d. `tests/integration/execute-code-images.test.ts` の更新**

- `resource_uri` の正規表現マッチ（`/^jupyter:\/\/sessions\/.+/`）を `file_path` 形式（`/^workspaces\/.+\/output\/exec-\d+-img-\d+\.\w+$/`）に変更

### 技術的な考慮事項

- **ImageStore の廃止は安全**: 現在 `get_image_resource` ツールも MCP リソース（resources/list, resources/read）も未実装のため、ImageStore の `get()` / `listAll()` / `listBySession()` を呼び出すコードは存在しない。`store()` のみが `execute-code.ts` から呼ばれており、これをマッピング関数に置き換えるだけで完結する
- **`ImageOutput` 型の変更**: jupyter-server 18.1 の API レスポンスで `file_path` / `mime_type` / `description` が返るようになっている前提。`jupyter-client/types.ts` の型をこれに合わせる
- **AI 同期イベント**: AI 同期イベント（cell_output）には従来通り base64 が含まれ、JupyterLab のセル出力に画像が表示される。この部分は jupyter-server 側の責務であり、本タスクでは変更不要
- **image-store ディレクトリ**: `uri-utils.ts` を削除した後もディレクトリは残す（`index.ts` と `types.ts` が残るため）。ただし、将来的に `types.ts` を別の場所に移動し、`toImageReference` を `utils/` に移す簡略化も考えられるが、本タスクの範囲外とする

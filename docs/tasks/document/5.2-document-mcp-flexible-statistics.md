# タスク詳細: 5.2 document-mcp 柔軟な統計項目対応

## 概要

document-mcp の `get_table_detail` ツールで、document-server が返す `statistics.additional`（テーブル固有の拡張統計項目）を MCP 経由で取得できるようにする。

タスク 5.1 で document-server 側に `additional` フィールドを追加済み。document-mcp は document-server のレスポンスを透過的に返す設計のため、主な変更は TypeScript 型定義の拡張とテスト追加である。

## 関連ドキュメント

- 要件定義: `docs/requirements/document-mcp.md` の「F2: テーブル詳細取得（第2層）」セクション
  - F2.1: statistics に additional（テーブル固有の拡張統計項目）を含めること
  - AC2: additional が定義されている場合はレスポンスに含まれること、未定義の場合は固定フィールドのみで正常返却されること
- API仕様: `docs/design/api-contracts.md` の「POST /catalog/tables」セクション
  - statistics.additional はテーブルごとに任意のキー・値を持つ自由形式オブジェクト
- 類似タスク: `docs/tasks/document/5.1-document-server-flexible-statistics.md`（document-server 側の実装）

### 実装手順

#### ステップ 1: 型定義の拡張（`types.ts`）

`Statistics` インターフェース（行 67-71）に `additional` フィールドを追加する。

```typescript
export interface Statistics {
  row_count?: number;
  date_range?: DateRange;
  update_frequency?: string;
  additional?: Record<string, unknown>;  // 追加
}
```

- `additional` はオプショナル（`?`）とする。document-server は空 dict `{}` を常に返すが、型としては未定義ケースも許容する
- 値の型は `unknown`（数値、文字列、配列、ネストオブジェクト等を許容）

#### ステップ 2: ツール description の更新（`tools/index.ts`）

`get_table_detail` の description に、additional を含むことを追記する。AI がツールの戻り値に additional が存在することを認識できるようにする。

#### ステップ 3: テスト追加（`table-detail.test.ts`）

既存テストパターン（key_types テストケース等）に倣い、以下のテストケースを追加する。

### 技術的な考慮事項

- **透過的なデータフロー**: `executeTableDetail` は `result.tables` をそのまま `createSuccessResponse` に渡すだけなので、ツール実装コード自体の変更は不要。型定義を正しくすれば、document-server のレスポンスがそのまま MCP 応答に含まれる
- **後方互換性**: `additional` はオプショナルフィールドのため、既存の型利用箇所に影響なし。Phase 4 の `key_types` 追加と同じパターン
- **document-client/client.ts は変更不要**: REST API 呼び出し自体は変わらない。型推論で `Statistics` の `additional` フィールドが自動的に含まれる

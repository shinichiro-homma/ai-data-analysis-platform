# タスク詳細: 4.2 document-mcp key_types 対応

## 概要

document-mcp の型定義に `key_types`（条件付きキー種別）フィールドを追加し、`get_table_detail` ツールで条件付きキー情報が正しく返却されるようにする。

タスク 4.1 で document-server 側に `key_types` 対応を実装済み。本タスクでは MCP クライアント側（document-mcp）の型定義を更新し、サーバーから返却される `key_types` フィールドが正しく型付けされた状態で透過的に返却されることを確認する。

## 関連ドキュメント

- 要件定義: `docs/requirements/document-mcp.md` の「F2.1: テーブル詳細取得」セクション
  - カラム定義に key_type/key_types（結合キー種別）を含む
  - key_types は条件付きキー種別で、key_type と排他
- API仕様: `docs/design/api-contracts.md` の「POST /catalog/tables」セクション
  - key_types 配列の各要素: `{ value: string, condition: string | null }`（null はデフォルトキー種別）
- 受け入れ条件: AC2「条件付きkey_types（配列形式）を持つカラムが正しく返却される」

## 実装計画

### 変更するファイル

| ファイル | 内容 |
|----------|------|
| `document-mcp/src/document-client/types.ts` | `ConditionalKeyType` インターフェース追加、`ColumnInfo` に `key_types` フィールド追加 |
| `document-mcp/tests/unit/tools/table-detail.test.ts` | `key_types` を含むカラムの返却テスト追加 |

### 実装手順

1. **型定義の追加**（`src/document-client/types.ts`）
   - `ConditionalKeyType` インターフェースを新規定義（`value: string`, `condition: string | null`）。condition が null の場合はデフォルトのキー種別を表す
   - `ColumnInfo` インターフェースに `key_types?: ConditionalKeyType[]` フィールドを追加

2. **テストの追加**（`tests/unit/tools/table-detail.test.ts`）
   - `key_types` を持つカラムが正しく返却される正常系テストケースを追加
   - `key_type` のみのカラムと `key_types` のみのカラムが混在するレスポンスの検証

3. **型チェック・テスト実行**
   - `scripts/test.sh document-mcp` で全テスト通過を確認

### 技術的な考慮事項

- **ロジック変更は不要**: document-mcp は document-server の API レスポンスを JSON としてそのまま返却する透過型アーキテクチャ。`key_types` フィールドは型定義を追加するだけで自動的に返却される
- **後方互換性**: `key_types` はオプショナルフィールドのため、既存のカラム定義（`key_type` のみ）に影響なし
- **排他チェックは document-server 側で実施済み**: `key_type` と `key_types` の排他バリデーションは Pydantic モデル（タスク 4.1）で対応済みのため、document-mcp 側での重複チェックは不要

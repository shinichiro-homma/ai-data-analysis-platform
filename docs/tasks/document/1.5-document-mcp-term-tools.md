# タスク詳細: 1.5 document-mcp 用語集MCPツール実装

## 概要

document-mcp に用語集参照用の MCP ツール（`get_term_index`, `get_term_detail`）を追加する。タスク 1.4 で構築済みのテーブルツールと同じアーキテクチャ・パターンを踏襲し、document-server の用語集 API（`GET /glossary/index`, `POST /glossary/terms`）を MCP 経由で AI に提供する。

`get_term_detail` は `term_names` 配列による一括取得に対応し、テーブルツール（`get_table_detail`）と同一のパターンで実装する。

これにより AI がデータ分析時に業務用語の定義・別名・関連用語を参照でき、正確な SQL 生成や分析レポート作成が可能になる。

### 実装手順

#### Step 1: 型定義の追加（`document-client/types.ts`）

以下の型を追加する（テーブル型定義の直後に配置）:

```typescript
// --- 用語集（Glossary）---

export interface TermIndex {
  name: string;
  summary: string;
}

export interface TermIndexResponse {
  data: {
    terms: TermIndex[];
    total: number;
  };
}

export interface TermValue {
  label: string;
  description: string;
}

export interface TermDetail {
  name: string;
  aliases: string[];
  definition: string;
  related_terms?: string[];
  values?: TermValue[];
}

export interface TermDetailResponse {
  data: {
    terms: TermDetail[];
    not_found: string[];
  };
}
```

#### Step 2: API クライアントメソッドの追加（`document-client/client.ts`）

`DocumentServerClient` クラスに 2 メソッドを追加:

- `getTermIndex()`: `GET /glossary/index` → `{ terms, total }` を返却
- `getTermDetails(termNames: string[])`: `POST /glossary/terms` (body: `{ term_names: termNames }`) → `{ terms, not_found }` を返却

`getTableIndex` / `getTableDetails` と同一パターン。import に `TermIndexResponse`, `TermDetailResponse` を追加。

```typescript
async getTermIndex(): Promise<TermIndexResponse["data"]> {
  try {
    const response = await this.httpClient.get<TermIndexResponse>("/glossary/index");
    return response.data.data;
  } catch (error) {
    throw this.handleError(error);
  }
}

async getTermDetails(termNames: string[]): Promise<TermDetailResponse["data"]> {
  try {
    const response = await this.httpClient.post<TermDetailResponse>(
      "/glossary/terms",
      { term_names: termNames }
    );
    return response.data.data;
  } catch (error) {
    throw this.handleError(error);
  }
}
```

#### Step 3: ツール実装（`tools/term-index.ts`, `tools/term-detail.ts`）

- `term-index.ts`: `table-index.ts` と同パターン。引数なし。`getDocumentClient().getTermIndex()` を呼び出し、`createSuccessResponse({ terms, total })` で返却。

```typescript
export async function executeTermIndex(
  _args: Record<string, unknown>
): Promise<McpResponse> {
  try {
    const { terms, total } = await getDocumentClient().getTermIndex();
    return createSuccessResponse({ terms, total });
  } catch (error) {
    return createErrorResponseFromError(error);
  }
}
```

- `term-detail.ts`: `table-detail.ts` と同パターン。`validateStringArrayParameter(args.term_names, "term_names", { required: true, maxLength: 128, minItems: 1, maxItems: 50 })` でバリデーション後、`getDocumentClient().getTermDetails(validation.value)` を呼び出す。

```typescript
export async function executeTermDetail(
  args: Record<string, unknown>
): Promise<McpResponse> {
  const termNames = args.term_names;

  const validation = validateStringArrayParameter(termNames, "term_names", {
    required: true,
    maxLength: 128,
    minItems: 1,
    maxItems: 50,
  });
  if (!validation.isValid) {
    return createErrorResponse(validation.errorMessage, "VALIDATION_ERROR");
  }

  try {
    const result = await getDocumentClient().getTermDetails(validation.value);
    return createSuccessResponse({
      terms: result.terms,
      not_found: result.not_found,
    });
  } catch (error) {
    return createErrorResponseFromError(error);
  }
}
```

### 技術的な考慮事項

- **v2 API パターンの厳密な踏襲**: テーブルツール（1.4）で確立された一括取得パターン（POST + 配列引数 + `not_found` 配列レスポンス）をそのまま適用する。独自の拡張や最適化は行わない。
- **エラーコード**: document-server 側は `TERM_NOT_FOUND` を返却する。`createErrorResponseFromError` がそのまま code を伝播するため、特別な処理は不要。
- **`term_names` のバリデーション**: `table_names` と同じオプション（`required: true`, `maxLength: 128`, `minItems: 1`, `maxItems: 50`）を使用する。
- **Optional フィールド**: `related_terms` と `values` は document-server 側で optional。document-mcp ではサーバーのレスポンスをそのまま返却するため、特別な null チェックは不要。
- **一括取得の部分成功**: `term_names` で指定した一部が見つからない場合、見つかった用語は `terms` に、見つからなかった用語は `not_found` に返却される。これは document-server の仕様であり、document-mcp はそのまま透過する。

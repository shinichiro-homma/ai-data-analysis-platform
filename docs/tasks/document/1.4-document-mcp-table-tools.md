# タスク詳細: 1.4 document-mcp テーブルMCPツール実装（v2対応）

## 概要

既存の document-mcp テーブルMCPツール（v1実装済み）を v2 要件に合わせて修正する。

主な変更点:
- **APIパス変更**: `/api/v1/tables` → `/catalog/index`, `/catalog/tables`
- **一括取得対応**: `get_table_detail` を単一テーブル (`table_name: string`) から複数テーブル (`table_names: string[]`) に変更
- **レスポンス形式変更**: テーブル詳細レスポンスに `not_found` 配列を追加

**なぜこのタスクが必要か:**
- v2 要件でAPIパスが `/catalog/*` に変更されたため、クライアントのエンドポイントを更新する必要がある
- 一括取得対応により、AIが複数テーブルの詳細を1回のMCPツール呼び出しで取得でき、コンテキスト効率が向上する

### 実装手順

#### ステップ 1: 型定義の修正 (`src/document-client/types.ts`)

- `TableDetailResponse` を修正:
  - 旧: `{ data: TableDetail }`
  - 新: `{ data: { tables: TableDetail[]; not_found: string[] } }`
- `TableIndexResponse` はAPIパスが変わるのみで形式は同じ。変更不要

#### ステップ 2: APIクライアントの修正 (`src/document-client/client.ts`)

- `getTableIndex()` のエンドポイントを変更:
  - 旧: `GET /api/v1/tables`
  - 新: `GET /catalog/index`
- `getTableDetail(tableName: string)` を `getTableDetails(tableNames: string[])` に変更:
  - 旧: `GET /api/v1/tables/{tableName}`
  - 新: `POST /catalog/tables` (body: `{ table_names: tableNames }`)
  - 戻り値: `{ tables: TableDetail[], not_found: string[] }`

#### ステップ 3: バリデーション関数の追加 (`src/utils/validation.ts`)

- `validateStringArrayParameter(value, fieldName, options)` を追加:
  - `required`: 必須チェック（undefinedでないこと）
  - 配列であることの型チェック
  - 空配列チェック（`minLength: 1` など）
  - 各要素が文字列であることのチェック
  - 各要素の `maxLength` チェック
  - 既存の `validateStringParameter` はそのまま残す

#### ステップ 4: ツール定義の修正 (`src/tools/index.ts`)

- `get_table_detail` の inputSchema を修正:
  - 旧: `{ table_name: { type: "string" } }`, `required: ["table_name"]`
  - 新: `{ table_names: { type: "array", items: { type: "string" }, description: "テーブル名の配列（get_table_index で取得した table_name を指定）" } }`, `required: ["table_names"]`
- `get_table_detail` の description を修正:
  - 「複数テーブルを一度に取得できます」を含む v2 版に更新
- `get_table_index` の定義は変更不要

#### ステップ 5: ツール実装の修正 (`src/tools/table-detail.ts`)

- 引数を `table_name` → `table_names` に変更
- バリデーションを `validateStringParameter` → `validateStringArrayParameter` に変更
- API 呼び出しを `documentClient.getTableDetail(tableName)` → `documentClient.getTableDetails(tableNames)` に変更
- 成功レスポンスを `{ table: ... }` → `{ tables: [...], not_found: [...] }` に変更

#### ステップ 6: テストの修正

**`tests/unit/document-client/client.test.ts`:**
- `getTableIndex` のモック URL を `/catalog/index` に変更
- `getTableDetail` → `getTableDetails` に変更:
  - `POST /catalog/tables` への POST リクエストに変更
  - リクエストボディ `{ table_names: [...] }` の検証
  - レスポンスが `{ tables: [...], not_found: [...] }` 形式

**`tests/unit/tools/table-detail.test.ts`:**
- 正常系: 単一テーブル指定で取得できる
- 正常系: 複数テーブル指定で一括取得できる
- 正常系: 一部テーブルが見つからない場合、`tables` と `not_found` の両方が返る
- 異常系: `table_names` 未指定 → VALIDATION_ERROR
- 異常系: `table_names` が空配列 → VALIDATION_ERROR
- 異常系: `table_names` が文字列（配列でない） → VALIDATION_ERROR
- 異常系: API 接続エラー

### 技術的な考慮事項

- **既存コードの修正**: v1実装が既に存在するため、ゼロからの構築ではなく差分修正として進める。プロジェクト基盤（package.json, tsconfig.json, index.ts, server.ts, logger.ts, response-formatter.ts）は変更不要
- **get_table_detail のレスポンス形式**: document-server の `POST /catalog/tables` レスポンスの `not_found` 配列をそのまま MCP ツールの成功レスポンスに含める。全テーブルが見つからない場合でも `success: true` で返し（`tables: [], not_found: [...]`）、クライアント側で判断可能にする
- **後方互換性**: ツール名 `get_table_detail` は維持する（v1 と同名）。引数が `table_name` → `table_names` に変わるため、呼び出し側は修正が必要だが、MCP ツールの名前変更は不要
- **1.5 への拡張性**: `validateStringArrayParameter` は用語集ツール（`get_term_detail`）でも再利用できる。`document-client/client.ts` に `getTermIndex` / `getTermDetails` メソッドを追加するだけで拡張可能

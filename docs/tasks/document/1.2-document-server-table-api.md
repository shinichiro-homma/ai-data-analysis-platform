# タスク詳細: 1.2 document-server テーブルAPI実装（v2）

## 概要

document-server のテーブル API を v2 要件に合わせて再実装する。既存の v1 実装（`GET /api/v1/tables`, `GET /api/v1/tables/{name}`）を、v2 の新しい API パス（`GET /catalog/index`, `POST /catalog/tables`）に変更し、一括取得対応・インデックスファイル読み込み方式に移行する。

### v1 → v2 の主な変更点

| 項目 | v1（現状） | v2（今回の実装） |
|------|-----------|-----------------|
| テーブルインデックス | `GET /api/v1/tables`（YAML から自動生成） | `GET /catalog/index`（`index.yaml` から読み込み） |
| テーブル詳細 | `GET /api/v1/tables/{name}`（単一取得） | `POST /catalog/tables`（`table_names` 配列で一括取得） |
| Not Found | 404 エラーレスポンス | レスポンス内 `not_found` 配列 |
| 環境変数 | `CATALOG_DIR`（デフォルト `./catalog`） | `DATA_DIR`（デフォルト `./data`） |
| データ配置 | `catalog/tables/*.yaml` | `data/catalog/tables/*.yaml` + `data/catalog/index.yaml` |
| ルータープレフィックス | `/api/v1` | なし（直接 `/catalog/*`） |

### タスクスコープ

このタスクでは、テーブル API の v2 対応に加え、以下の共通基盤変更も含む：

- 環境変数 `CATALOG_DIR` → `DATA_DIR` への変更
- データディレクトリの再配置（`catalog/` → `data/`）
- `/api/v1` プレフィックスの廃止

用語集 API（`/terms`）は 1.3 で `/glossary/*` に変更するため、本タスクではプレフィックス廃止に伴う最低限の調整のみ行う。

#### Step 1: データディレクトリ再配置

既存の `catalog/` ディレクトリの内容を `data/` に移動し、v2 のディレクトリ構成に合わせる。

```
document-server/data/
├── catalog/
│   ├── index.yaml              ← 新規作成
│   └── tables/
│       ├── customer_master.yaml    ← catalog/tables/ から移動
│       └── id_pos_transactions.yaml ← catalog/tables/ から移動
└── glossary/
    └── terms/
        └── glossary.yaml           ← catalog/terms/ から移動
```

`data/catalog/index.yaml` を新規作成:

#### Step 4: CatalogStore 変更（catalog_loader.py）

3. `load_terms(data_dir)` のパスを変更:

#### Step 5: テーブルルーター変更（routers/tables.py）

ルート定義を v2 に変更:

```python
router = APIRouter(prefix="/catalog", tags=["catalog"])

@router.get("/index")
def get_table_index(store: CatalogStore = Depends(get_catalog_store)) -> dict:
    tables = [t.model_dump() for t in store.get_all_indexes()]
    return {"data": {"tables": tables, "total": len(tables)}}

@router.post("/tables", response_model=None)
def get_table_details(
    request: TableDetailRequest,
    store: CatalogStore = Depends(get_catalog_store),
) -> dict:
    tables, not_found = store.get_table_details(request.table_names)
    return {
        "data": {
            "tables": [t.model_dump(by_alias=True) for t in tables],
            "not_found": not_found,
        }
    }
```

### 技術的な考慮事項

- **インデックスと詳細の分離**: v2 ではインデックスを `index.yaml` から読み込む。これにより、インデックスに表示する情報（summary, category）を詳細 YAML と独立して管理できる。CatalogStore では `_indexes` と `_details` を別々のソースから読み込むが、整合性チェック（インデックスにあるが詳細がないテーブル）はログ警告に留める
- **一括取得の not_found 処理**: 要件では「存在しないテーブルを含む場合、見つかったものと見つからなかったもの両方を返却」と定義。HTTP ステータスは常に 200 とし、not_found 配列で通知する
- **用語集 API の暫定対応**: プレフィックス廃止で `/terms` に変わるが、1.3 で `/glossary/*` に移行予定。テストパスの変更のみ行い、機能変更は 1.3 のスコープとする
- **DATA_DIR 環境変数**: テーブルは `DATA_DIR/catalog/`、用語は `DATA_DIR/glossary/`、ロジックは `DATA_DIR/logic/`（1.6）と各機能がサブディレクトリを持つ構成。CatalogStore の各 `load_*` メソッドが自身のサブディレクトリパスを解決する

# タスク詳細: 2.1 用語集検索機能（サーバー＋MCP）

## 概要

`get_term_index` に `query` パラメータを追加し、用語名（name）および別名（aliases）の部分一致検索を実現する。

ユーザーのプロンプトに略称や表記揺れ（例: "PC"）が含まれていても、aliases を検索して正しい用語（例: "ポイントキャンペーン"）にマッチできるようにする。aliases は第2層（個別 YAML）にのみ格納されているため、サーバー起動時に全用語詳細を読み込んで検索インデックスを構築する。

### 実装手順

#### Step 1: document-server — 検索インデックス構築（catalog_loader.py）

`CatalogStore` に以下を追加する:

1. `_term_search_index: dict[str, list[str]]` — 用語名をキー、`[name] + aliases` の小文字リストを値とするマップ
2. `_build_term_search_index()` メソッド — `load_terms()` 完了後に呼び出し、全用語詳細から aliases を読み込んでインデックスを構築
3. `search_term_indexes(query: str) -> list[TermIndex]` メソッド — query を小文字化し、`_term_search_index` の各エントリで部分一致を判定、マッチした用語の `TermIndex` を返却

```python
# 検索インデックスの構造イメージ
_term_search_index = {
    "ロイヤルティランク": ["ロイヤルティランク", "loyalty rank", "顧客ランク"],
    "ポイントキャンペーン": ["ポイントキャンペーン", "pc", "point campaign"],
}
```

検索ロジック:
- query を小文字化
- 各用語の検索キーワードリスト（name + aliases を小文字化したもの）に対して `query in keyword` で部分一致判定
- いずれかのキーワードにマッチした用語を結果に含める

#### Step 2: document-server — ルーター変更（routers/terms.py）

```python
from fastapi import Query

@router.get("/index")
def get_term_index(
    store: CatalogStore = Depends(get_catalog_store),
    query: str | None = Query(default=None, description="検索キーワード（name + aliases 部分一致）"),
) -> dict:
    if query:
        terms = [t.model_dump() for t in store.search_term_indexes(query)]
    else:
        terms = [t.model_dump() for t in store.get_all_term_indexes()]
    return index_response("terms", terms)
```

#### Step 5: document-mcp — ツール実装更新（tools/term-index.ts）

`executeTermIndex` で `query` を引数から取り出し、クライアントに渡す:

```typescript
export async function executeTermIndex(
  args: Record<string, unknown>
): Promise<McpResponse> {
  try {
    const query = typeof args.query === "string" ? args.query : undefined;
    const { terms, total } = await getDocumentClient().getTermIndex(query);
    return createSuccessResponse({ terms, total });
  } catch (error) {
    return createErrorResponseFromError(error);
  }
}
```

### 技術的な考慮事項

- **検索インデックスはインメモリ**: aliases は第2層（個別 YAML）にのみ存在するため、起動時に全詳細を読み込んでインデックスを構築する。既存の `load_terms()` で詳細は既に読み込まれているので、そこから aliases を抽出する
- **部分一致の方式**: 大文字小文字を区別しない部分一致（`query.lower() in keyword.lower()`）。正規表現や全文検索エンジンは不要（用語数は数十〜数百程度を想定）
- **admin/reload 対応**: `POST /admin/reload` 時に検索インデックスも再構築する必要がある
- **パフォーマンス**: 用語数が限られているため、線形探索で十分（NF1: 200ms 以内の要件を満たす）

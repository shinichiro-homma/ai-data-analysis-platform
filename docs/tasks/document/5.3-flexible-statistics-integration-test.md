# タスク詳細: 5.3 柔軟な統計項目の結合テスト

## 概要

タスク 5.1（document-server）と 5.2（document-mcp）で実装した柔軟な統計項目（`statistics.additional`）が、サンプルデータを通じてエンドツーエンドで正しく動作することを結合テストで検証する。

サンプルカタログにカスタム統計項目を追加し、document-mcp 経由で取得した際にテーブル固有の統計情報が正しく返却されることを確認する。

## 関連ドキュメント

- 要件定義: `docs/requirements/document-server.md` の「F2.2: テーブル詳細」「statistics の属性テーブル」「AC1（582行）」「AC2（588-590行）」
- 要件定義: `docs/requirements/document-mcp.md` の「F2.1: テーブル詳細取得」「get_table_detail ツール定義」「AC2（543-553行）」
- 類似タスク: `docs/tasks/document/4.3-key-types-integration-test.md`（同パターンの結合テスト）
- 先行タスク: `docs/tasks/document/5.1-document-server-flexible-statistics.md`、`docs/tasks/document/5.2-document-mcp-flexible-statistics.md`

## 実装計画

### 作成・変更するファイル

| ファイル | 内容 |
|----------|------|
| `document-server/data/sample/catalog/tables/purchase_history.yaml` | サンプルカタログにカスタム統計項目（`avg_basket_size`, `top_categories`, `cancelled_rate`）を追加 |
| `document-mcp/tests/integration/catalog-integration.test.ts` | 結合テストケースの追加（新規作成 or 既存ファイルに追記） |

### 実装手順

1. **サンプルカタログにカスタム統計項目を追加**
   - `document-server/data/sample/catalog/tables/purchase_history.yaml` の `statistics` セクションに以下を追加:
     ```yaml
     statistics:
       row_count: 15000000
       date_range:
         from: "2020-01-01"
         to: "2025-12-31"
       update_frequency: "日次バッチ"
       # テーブル固有の拡張統計項目（additional として格納）
       avg_basket_size: 3.2
       top_categories: ["食品", "日用品", "衣料"]
       cancelled_rate: 0.05
     ```
   - 要件定義の YAML 記述例と一致させる
   - `customer_master.yaml` は additional なし（既存のまま）とし、additional 未定義パターンの検証に使用する

2. **document-mcp 結合テストを作成**
   - `document-mcp/tests/integration/catalog-integration.test.ts` に結合テストを追加
   - `vitest.config.integration.ts` の設定（`tests/integration/**/*.test.ts`）に従う
   - document-server が起動している前提で、HTTP 経由で実際の API を呼び出す
   - テスト実行: `scripts/test.sh --integration document-mcp`

3. **既存テストのリグレッション確認**
   - `scripts/test.sh document-server` で document-server の全テスト通過を確認
   - `scripts/test.sh document-mcp` で document-mcp の単体テスト通過を確認

### 技術的な考慮事項

- **サンプルデータ変更の影響**: `purchase_history.yaml` への統計項目追加は、既存のテスト（カラム数固定チェック等）に影響しない。統計情報はカラム定義とは独立したセクション
- **additional の空オブジェクト**: `additional` はデフォルト `{}` で常にレスポンスに含まれる（`key_types` の `None` 除外とは異なる設計判断）。additional 未定義テーブルでは `additional: {}` が返却される
- **結合テストの前提条件**: Docker 環境で document-server が起動し、最新のサンプルデータが読み込まれている必要がある。`scripts/test.sh --integration --rebuild document-mcp` で対応可能
- **MCP レスポンスの検証**: `handleToolCall()` のレスポンスは `{ content: [{ type: "text", text: JSON.stringify({ success: true, ...data }) }] }` 形式。テストでは `JSON.parse(result.content[0].text)` でパースしてアサーション

## テスト計画

### 結合テスト（catalog-integration.test.ts）

| テストケース | 検証内容 |
|-------------|---------|
| `get_table_detail で statistics.additional にカスタム統計項目が含まれる` | `purchase_history` を取得し、`additional.avg_basket_size === 3.2`、`additional.top_categories` が配列、`additional.cancelled_rate === 0.05` を確認 |
| `additional 未定義テーブルで空オブジェクトが返却される` | `customer_master` 等 additional を持たないテーブルを取得し、`additional` が `{}` であることを確認 |
| `additional と既知フィールドが共存する` | `purchase_history` で `row_count`、`date_range`、`update_frequency` の既知フィールドと `additional` が同時に正しく返却されることを確認 |

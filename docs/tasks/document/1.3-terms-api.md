# タスク詳細: 1.3 document-server: 用語集API実装（v2）

## 概要

document-server の用語集 API を v2 要件に合わせて再実装する。既存の v1 実装（`GET /terms`, `GET /terms/{name}`）を、v2 の新しい API パス（`GET /glossary/index`, `POST /glossary/terms`）に変更し、一括取得対応・インデックスファイル分離・用語ファイル個別化に移行する。

### v1 → v2 の主な変更点

| 項目 | v1（現状） | v2（今回の実装） |
|------|-----------|-----------------|
| 用語インデックス | `GET /terms`（YAML の terms 配列から自動生成） | `GET /glossary/index`（`glossary/index.yaml` から読み込み） |
| 用語詳細 | `GET /terms/{name}`（単一取得） | `POST /glossary/terms`（`term_names` 配列で一括取得） |
| Not Found | 404 / `TERM_NOT_FOUND` エラーレスポンス | レスポンス内 `not_found` 配列（HTTP 200） |
| ルータープレフィックス | なし（`/terms`） | `/glossary` |
| データ配置 | `glossary/terms/glossary.yaml`（1ファイルに全用語） | `glossary/index.yaml` + `glossary/terms/{用語名}.yaml`（1用語1ファイル） |

タスク 1.2 で実装済みのテーブル API（`/catalog/*`）と同じアーキテクチャパターンを踏襲する。

### 実装手順

#### Step 1: 用語集 YAML データ再構成

既存の `data/glossary/terms/glossary.yaml`（全用語1ファイル）を分離し、v2 のディレクトリ構成に変更する。

**変更後の構成:**

```
data/glossary/
├── index.yaml              # 用語インデックス（第1層）
└── terms/
    ├── ロイヤルティランク.yaml     # 用語詳細（第2層）
    ├── 統合会員ID.yaml
    └── 館.yaml
```

**`data/glossary/index.yaml`（新規作成）:**

```yaml
terms_index:
  - name: "ロイヤルティランク"
    summary: "統合会員の購買実績に基づく顧客ロイヤルティランク"
  - name: "統合会員ID"
    summary: "サンプル株式会社の統合顧客ID体系"
  - name: "店舗"
```

**`data/glossary/terms/ロイヤルティランク.yaml`（新規作成）:**

```yaml
name: "ロイヤルティランク"
aliases: ["ロイヤルティランク", "Loyalty Rank", "顧客ランク"]
```

他の2用語も同様に個別ファイル化。`data/glossary/terms/glossary.yaml` を削除。

#### Step 2: Pydantic モデル変更（models.py）

一括取得リクエスト用の `TermDetailRequest` モデルを追加:

```python
class TermDetailRequest(BaseModel):
    term_names: list[str] = Field(..., min_length=1, max_length=100)
```

既存の `TermValue`, `TermIndex`, `TermDetail` モデルはそのまま利用する。

#### Step 3: CatalogStore 変更（catalog_loader.py）

1. **`load_terms(data_dir)` を変更:**
   - インデックスを `data_dir / "glossary" / "index.yaml"` から `terms_index` キーで読み込み → `_term_indexes` 辞書に格納
   - 詳細を `data_dir / "glossary" / "terms" / "*.yaml"` から1ファイル1用語として読み込み → `_term_details` 辞書に格納
   - テーブル API の `load_tables()` と同じパターン（インデックスと詳細を別ソースから読み込み）

2. **`_parse_term_detail(term_data)` を新規追加（または既存 `_parse_term` をリファクタ）:**
   - 個別ファイルの YAML（`name` キーがトップレベル）をパースして `TermDetail` を返す
   - v1 の `_parse_term()` は `terms` 配列内の要素をパースしていたが、v2 ではトップレベルの辞書をパースする

3. **`_parse_term_index(entry)` を新規追加:**
   - `index.yaml` の `terms_index` 配列の各要素をパースして `TermIndex` を返す

4. **`get_term_details(term_names: list[str])` メソッドを新規追加:**
   - テーブル API の `get_table_details()` と同じパターン
   - 指定された `term_names` の用語詳細を一括取得
   - 戻り値: `tuple[list[TermDetail], list[str]]`（`terms`, `not_found`）

5. **既存メソッドの整理:**
   - `get_term_detail(name)` → 不要になるため削除（一括取得に統合）
   - `get_all_term_indexes()` → そのまま維持
   - 整合性チェック: インデックスにあるが詳細がない用語をログ警告

#### Step 4: 用語集ルーター変更（routers/terms.py）

v2 の API パスに変更:

```python
router = APIRouter(prefix="/glossary", tags=["glossary"])

@router.get("/index")
def get_term_index(store: CatalogStore = Depends(get_catalog_store)) -> dict:
    terms = [t.model_dump() for t in store.get_all_term_indexes()]
    return {"data": {"terms": terms, "total": len(terms)}}

@router.post("/terms", response_model=None)
def get_term_details(
    request: TermDetailRequest,
    store: CatalogStore = Depends(get_catalog_store),
) -> dict:
    terms, not_found = store.get_term_details(request.term_names)
    return {
        "data": {
            "terms": [t.model_dump() for t in terms],
            "not_found": not_found,
        }
    }
```

#### Step 5: main.py / admin.py 更新

- **main.py:** terms ルーター登録でプレフィックスが `/glossary` に変更されることを確認（ルーター側で設定済み）
- **admin.py:** `reload` 時の `terms_loaded` が新しい `load_terms()` で正しく動作することを確認

1. **conftest.py:** 用語集のサンプルデータを v2 構造（`index.yaml` + 個別ファイル）に変更

### 技術的な考慮事項

- **テーブル API との一貫性**: テーブル API（`/catalog/index` + `POST /catalog/tables`）と全く同じパターンで実装する。コードの対称性を保つことで保守性を向上
- **用語名の日本語対応**: 用語名は日本語を含む。ファイル名にも日本語が使われるため、`Path` オブジェクトのUTF-8 ハンドリングに注意。ただし Python の `pathlib` は標準でUTF-8対応
- **オプションフィールド**: `related_terms` と `values` はオプション。YAML に記載がない場合は `None` として扱う
- **v1 API の完全削除**: `GET /terms`, `GET /terms/{name}` は v2 で完全に置き換える（v1 の互換性維持は不要）

## テスト計画

### CatalogStore テスト（test_catalog_loader.py 変更）

- `glossary/index.yaml` から用語インデックスが読み込めること
- `glossary/terms/*.yaml` から用語詳細が個別ファイルで読み込めること

- `get_term_details(["ロイヤルティランク", "nonexistent"])` で 1 件の詳細 + 1 件の not_found が返ること

- `values` ありの用語と `values` なしの用語が正しくパースされること
- reload 時にインデックス・詳細の両方が再読み込みされること

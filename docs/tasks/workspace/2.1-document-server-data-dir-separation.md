# タスク詳細: 2.1 document-server データディレクトリ分離

## 概要

document-server の `data/` ディレクトリをサンプルデータと本番データで分離し、環境変数 `DATA_ENV` で切り替えられるようにする。

現在は `data/` 直下にカタログ・用語集・ロジックファイルがフラット配置されているが、これを `data/sample/` と `data/production/` に分離する。`config.py` の `DATA_DIR` 解決ロジックに `DATA_ENV` を組み込み、起動時に指定環境のデータが読み込まれるようにする。

### なぜこのタスクが必要か

- サンプルデータ（開発・検証用）と本番データ（実運用）を同じディレクトリで管理すると、誤って本番データを上書きするリスクがある
- 環境切り替えにより、開発中はサンプルデータで動作確認し、運用時は本番データに切り替える運用が可能になる
- Workspace Phase 2 の後続タスク（2.2〜2.5）の前提となるタスク

### 実装手順

#### ステップ 1: データディレクトリの移動

現在のフラット構成:
```
data/
├── catalog/
├── glossary/
└── logic/
```

を以下に移動:
```
data/
└── sample/
    ├── catalog/
    ├── glossary/
    └── logic/
```

具体的には:
```bash
mkdir -p document-server/data/sample
mv document-server/data/catalog document-server/data/sample/
mv document-server/data/glossary document-server/data/sample/
mv document-server/data/logic document-server/data/sample/
```

#### ステップ 2: config.py の変更

現在の実装:
```python
DATA_DIR: Path = Path(os.environ.get("DATA_DIR", "./data")).resolve()
```

変更後:
```python
DATA_ENV: str = os.environ.get("DATA_ENV", "sample")
DATA_DIR: Path = Path(os.environ.get("DATA_DIR", f"./data/{DATA_ENV}")).resolve()
```

ポイント:
- `DATA_ENV` のデフォルトは `sample`（開発環境では常にサンプルデータ）
- `DATA_DIR` を明示的に指定した場合は `DATA_ENV` を無視する（テスト時に `tmp_path` を直接指定するため）
- 起動時に `DATA_DIR` の存在チェックを行い、存在しない場合はエラーで起動失敗させる（要件 AC1 に記載）

#### ステップ 3: 起動時バリデーションの追加

`main.py` の `lifespan` 内で、`DATA_DIR` の存在チェックを追加する。現在は `store.load_all(DATA_DIR)` の中で暗黙的に失敗するが、明示的なエラーメッセージを出す。

```python
if not DATA_DIR.is_dir():
    raise RuntimeError(f"Data directory not found: {DATA_DIR} (DATA_ENV={DATA_ENV})")
```

#### ステップ 4: テストの更新

**conftest.py の変更:**

`_create_data_dir` ヘルパーは `tmp_path` 直下にカタログ・用語集・ロジックのディレクトリを作成している。これは `DATA_DIR` を直接 `tmp_path` に設定しているため、**ディレクトリ構造自体の変更は不要**。テストでは `DATA_DIR` を明示的に渡しており、`DATA_ENV` によるパス解決は通らない。

**test_catalog_loader.py に追加するテストケース:**

- `DATA_ENV=sample` で `data/sample/` からデータが読み込まれることの検証
- `DATA_ENV=production` で `data/production/` が存在しない場合のエラー検証
- `DATA_DIR` を明示指定した場合に `DATA_ENV` が無視されることの検証

**config.py 単体のテスト:**

`DATA_ENV` → `DATA_DIR` のパス解決ロジックを直接テストする。

### 技術的な考慮事項

- **後方互換性**: `DATA_DIR` を明示指定すれば従来通り動作するため、既存テストへの影響は最小限
- **main.py / admin.py は変更不要**: これらは `from .config import DATA_DIR` で import しているため、`config.py` の変更だけで動作が変わる
- **admin.py の reload**: `/admin/reload` は `DATA_DIR` をそのまま使うため、サーバー起動後に `DATA_ENV` を切り替える機能は不要（再起動が必要）
- **Dockerfile**: `DATA_ENV` 環境変数は `docker-compose.yml` 側で設定するため（タスク 2.4）、ここでは変更しない

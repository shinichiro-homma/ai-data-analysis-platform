# タスク詳細: 1.3 ワークスペース分離の結合テスト

## 概要

Workspace Phase 1 で実装したワークスペース分離機能（1.1 ワークスペース作成・一覧、1.2 既存ツールのワークスペーススコープ対応）が正しく動作することを結合テストで検証する。

2つのワークスペースを作成し、各ワークスペース内でノートブック作成・ファイル操作を行い、**互いのワークスペースのファイルが見えないこと（分離性）**を確認する。また、MCP再起動後もワークスペースが`workspace_list`で再発見可能であることを確認する。

### 実装手順

1. **テストファイル作成**: `tests/integration/workspace-isolation.test.ts` を作成
2. **テストヘルパー追加**: `tests/setup.ts` にワークスペースクリーンアップ用ヘルパー `cleanupWorkspace` を追加（`jupyterClient.deleteContents('workspaces/{workspace_id}')` を使用）
3. **テストケース実装**: 以下の5つのテストケースを実装

### テストケース一覧

#### 1. ワークスペース作成・一覧の基本動作

```
workspace_create("分析A") → workspace_create("分析B") → workspace_list
→ 2つのワークスペースが一覧に含まれることを確認
```

#### 2. ワークスペース間のファイル分離

```
workspace_create("WS-A") → workspace_create("WS-B")
→ session_create(workspace_id=A) → notebook_create(workspace_id=A, name="analysis-a")
→ session_create(workspace_id=B) → notebook_create(workspace_id=B, name="analysis-b")
→ file_list(workspace_id=A): "analysis-a.ipynb" のみ（"analysis-b" は見えない）
→ file_list(workspace_id=B): "analysis-b.ipynb" のみ（"analysis-a" は見えない）
```

#### 3. ワークスペーススコープのセッション作成

```
workspace_create("WS-C")
→ session_create(workspace_id=C)
→ execute_code(session_id, 'import os; print(os.getcwd())')
→ stdout にワークスペースのパスが含まれることを確認
```

#### 4. ワークスペースの永続性（MCP再起動シミュレーション）

```
workspace_create("永続テスト") → notebook_create(workspace_id, name="persist-test")
→ 新しい jupyterClient インスタンスで workspace_list を呼び出し
→ 作成したワークスペースが一覧に含まれることを確認
→ file_list(workspace_id) で notebook が存在することを確認
```

**注**: 実際のMCP再起動は行わず、`jupyterClient.listWorkspaces()` を直接呼び出して永続性を検証する。ワークスペースはファイルシステム上のディレクトリとして永続化されるため、APIクライアント経由で再発見できることを確認すれば十分。

#### 5. E2Eフロー: ワークスペースでの分析フロー

```
workspace_create("E2E分析")
→ session_create(workspace_id, notebook_path="e2e-analysis.ipynb")
→ notebook_create(workspace_id, session_id, name="e2e-analysis")
→ notebook_add_cell(notebook_path, cell_type="code", source="x = 42")
→ execute_code(session_id, 'x = 42')
→ execute_code(session_id, 'print(x)')
→ stdout が "42" であることを確認
→ file_list(workspace_id): "e2e-analysis.ipynb" が存在
→ session_delete(session_id)
```

### 技術的な考慮事項

- **テストの独立性**: 各テストケースで新しいワークスペースを作成し、afterEach でクリーンアップする。テスト間の依存を排除する
- **クリーンアップ**: ワークスペースのクリーンアップは `jupyterClient.deleteContents('workspaces/{workspace_id}')` で行う。セッションは `cleanupSession` で個別に削除する
- **ノートブックパスの扱い**: ワークスペーススコープのツールでは、ノートブックパスが `workspaces/{workspace_id}/{name}.ipynb` の形式になる。file_list の結果からはこのプレフィックスが除去される
- **テスト実行時間**: ワークスペース作成、セッション作成、コード実行を含むため、各テストに十分なタイムアウト（15〜20秒）を設定する
- **既存テストパターン踏襲**: `ai-sync-flow.test.ts` や `variables-workflow.test.ts` と同様のパターン（beforeAll で接続確認、afterEach でクリーンアップ、handleToolCall + parseToolCallResult）を使用する

## テスト計画

### テスト実行方法

```bash
# ワークスペース分離テストのみ
cd jupyter-mcp
npm run test:integration -- --testPathPattern workspace-isolation

# 全結合テスト
npm run test:integration
```

### 前提条件

- `docker-compose up -d` で jupyter-server が起動していること
- 環境変数 `JUPYTER_SERVER_URL`、`JUPYTER_TOKEN` が設定されていること

### テストフレームワーク

- Vitest（既存プロジェクトの統一フレームワーク）
- `vitest.config.integration.ts` の設定を使用（testTimeout: 30000ms、singleFork: true）

# タスク詳細: 2.6 jupyter-server 環境切り替え対応

## 概要

`DATA_ENV` 環境変数に応じて、jupyter-server のワークスペースルートディレクトリを `workspaces/{DATA_ENV}` に自動解決する。これにより、サンプルデータと本番データの分析ワークスペースが環境ごとに分離され、`switch-env.sh` での環境切り替え時にワークスペースが混在しなくなる。

Workspace Phase 2 の他タスク（2.1〜2.5）で document-server・PostgreSQL・docker-compose の環境分離は完了済み。本タスクは jupyter-server 側の対応を行い、Workspace Phase 2 を完了させる。

## 関連ドキュメント

- 要件定義: `docs/requirements/jupyter-server.md`
  - NF4（運用性）: `DATA_ENV` に応じて WORKSPACE_ROOT_DIR が自動解決される
  - 環境変数表: `DATA_ENV`, `WORKSPACE_ROOT_DIR` の定義
- PLAN.md の変更履歴（2026-03-05）に詳細な説明あり

### 実装手順

#### ステップ 1: base.py の WORKSPACE_ROOT_DIR 解決ロジック変更

`jupyter-server/extensions/custom_api/base.py` L16-18 を変更:

**変更前:**
```python
WORKSPACE_ROOT_DIR = os.environ.get(
    "WORKSPACE_ROOT_DIR", "/home/jovyan/work/workspaces"
)
```

**変更後:**
```python
_data_env = os.environ.get("DATA_ENV", "sample")
WORKSPACE_ROOT_DIR = os.environ.get(
    "WORKSPACE_ROOT_DIR", f"/home/jovyan/work/workspaces/{_data_env}"
)
```

設計判断:
- `WORKSPACE_ROOT_DIR` が明示的に設定されている場合はそちらを優先（既存の挙動を壊さない）
- `WORKSPACE_ROOT_DIR` 未設定時のみ `DATA_ENV` を使ってデフォルトを算出
- `DATA_ENV` のデフォルトは `sample`（他コンポーネントと統一）

#### ステップ 2: jupyter-server/CLAUDE.md の更新

環境変数表の `DATA_ENV` 行から「Phase未着手」の注記を削除し、実装済みであることを反映する。

#### ステップ 3: 動作確認

1. `docker-compose config` で `DATA_ENV` が jupyter-server に渡されていることを確認（既に 2.4 で対応済みだが念のため）
2. `scripts/switch-env.sh` で jupyter-server が再起動対象に含まれていることを確認（既に対応済みだが念のため）

### 技術的な考慮事項

- **既存ワークスペースへの影響**: `jupyter_work` ボリュームは `switch-env.sh` で削除されない設計。環境切り替え後もワークスペースデータは保持されるが、`WORKSPACE_ROOT_DIR` が変わるため、別環境のワークスペースは見えなくなる（意図通り）
- **テスト時の考慮**: 単体テストでは `WORKSPACE_ROOT_DIR` を直接設定するため、`DATA_ENV` による解決ロジックの影響を受けない。`DATA_ENV` 解決ロジック自体のテストを追加する
- **docker-compose.yml への変更は不要**: `DATA_ENV` は既にタスク 2.4 で jupyter-server に渡されている
- **switch-env.sh への変更は不要**: jupyter-server は既に再起動対象に含まれている

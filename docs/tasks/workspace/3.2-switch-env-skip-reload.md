# タスク詳細: 3.2 switch-env.sh のスキップ判定 + ユーザー確認フロー

## 概要

`switch-env.sh` に環境別ボリュームの存在チェックとユーザー確認フローを追加し、データに更新がない場合の再ロードをスキップできるようにする。

### 新しいフロー

```
$ scripts/switch-env.sh production

現在の環境: sample
切り替え先: production

--- ケース A: ボリュームが存在しない（初回） ---
production のデータボリュームが見つかりません。
フルデータロードを実行します。
（既存フロー: postgres 起動 → run_load_data → サービス起動）

--- ケース B: ボリュームが存在する ---
production のデータは既にロード済みです。
データに更新はありますか？ [y/N]

  N → ボリューム切り替えのみ
      1. .env の DATA_ENV を書き換え
      2. postgres を停止 → 再起動（既存ボリュームを使用）
      3. document-server, jupyter-server を再起動
      → 数秒で完了

  y → フルリロード
      1. 既存ボリュームを削除
      2. 既存フローで再ロード
```

### 実装手順

#### Step 1: ボリューム存在チェックの追加

```bash
target_env="$ENV"

if postgres_volume_exists "$target_env"; then
  # ケース B: ボリュームあり
  echo "${target_env} のデータは既にロード済みです。"
  read -p "データに更新はありますか？ [y/N] " data_updated
  if [[ "${data_updated}" == "y" || "${data_updated}" == "Y" ]]; then
    # フルリロード（既存フロー）
    ...
  else
    # スキップフロー（ボリューム保持、サービス再起動のみ）
    ...
  fi
else
  # ケース A: ボリュームなし → フルロード（既存フロー）
  ...
fi
```

#### Step 2: スキップフロー（ボリューム保持）の実装

ボリュームを削除せずに postgres を再起動し、document-server と jupyter-server を再起動する。

```bash
skip_reload_flow() {
  # postgres を停止→再起動（ボリューム保持）
  docker compose rm -fs postgres document-server jupyter-server
  docker compose up -d postgres
  wait_for_postgres_ready ...
  # DB が既にデータを持っているため run_load_data は不要
  # ただし create-tables.sql の再適用も不要（IF NOT EXISTS で冪等）
  docker compose up -d document-server
  wait_for_http_service ...
  docker compose up -d jupyter-server
  wait_for_http_service ...
}
```

#### Step 3: `-y` / `--yes` オプションとの整合

`-y` が指定されている場合:
- ボリュームなし → 確認なしでフルロード（既存動作）
- ボリュームあり → **再ロードしない**（スキップフロー）

`-y` + データ更新を強制する場合は `--force-reload` オプションを追加:
```bash
scripts/switch-env.sh -y --force-reload production
```

### 技術的な考慮事項

- **create-tables.sql の冪等性**: `CREATE TABLE IF NOT EXISTS` で生成されているため、スキップフロー時に再適用しても安全。ただし再適用自体不要（データは既に存在）
- **init スクリプトの変更検知**: カタログ YAML を変更した場合、init スクリプトが古くなる。この場合は `check-freshness.sh` が STALE を報告するので、ユーザーが判断できる
- **postgres コンテナの再起動**: ボリュームを保持したまま `docker compose up -d postgres` するだけで、既存データがマウントされる

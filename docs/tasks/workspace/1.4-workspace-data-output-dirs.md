# タスク詳細: 1.4 ワークスペース data/output ディレクトリ

## 概要

ワークスペース作成時に `data/` と `output/` サブディレクトリを自動作成し、APIレスポンスに `data_path` と `output_path` を含めるようにする。これにより、AIエージェントが分析用データの配置場所（`data/`）と分析結果の出力先（`output/`）を明確に把握でき、ワークスペース内のファイル管理が整理される。

現在のワークスペース作成（タスク 1.1）では、ワークスペースディレクトリと `metadata.json` のみが作成されており、`data/` と `output/` サブディレクトリは未実装。

## 関連ドキュメント

- 要件定義:
  - `docs/requirements/jupyter-server.md`「F6.1: ワークスペースディレクトリ作成」— `data/` と `output/` サブディレクトリの自動作成
  - `docs/requirements/jupyter-mcp.md`「F8.1: ワークスペース作成」— 戻り値に `data_path` と `output_path` を含める
- API仕様: `docs/design/api-contracts.md`「POST /api/workspaces」「GET /api/workspaces」— レスポンスに `data_path`, `output_path` フィールド

### 実装手順

#### ステップ1: jupyter-server ワークスペースハンドラー修正

`workspace_handlers.py` を修正する。

**POST /api/workspaces（作成）の変更:**
1. ワークスペースディレクトリ作成後に `data/` と `output/` サブディレクトリを作成
2. レスポンスに `data_path` と `output_path` を追加

```python
# ディレクトリ作成（既存コードの後に追加）
(workspace_dir / "data").mkdir(exist_ok=True)
(workspace_dir / "output").mkdir(exist_ok=True)

# レスポンスに追加
self.write_success({
    "workspace_id": workspace_id,
    "name": metadata["name"],
    "path": f"workspaces/{workspace_id}",
    "data_path": f"workspaces/{workspace_id}/data",
    "output_path": f"workspaces/{workspace_id}/output",
    "created_at": created_at,
})
```

**GET /api/workspaces（一覧）の変更:**
1. `_read_workspace()` のレスポンスに `data_path` と `output_path` を追加
2. `file_count` のカウントから `metadata.json`、`data/`、`output/` を除外（構造ファイルはカウントしない）

#### ステップ2: jupyter-mcp 型定義修正

`types.ts` の `WorkspaceInfo` にフィールドを追加:

```typescript
export interface WorkspaceInfo {
  workspace_id: string;
  name: string;
  path: string;
  data_path?: string;    // 追加
  output_path?: string;  // 追加
  created_at: string;
  file_count?: number;
}
```

`data_path`, `output_path` はオプショナルとする。既存のワークスペース（タスク 1.4 以前に作成されたもの）にはこれらのフィールドがない可能性があるため。

### 技術的な考慮事項

#### 既存ワークスペースとの互換性
- タスク 1.4 以前に作成されたワークスペースには `data/` と `output/` が存在しない
- `_read_workspace()` では、ディレクトリの存在に関わらず `data_path` と `output_path` を常にレスポンスに含める（パスの規約に基づく）
- `WorkspaceInfo` 型では `data_path`, `output_path` をオプショナルにすることで型の互換性を維持

#### file_count の算出方法変更
- 現在: `metadata.json` を除く全エントリをカウント
- 変更後: `metadata.json`、`data/`、`output/` を除外してカウント
- 理由: `data/` と `output/` はインフラ的なディレクトリであり、ユーザーが作成したファイル数として数えるべきではない

#### 冪等性
- `(workspace_dir / "data").mkdir(exist_ok=True)` を使用するため、ディレクトリが既に存在してもエラーにならない

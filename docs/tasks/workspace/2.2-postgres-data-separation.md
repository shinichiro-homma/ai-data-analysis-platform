# タスク詳細: 2.2 PostgreSQL データ分離

## 概要

PostgreSQL の初期データ（CSV）を環境別ディレクトリで管理できるようにする。現在 `postgres/data/` に直接配置されている CSV ファイルを `postgres/data/sample/` に移動し、`02-load-data.sh` が `DATA_ENV` 環境変数に応じて適切なサブディレクトリからデータをロードするように変更する。

タスク 2.1（document-server データ分離）で確立された `DATA_ENV` パターンを PostgreSQL 初期化スクリプトにも適用する。

## 実装計画

### 変更するファイル

| ファイル | 変更内容 |
|----------|----------|
| `postgres/data/sample/*.csv` | 既存 CSV を `sample/` サブディレクトリに移動 |
| `postgres/data/production/.gitkeep` | 本番データ用ディレクトリを作成（空） |
| `postgres/init/02-load-data.sh` | `DATA_ENV` 環境変数による切り替え対応 |

### 実装手順

#### ステップ 1: ディレクトリ構造の変更

現在の構成：
```
postgres/data/
├── customer_master.csv
├── product_master.csv
└── purchase_history.csv
```

変更後：
```
postgres/data/
├── sample/
│   ├── customer_master.csv
│   ├── product_master.csv
│   └── purchase_history.csv
└── production/
    └── .gitkeep
```

- `postgres/data/sample/` ディレクトリを作成
- 既存の 3 つの CSV ファイルを `sample/` に移動
- `postgres/data/production/` ディレクトリを作成し `.gitkeep` を配置

#### ステップ 2: `02-load-data.sh` の環境切り替え対応

現在のスクリプトは `DATA_DIR="/tmp/data"` をハードコードしている。これを `DATA_ENV` 環境変数で切り替えるように変更する。

変更内容：
```bash
#!/bin/bash
set -euo pipefail

# DATA_ENV: sample (default) or production
DATA_ENV="${DATA_ENV:-sample}"

# Validate DATA_ENV
case "$DATA_ENV" in
    sample|production) ;;
    *)
        echo "ERROR: Invalid DATA_ENV='$DATA_ENV'. Must be 'sample' or 'production'" >&2
        exit 1
        ;;
esac

DATA_DIR="/tmp/data/${DATA_ENV}"

# ... (以下は既存のファイル存在チェック＋COPY処理をそのまま維持)
```

設計判断：
- docker-compose.yml のボリュームマウント（`./postgres/data:/tmp/data`）は変更不要。`postgres/data/` 全体がマウントされるため、スクリプト側で `${DATA_ENV}` サブディレクトリを参照すればよい
- docker-compose.yml への `DATA_ENV` 環境変数の追加はタスク 2.4 のスコープ。現時点ではデフォルト値 `sample` で動作する

### 技術的な考慮事項

- **docker-compose.yml との関係**: 現在の `./postgres/data:/tmp/data` マウントはそのまま維持。ディレクトリ構造が変わっても `/tmp/data/sample/`, `/tmp/data/production/` として参照できる
- **後方互換性**: `DATA_ENV` 未設定時はデフォルト `sample` のため、既存の `docker-compose up` はそのまま動作する
- **タスク 2.3/2.4 との依存**: 本タスクは `02-load-data.sh` のロジック変更のみ。`DATA_ENV` 環境変数を docker-compose 経由で渡す設定は 2.4、`switch-env.sh` スクリプトは 2.3 で対応
- **PostgreSQL 初期化タイミング**: `docker-entrypoint-initdb.d` のスクリプトは初回起動時のみ実行される。環境切り替え時はボリューム削除→再構築が必要（タスク 2.3 のスコープ）

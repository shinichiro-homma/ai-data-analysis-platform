# タスク詳細: 9.3 jupyterlab-ai-sync ビルドのルート venv 統合

## 概要

`jupyterlab-ai-sync` の `npm run build`（内部で `jupyter labextension build .` を呼ぶ）が必要とする `jupyter` / `jupyterlab` / `jupyter_packaging` をルート venv に集約し、ローカル開発者が別途 `pip install jupyterlab` を実行しなくてもビルドできるようにする。

`jupyterlab-ai-sync/pyproject.toml` の `[build-system]`（`jupyter_packaging~=0.12` による build backend）は変更しない。既存の extension ビルドフローを維持したまま、ビルドに必要な Python 依存のみをルート venv 側で提供する。

Docker ビルド経路（`jupyter-server/Dockerfile` 内の JupyterLab 側処理、`.github/workflows/ci.yml` の `jupyterlab-ai-sync-build` ジョブ）には一切手を加えない。CI は既に `setup-python@v5` + `pip install jupyterlab` で独立動作しており、本 Phase の対象外。

### 技術的な考慮事項

- **`uv run` の project 解決**: `jupyterlab-ai-sync/` 内で `uv run` を実行すると、uv はディレクトリ直下の `pyproject.toml`（build backend 定義）を拾ってしまう。ルート venv を使わせるには `--project <repo_root>` オプションを明示する必要がある
- **`jupyter_packaging` のバージョン互換**: `jupyterlab-ai-sync/pyproject.toml` の `build-system.requires` は `jupyter_packaging~=0.12` を要求する。ルート dev group の `jupyter-packaging>=0.12,<1` がこれと互換である必要がある（`~=0.12` は `>=0.12, <1.0` 相当なので互換）
- **`jupyterlab` メジャーバージョン**: `build-system.requires` は `jupyterlab~=4.0`。ルート dev group も `jupyterlab>=4.0.0,<5` で揃える
- **PATH 解決**: `npm run build` が `jupyter labextension build .` を実行する際、`jupyter` コマンドは `uv run` 環境下の `$PATH` から解決される。`uv run -- npm run build` 形式で npm を起動すれば、その子プロセスにも venv の PATH が伝播する
- **CI との独立性**: 本タスクはローカル統一のみ。CI の `pip install jupyterlab>=4.0.0` は従来通り動く。将来 CI を uv 化する場合は別 Phase
- **Docker との独立性**: `jupyter-server/Dockerfile` は JupyterLab 本体を Docker イメージ内にインストールし、その上に別途 custom_api を配置している。jupyterlab-ai-sync のビルド成果物を Docker イメージに含める経路があるかどうかは実装時に再確認し、あってもローカル Python 環境とは独立に動くことを確認する
- **`jupyterlab-ai-sync/pyproject.toml` の非 workspace 化**: フラット配置方針のため、workspace member には追加しない。ビルド時にルート venv の `jupyter_packaging` を使う形になる

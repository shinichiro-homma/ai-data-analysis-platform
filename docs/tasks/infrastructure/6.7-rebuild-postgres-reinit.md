# タスク詳細: 6.7 rebuild.sh の postgres データ自動更新

## 概要

`rebuild.sh` の通常リビルドフローに postgres の鮮度チェック＋再初期化を組み込む。CSV ファイルの追加・変更やカタログ YAML の更新後に `rebuild.sh` を実行すると、DB データが自動的に最新化される。

## 関連ドキュメント

- `scripts/rebuild.sh` — 変更対象
- `scripts/check-freshness.sh` — 鮮度チェックロジックの参照元
- `scripts/switch-env.sh` — postgres 再初期化ロジックの参照元

## 実装計画

### 変更するファイル

| ファイル | 内容 |
|----------|------|
| `scripts/rebuild.sh` | postgres 鮮度チェック＋再初期化の組み込み |

### 再初期化の判定ルール

| ケース | 再初期化 |
|--------|---------|
| `rebuild.sh`（全サービス）| データが古い場合のみ |
| `rebuild.sh --clean` | 常に再初期化 |
| `rebuild.sh postgres` | 常に再初期化 |
| `rebuild.sh jupyter-server` | しない（スコープ外） |
| `rebuild.sh --reset` | 既存動作のまま（全ボリューム削除） |

### 実装手順

1. `.env` から `DATA_ENV` を読み込む（`check-freshness.sh` と同じパターン）
2. ヘルパー関数を追加:
   - `newest_file_epoch()` — ディレクトリ内の最新ファイルのタイムスタンプ取得
   - `is_postgres_in_scope()` — SERVICES に postgres が含まれるか判定
   - `check_postgres_needs_reinit()` — 鮮度チェック（2層）+ 判定
   - `reinitialize_postgres()` / `wait_for_postgres_init()` — postgres 再初期化
3. 通常リビルドフローに postgres 鮮度チェック＋再初期化を挿入
4. `--reset` フローにも postgres 初期化完了待機を追加
5. usage テキストを更新

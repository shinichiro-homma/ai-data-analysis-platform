# タスク詳細: 2.4 ドキュメント最終整備

## 概要

プロジェクト全体のドキュメントを最終整備する。ルート README.md を拡充し、初めてプロジェクトに触れる人が「クローン → セットアップ → 起動 → AI接続」まで迷わず進められる状態にする。

現状の README.md は簡素で、以下の重要情報が欠落している：
- jupyterlab-ai-sync コンポーネントの記載
- 環境変数（`.env`）のセットアップ手順
- Claude Desktop への MCP 接続設定方法
- PostgreSQL・データカタログの説明
- 主要機能（ワークスペース分離、AIリアルタイム同期）の説明
- MCPツール一覧

## 関連ドキュメント

- 全体像: `docs/overview.md`（アーキテクチャ図、コンポーネント詳細、MCPツール一覧、API一覧）
- 各コンポーネント: `*/CLAUDE.md`（ディレクトリ構成、コマンド一覧、環境変数）
- 現行 README: `README.md`（簡素版、拡充が必要）

## 実装計画

### 更新するファイル

| ファイル | 内容 |
|----------|------|
| `README.md` | ルート README を全面拡充 |
| `jupyterlab-ai-sync/README.md` | 日本語化・内容更新 |
| `jupyterlab-ai-sync/package.json` | プレースホルダー（author 等）の修正 |

### 設計方針

- **ルート README.md に情報を集約する**。各コンポーネントの README は作成しない（CLAUDE.md が既に各コンポーネントの詳細を提供しているため、重複を避ける）
- **README.md は「利用者向け」**、CLAUDE.md は「AI/開発者向け」と位置づける
- docs/ 配下の詳細ドキュメントへのリンクを適切に配置し、README.md を入口として機能させる
- 既存の構造・スタイルを尊重し、日本語で統一する

### 技術的な考慮事項

- **コンポーネント個別の README は作成しない**: 各コンポーネントには既に CLAUDE.md が存在し、ディレクトリ構成・コマンド一覧・環境変数が記載されている。README を別途作成すると情報が二重管理になり、メンテナンスコストが上がる
- **MCP サーバーは docker-compose 外で起動**: jupyter-mcp と document-mcp は Claude Desktop からローカルプロセスとして起動されるため、docker-compose には含まれない。この点を README で明確にする
- **claude_desktop_config.json の設定例**: 実際のパスはユーザー環境に依存するため、プレースホルダーを使用する

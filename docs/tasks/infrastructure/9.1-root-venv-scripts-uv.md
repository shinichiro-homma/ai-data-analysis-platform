# タスク詳細: 9.1 ルート venv 導入 + scripts uv 化 + Bash フック

## 概要

リポジトリルートに uv ベースの単一仮想環境を導入し、`scripts/` 配下の全シェルスクリプトが呼び出す `python` / `python3` を `uv run python` 経由に置換する。さらに `.claude/hooks/block-direct-python.sh` を PreToolUse on Bash フックとして登録し、Claude Code セッション内での `python` / `python3` / `pip` / `pip3` 直叩きをブロックする（`uv run ...` は通す）。

本タスクは Phase 9 の基盤であり、9.2 / 9.3 はこの venv に後から依存を積む形で成立する。Docker ビルド経路には一切触らない。

### 技術的な考慮事項

- **ルート `pyproject.toml` と `scripts/pyproject.toml` の関係**: `scripts/pyproject.toml` は ruff 設定のために残す。ルート `pyproject.toml` は依存管理専用。uv workspace は使わず、ルートの `pyproject.toml` だけが `uv sync` の対象になる（フラット配置方針）
- **ルート dev 依存の範囲**: scripts/ の Python 直叩きで使われている外部パッケージ（`psycopg2` / `pyarrow` / `pyyaml`）を旧 `scripts/.venv/` と同じバージョン帯でルート venv に含める。これを含めないと `uv run python -c "import psycopg2"` 等が失敗し、`switch-env.sh` のホスト TCP 接続チェック・`load-data.py`・`generate_init.py` が動かなくなる（等価置換の前提条件）。`mypy`, `pytest` 等のテスト系は 9.2 で追加
- **フックの検出範囲**: `pytest`, `mypy`, `ruff` はブロック対象外（`scripts/test.sh` / `scripts/lint.sh` が統一入口になるため、これらを直接叩いても問題ない）
- **`scan-adhoc-script.sh` との競合なし**: 既存の `scan-adhoc-script.sh` は tmp/ スクリプト内の文字列スキャンのみを行い、Python 実行自体は扱わない。新規フックと責務が重複しない
- **shebang スクリプト**: `scripts/convert-csv-to-parquet.py` と `scripts/lib/generate_init.py` の shebang は保持し、呼び出し側を `uv run python <path>` 形式にする
- **既存 `scripts/.venv/`**: 既に uv で作成済み。ルート `.venv/` に切り替えた後、`scripts/.venv/` は不要になるが削除は手作業で行う（本タスクのスクリプトでは消さない）
- **フック exit コード**: ブロック時は exit 2 + stderr にブロック理由を出力（既存フックの流儀に合わせる）

# タスク詳細: 3.3 ワークスペース分離の動作確認

## 概要

複数ワークスペースで独立した分析を同時実行し、データ・セッションが相互に分離されていることをMCPクライアント（Claude Code）から手動で確認する。MCP再起動後のワークスペース再発見も検証する。

Phase 10（ワークスペース分離）で実装された機能が、実際のMCPクライアント操作で正常に動作することを保証するための検証タスク。

### 検証手順

15.1・15.2 と同様に、MCPクライアント（Claude Code）からMCPツールを直接呼び出して検証する。

#### Phase 1: 環境準備

```bash
docker-compose up -d
scripts/rebuild-mcp.sh jupyter-mcp
```

確認項目:
- [ ] jupyter-server が起動している（http://localhost:8888）
- [ ] jupyter-mcp が接続可能（MCPツール一覧に workspace_create 等が表示される）

#### Phase 2: ワークスペース作成と基本操作

2つのワークスペースを作成し、それぞれで独立した分析環境を構築する。

| 操作 | ツール | パラメータ |
|------|--------|-----------|
| ワークスペースA作成 | `workspace_create` | `name: "分析A"` |
| ワークスペースB作成 | `workspace_create` | `name: "分析B"` |
| ワークスペース一覧確認 | `workspace_list` | - |

確認項目:
- [ ] ワークスペースAが作成され、workspace_id が返される
- [ ] ワークスペースBが作成され、異なる workspace_id が返される
- [ ] workspace_list で両方のワークスペースが表示される
- [ ] 各ワークスペースの戻り値に `data_path` と `output_path` が含まれる

#### Phase 3: 独立したセッション・ノートブック作成

各ワークスペースにノートブックとセッションを作成する。

| 操作 | ツール | パラメータ |
|------|--------|-----------|
| ワークスペースAにセッション作成 | `session_create` | `workspace_id: "{ws_a_id}"` |
| ワークスペースBにセッション作成 | `session_create` | `workspace_id: "{ws_b_id}"` |
| ワークスペースAにノートブック作成 | `notebook_create` | `workspace_id: "{ws_a_id}", session_id: "{session_a_id}", name: "analysis-a"` |
| ワークスペースBにノートブック作成 | `notebook_create` | `workspace_id: "{ws_b_id}", session_id: "{session_b_id}", name: "analysis-b"` |

確認項目:
- [ ] ワークスペースAのセッションが作成される（workspace_id がAのもの）
- [ ] ワークスペースBのセッションが作成される（workspace_id がBのもの）
- [ ] ノートブックが各ワークスペースに作成される

#### Phase 4: ファイル分離の確認

各ワークスペースのファイル一覧を確認し、他方のファイルが見えないことを確認する。

| 操作 | ツール | パラメータ |
|------|--------|-----------|
| ワークスペースAのファイル一覧 | `file_list` | `workspace_id: "{ws_a_id}"` |
| ワークスペースBのファイル一覧 | `file_list` | `workspace_id: "{ws_b_id}"` |

確認項目:
- [ ] ワークスペースAの file_list に `analysis-a.ipynb` が表示される
- [ ] ワークスペースAの file_list に `analysis-b.ipynb` が表示されない
- [ ] ワークスペースBの file_list に `analysis-b.ipynb` が表示される
- [ ] ワークスペースBの file_list に `analysis-a.ipynb` が表示されない
- [ ] 各ワークスペースに `data/` と `output/` ディレクトリが存在する

#### Phase 5: 独立したコード実行

各ワークスペースで独立した変数空間を持つことを確認する。

| 操作 | ツール | パラメータ |
|------|--------|-----------|
| ワークスペースAでコード実行 | `execute_code` | `session_id: "{session_a_id}", code: "workspace_name = 'A'\nvalue_a = 100"` |
| ワークスペースBでコード実行 | `execute_code` | `session_id: "{session_b_id}", code: "workspace_name = 'B'\nvalue_b = 200"` |
| ワークスペースAで変数確認 | `get_variables` | `session_id: "{session_a_id}"` |
| ワークスペースBで変数確認 | `get_variables` | `session_id: "{session_b_id}"` |

確認項目:
- [ ] ワークスペースAの変数に `workspace_name='A'` と `value_a=100` が存在する
- [ ] ワークスペースAの変数に `value_b` が存在しない
- [ ] ワークスペースBの変数に `workspace_name='B'` と `value_b=200` が存在する
- [ ] ワークスペースBの変数に `value_a` が存在しない

#### Phase 6: data/output ディレクトリの分離確認

各ワークスペースの data/output ディレクトリにファイルを書き込み、相互に見えないことを確認する。

| 操作 | ツール | パラメータ |
|------|--------|-----------|
| ワークスペースAでデータ書き込み | `execute_code` | `session_id: "{session_a_id}", code: "import pandas as pd\ndf = pd.DataFrame({'x': [1,2,3]})\ndf.to_csv('data/data_a.csv', index=False)"` |
| ワークスペースBでデータ書き込み | `execute_code` | `session_id: "{session_b_id}", code: "import pandas as pd\ndf = pd.DataFrame({'y': [4,5,6]})\ndf.to_csv('data/data_b.csv', index=False)"` |
| ワークスペースAの data/ 確認 | `file_list` | `workspace_id: "{ws_a_id}", path: "data"` |
| ワークスペースBの data/ 確認 | `file_list` | `workspace_id: "{ws_b_id}", path: "data"` |

確認項目:
- [ ] ワークスペースAの data/ に `data_a.csv` が存在する
- [ ] ワークスペースAの data/ に `data_b.csv` が存在しない
- [ ] ワークスペースBの data/ に `data_b.csv` が存在する
- [ ] ワークスペースBの data/ に `data_a.csv` が存在しない

#### Phase 7: ワークスペース間アクセス制限の確認

ワークスペースAのセッションからワークスペースBのファイルにアクセスできないことを確認する。

| 操作 | ツール | パラメータ |
|------|--------|-----------|
| ワークスペースBのパスにアクセス試行 | `execute_code` | `session_id: "{session_a_id}", code: "import os\nos.listdir('../')"` |
| os.chdir で脱出試行 | `execute_code` | `session_id: "{session_a_id}", code: "import os\nos.chdir('..')"` |

確認項目:
- [ ] ワークスペースAのセッションから親ディレクトリの参照がエラーになる（PermissionError 等）
- [ ] os.chdir でワークスペース外に移動しようとするとエラーになる

#### Phase 8: MCP再起動後の永続性確認

MCP サーバーを再起動し、既存ワークスペースが再発見できることを確認する。

```bash

```

| 操作 | ツール | パラメータ |
|------|--------|-----------|

| ワークスペースAのファイル確認 | `file_list` | `workspace_id: "{ws_a_id}"` |
| ワークスペースBのファイル確認 | `file_list` | `workspace_id: "{ws_b_id}"` |

確認項目:
- [ ] MCP再起動後、workspace_list で両方のワークスペースが表示される
- [ ] ワークスペースAのファイル（analysis-a.ipynb, data/data_a.csv）にアクセスできる
- [ ] ワークスペースBのファイル（analysis-b.ipynb, data/data_b.csv）にアクセスできる
- [ ] 再起動後に新しいセッションを作成し、既存データを読み込めることを確認

### 技術的な考慮事項

- **手動検証タスク**: Infrastructure Phase 3 は実際のMCPクライアント操作による動作確認フェーズ。自動テストは Phase 10.3（workspace-isolation.test.ts）と Phase 10.5（workspace-access-restriction.test.ts）で既にカバー済み

- **既知の問題**: 3.1 で `execute_sql` ツールが表示されない問題があった（ビルドが古かった）。事前に `scripts/rebuild-mcp.sh jupyter-mcp` を実行しておくこと

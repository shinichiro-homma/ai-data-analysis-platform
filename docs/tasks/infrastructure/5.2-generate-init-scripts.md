# タスク詳細: 5.2 init スクリプト自動生成スクリプト

## 概要

カタログ YAML を Single Source of Truth として、PostgreSQL の init スクリプト（`create-tables.sql` と `load-data.sh`）を自動生成する `scripts/generate-init-scripts.sh` を作成する。

**なぜ必要か:** 現在 `postgres/init/sample/create-tables.sql` と `load-data.sh` は手動で作成・メンテナンスされている。テーブル追加のたびにカタログ YAML と init スクリプトの二重管理が発生し、不整合のリスクがある。カタログ YAML から自動生成することで、テーブル追加フローを「CSV配置 → YAML作成 → スクリプト実行」の3ステップに簡素化する。

## 実装計画

### 作成するファイル

| ファイル | 内容 |
|----------|------|
| `scripts/generate-init-scripts.sh` | シェルスクリプト（エントリポイント）。引数バリデーション → Python スクリプト呼び出し |
| `scripts/lib/generate_init.py` | Python スクリプト本体。カタログ YAML パース → SQL/SH 生成 |

### 実装手順

#### ステップ 1: `scripts/generate-init-scripts.sh` 作成

シェルスクリプトのエントリポイント。既存スクリプト（`switch-env.sh`）のパターンに倣う。

- `set -euo pipefail`
- 引数: `ENV`（`sample` or `production`）
- バリデーション: `VALID_ENVS=("sample" "production")`
- `usage()` 関数でヘルプ表示
- Python スクリプト呼び出し: `python3 scripts/lib/generate_init.py "$ENV"`
- 生成結果の表示（生成されたファイルパスの一覧）

#### ステップ 2: `scripts/lib/generate_init.py` 作成

Python スクリプト本体。以下の処理を行う。

**2a. カタログ YAML の読み込み**

- `document-server/data/{ENV}/catalog/tables/*.yaml` を全件読み込み
- `external/` 配下は除外（`data_source.type: external` は PostgreSQL テーブルではない）
- PyYAML (`pyyaml`) を使用

**2b. `create-tables.sql` の生成**

各テーブル YAML から以下を生成:

```sql
-- Auto-generated from catalog YAML. DO NOT EDIT MANUALLY.
-- Generated at: {timestamp}

-- テーブル: {display_name}
CREATE TABLE IF NOT EXISTS {table_name} (
    {column_name} {type} [NOT NULL] [PRIMARY KEY],
    ...
);
```

生成ルール:
- `data_source.table` を PostgreSQL テーブル名として使用
- カラム名に日本語や特殊文字が含まれる場合はダブルクォート `"カラム名"` で囲む（安全のため全カラム名をクォートする方針）
- `type` はカタログ YAML の値をそのまま使用（`varchar(16)`, `integer`, `date` 等）
- `nullable: false` → `NOT NULL`
- `key_type: "primary"` → `PRIMARY KEY`
- `domain.values` → `CHECK ({column} IN ('値1', '値2', ...))` 制約生成
- `domain.master_table` → `REFERENCES {master_table}({master_column})` 外部キー生成
- テーブル順序: `index.yaml` の `tables_index` の順番に従う（外部キー依存を考慮）

**2c. `load-data.sh` の生成**

```bash
#!/bin/bash
# Auto-generated from catalog YAML. DO NOT EDIT MANUALLY.
# Generated at: {timestamp}

set -euo pipefail

DATA_DIR="/tmp/data/{ENV}"

# Check CSV files exist
for f in {csv_file_1} {csv_file_2} ...; do
  if [[ ! -f "$DATA_DIR/$f" ]]; then
    echo "ERROR: $DATA_DIR/$f not found"
    exit 1
  fi
done

psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" <<-EOSQL
\COPY {table_name}({col1}, {col2}, ...) FROM '$DATA_DIR/{table_name}.csv' CSV HEADER;
...
EOSQL
```

生成ルール:
- CSV ファイルパス: `/tmp/data/{ENV}/{table_name}.csv`（docker-compose のボリュームマウントに対応）
- `\COPY` のカラムリストから `SERIAL` 型のカラムを除外（自動採番）
- カラム名のクォート: `create-tables.sql` と同様、全カラム名をダブルクォートで囲む
- テーブル順序: `create-tables.sql` と同じ（外部キー依存を考慮）
- CSV ファイル存在チェック: 生成時ではなく実行時に `postgres/data/{ENV}/` 内のファイルを確認

**2d. ファイル書き出し**

- 出力先: `postgres/init/{ENV}/create-tables.sql` と `postgres/init/{ENV}/load-data.sh`
- `load-data.sh` に実行権限を付与（`chmod +x`）
- 既存ファイルは上書き（自動生成ファイルであるため）

#### ステップ 3: テスト

- 自動生成 → `switch-env.sh` → データロード確認の一連フローをテスト

### 技術的な考慮事項

**カラム名のクォート戦略:**
現在の sample データは全て英語カラム名だが、将来の日本語カラム名に備えて全カラム名をダブルクォートで囲む。PostgreSQL は `"column_name"` と `column_name` を同一視するため、英語カラム名でもクォートしても問題ない。ただし、クォートされたカラム名は大文字小文字を区別するようになる点に注意（カタログ YAML の `name` の値がそのまま使われる）。

**テーブル順序と外部キー依存:**
`index.yaml` の `tables_index` の順番を「テーブル作成順序」として使用する。外部キー参照先テーブルが先に作成されるよう、`index.yaml` の記載順序をユーザーが管理する前提。自動的な依存解決は行わない（過度な複雑化を避ける）。

**SERIAL 型の扱い:**
`type: serial` のカラムは `\COPY` のカラムリストから除外する。PostgreSQL が自動採番するため、CSV にも含まれない前提。

**`data_source.type` のフィルタリング:**
`postgresql` 型のテーブルのみ対象。`external` 型と `csv` 型は PostgreSQL に CREATE TABLE しないため除外。

**既存の手動 init スクリプトとの互換性:**
自動生成されるスクリプトは、既存の手動作成スクリプトと同じ構造（CREATE TABLE + インデックス / \COPY + CSV HEADER）を踏襲する。ただし、インデックス定義はカタログ YAML に含まれないため、自動生成されない。必要なら手動で追記するか、将来のカタログ拡張で対応する。

**Python 依存:**
`pyyaml` のみ使用。ホストマシンで実行するため、仮想環境は不要（`pip install pyyaml` または `brew install pyyaml`）。スクリプト冒頭で `import yaml` の ImportError をキャッチし、インストール方法を案内する。

## テスト計画

### 1. 自動生成の検証（ユニットテスト的）

```bash
# sample 環境で生成
scripts/generate-init-scripts.sh sample

# 生成結果を確認
cat postgres/init/sample/create-tables.sql
cat postgres/init/sample/load-data.sh
```

確認項目:
- 3テーブル（customer_master, product_master, purchase_history）の CREATE TABLE が含まれる
- 外部キー制約（purchase_history → customer_master, product_master）が含まれる
- CHECK 制約（gender の値域）が含まれる
- SERIAL 型（transaction_detail_id）が \COPY カラムリストに含まれない
- tenant_master（external 型）が含まれない

### 2. E2E テスト（Docker 環境）

```bash
# 自動生成 → 環境切り替え → データロード
scripts/generate-init-scripts.sh sample
scripts/switch-env.sh sample --yes

# データ確認
docker compose exec postgres psql -U jupyter -d analysis_db -c "SELECT count(*) FROM customer_master;"
docker compose exec postgres psql -U jupyter -d analysis_db -c "SELECT count(*) FROM product_master;"
docker compose exec postgres psql -U jupyter -d analysis_db -c "SELECT count(*) FROM purchase_history;"
```

### 3. 日本語カラム名テスト

テスト用に日本語カラム名を含む YAML を一時的に作成し、生成結果のダブルクォートを確認する（テスト後に削除）。

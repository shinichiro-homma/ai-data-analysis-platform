# タスク詳細: 9.2 mypy / pytest のルート venv 統合

## 概要

`document-server` と `jupyter-server` のローカル開発用型チェック（mypy）とテスト実行（pytest）を、ルート venv 単一経由で実行できるようにする。`scripts/test.sh` 内の per-component `.venv/bin/activate` 分岐を撤廃し、`uv run mypy` / `uv run pytest` に一本化する。

本タスクは 9.1 で導入したルート venv に依存を積み増す増分変更のみで、各サブディレクトリの `pyproject.toml` は変更しない（フラット配置方針）。Docker ビルド経路（`jupyter-server/requirements.txt`, `document-server/Dockerfile` 等）には一切触らない。

## 関連ドキュメント

- `docs/tasks/infrastructure/9.1-root-venv-scripts-uv.md` — 前提タスク（完了済み）
- `docs/plan/04-infrastructure.md` Phase 9 — 本タスクを含む Phase 定義
- `document-server/pyproject.toml` — `[project.dependencies]` と `[project.optional-dependencies].dev` が既に整備済み（変更しない）
- `jupyter-server/pyproject.toml` — `[project.optional-dependencies].dev` に `pytest`, `pytest-asyncio` のみ記載済み（`src/` は存在せずコードは `extensions/custom_api/` にある）
- `document-server/tests/conftest.py` — `from src.catalog_loader import ...` の形式で `src/` を import するため、`cd document-server` してから pytest を起動する必要がある
- `jupyter-server/tests/conftest.py` — `sys.modules` に外部依存（`jupyter_server`, `tornado`, `sqlalchemy`, `pandas` 等）をモック化しているため editable install 不要

### 変更対象外

- `document-server/pyproject.toml` — 既に well-structured。uv workspace 化しないため変更不要
- `jupyter-server/pyproject.toml` — 変更不要。`[build-system]` は追加しない（workspace 化しないため）
- `document-server/requirements.txt`, `jupyter-server/requirements.txt` — Docker 用。不変
- 各コンポーネントの `Dockerfile` — 不変
- `jupyter-server/CLAUDE.md` — 既にローカル Python コマンドを含まない（Docker コマンドのみ）
- `jupyter-server/tests/conftest.py` — 既に外部依存をモック化している。改変不要

### 実装手順

1. ルート `pyproject.toml` の `[dependency-groups] dev` に mypy / pytest / document-server runtime deps を追記する
2. `uv sync` を実行してルート `.venv/` に反映し、`uv run python -c "import fastapi, pydantic, pytest, mypy"` が成功することを確認する
3. ルートから `uv run mypy document-server/src` を実行し、既存ベースラインの型エラー件数を記録する（回帰検知用）
4. ルートから `(cd document-server && uv run --project .. pytest)` を実行し、既存テストが通ることを確認する
5. ルートから `(cd jupyter-server && uv run --project .. pytest)` を実行し、既存テスト（`sys.modules` モックに依存）が通ることを確認する（jupyter-server に mypy はかけない — `src/` 非存在のため）
6. `scripts/test.sh` の先頭に `REPO_ROOT="$(pwd)"` を追加する
7. mypy 分岐を編集: `HAS_VENV` 分岐とフォールバックを削除し、`if [[ -d "$component/src" ]]; then uv run mypy "$component/src"; else echo "  SKIP: no src/ directory"; fi` 形式に置換する
8. pytest 分岐も同様に編集し、`(cd "$component" && uv run --project "$REPO_ROOT" pytest)` に置換する。Python プロジェクト検出条件は維持する
9. 未使用になった `HAS_VENV` 変数を削除する
10. `scripts/test.sh document-server` と `scripts/test.sh jupyter-server` を実行し、lint + typecheck + pytest が一貫して通ることを確認する
11. `scripts/test.sh --typecheck document-server` と `scripts/test.sh --test jupyter-server` も実行し、既存オプションが壊れていないことを確認する
12. `document-server/CLAUDE.md` のコマンドセクションを `uv run` プレフィックス形式に更新する
13. `.claude/rules/python-uv.md` に mypy / pytest の運用ルールを追記する

### 技術的な考慮事項

- **workspace 不採用の理由**: uv workspace を使うと各 member を editable install する必要があり、`jupyter-server/pyproject.toml` に `[build-system]` を追加することになって変更範囲が広がる。フラット配置なら各コンポーネントの pyproject.toml を一切触らずに済む
- **editable install 不要**:
  - `document-server/tests/conftest.py` は `from src.catalog_loader import CatalogStore` を実行する。pytest は `cd document-server && pytest` で rootdir を `document-server/` と解決し、`conftest.py` 周辺ディレクトリを自動的に `sys.path` へ追加するため `src/` モジュールが解決される（現行と同じ挙動）
  - `jupyter-server/tests/conftest.py` は `sys.modules["jupyter_server"]` 等をモック化しており、`custom_api` モジュールは `extensions/` を `sys.path` に追加する形で解決される
- **pytest の実行ディレクトリ**: 各コンポーネントの `pyproject.toml` にある `[tool.pytest.ini_options]` の `testpaths=["tests"]` と rootdir 解決を生かすため、`cd <component>` してから `uv run --project "$REPO_ROOT"` で実行する。`--project` はルートを指定するため、依存解決はルート venv を使いながら、rootdir はコンポーネント直下を維持できる
- **jupyter-server の mypy はスキップ**: `jupyter-server/src/` は存在せず、コードは `extensions/custom_api/` にある。これを mypy にかけると `jupyter_server`, `tornado`, `sqlalchemy` などの未インストール型スタブで大量のエラーが出る。本タスクは venv 統合が目的であり、新規に型チェックを導入しない。従来通り `src/` 不在でスキップ扱いとする
- **mypy 設定**: `document-server` に `[tool.mypy]` セクションは存在しない。デフォルト設定で `mypy document-server/src` を実行する。将来的な型スタブ追加（`types-PyYAML` 等）が必要になった場合は別タスクで対応
- **`REPO_ROOT` の算出**: `scripts/lib/common.sh` には `REPO_ROOT` 変数が存在しない。`scripts/test.sh` 先頭の `cd "$(dirname "$0")/.."` 直後に `REPO_ROOT="$(pwd)"` を追加してローカル変数として扱う（common.sh 側は変更しない）
- **document-server の `pip install -r requirements.txt`**: これは Docker 用であり、ローカル開発者が実行する必要はない。CLAUDE.md から削除し、代わりに「ルートで `uv sync` 済みであれば追加操作不要」を明記する
- **`pyyaml` の重複回避**: 9.1 で既に root dev group に追加済み。`uv sync` は冪等だが、`pyproject.toml` 編集時に同じ行を重複させないよう注意する
- **workspace 化の将来拡張余地**: フラット配置でも、後日 workspace に切り替える場合は `[tool.uv.workspace] members = [...]` を追加するだけで移行可能。今は複雑さを避ける

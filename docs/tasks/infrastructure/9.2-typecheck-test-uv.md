# タスク詳細: 9.2 mypy / pytest のルート venv 統合

## 概要

`document-server` と `jupyter-server` のローカル開発用型チェック（mypy）とテスト実行（pytest）を、ルート venv 単一経由で実行できるようにする。`scripts/test.sh` 内の per-component `.venv/bin/activate` 分岐を撤廃し、`uv run mypy` / `uv run pytest` に一本化する。

本タスクは 9.1 で導入したルート venv に依存を積み増す増分変更のみで、各サブディレクトリの `pyproject.toml` は変更しない（フラット配置方針）。Docker ビルド経路（`jupyter-server/requirements.txt`, `document-server/Dockerfile` 等）には一切触らない。

- `jupyter-server/pyproject.toml` — `[project.optional-dependencies].dev` に `pytest`, `pytest-asyncio` のみ記載済み
- `jupyter-server/tests/conftest.py` — `sys.modules` に外部依存（`jupyter_server`, `tornado`, `sqlalchemy`, `pandas` 等）をモック化しているため editable install 不要

### 変更対象外

- `document-server/pyproject.toml` — 既に well-structured。uv workspace 化しないため変更不要
- `jupyter-server/pyproject.toml` — 変更不要。`[build-system]` は追加しない（workspace 化しないため）
- `document-server/requirements.txt`, `jupyter-server/requirements.txt` — Docker 用。不変
- 各コンポーネントの `Dockerfile` — 不変
- `jupyter-server/CLAUDE.md` — 既にローカル Python コマンドを含まない（Docker コマンドのみ）
- `jupyter-server/tests/conftest.py` — 既に外部依存をモック化している。改変不要

### 実装手順

1. ルート `pyproject.toml` の `[dependency-groups] dev` に依存を追記し、`uv sync` を実行してルート `.venv/` に反映する
2. ルートから `uv run mypy document-server/src` を実行し、既存の型エラーが再現することを確認する（回帰検知用ベースライン）
3. ルートから `(cd document-server && uv run --project .. pytest)` を実行し、既存テストが通ることを確認する
4. `jupyter-server` についても同様に `uv run mypy jupyter-server/extensions` と `(cd jupyter-server && uv run --project .. pytest)` が通ることを確認する
5. `scripts/test.sh` の mypy 分岐（L230-248 相当）を編集し、`.venv/bin/activate` 分岐を削除して `uv run mypy` に置換する
6. `scripts/test.sh` の pytest 分岐（L273-279 相当）も同様に `uv run --project "$REPO_ROOT" pytest` に置換する
7. `scripts/test.sh document-server` と `scripts/test.sh jupyter-server` をそれぞれ実行し、lint + mypy + pytest が一貫して通ることを確認する
8. `document-server/CLAUDE.md` のコマンドセクションを `uv run` プレフィックス形式に更新する
9. `.claude/rules/python-uv.md` に運用ルールを追記する

### 技術的な考慮事項

- **workspace 不採用の理由**: uv workspace を使うと各 member を editable install する必要があり、`jupyter-server/pyproject.toml` に `[build-system]` を追加することになって変更範囲が広がる。フラット配置なら各コンポーネントの pyproject.toml を一切触らずに済む
- **editable install 不要**:
  - `jupyter-server` の `conftest.py` が `sys.modules["jupyter_server"]` 等をモック化しており、`custom_api` モジュールは `PYTHONPATH` からの直接 import で解決される
  - `document-server` の tests も `src/` を `sys.path` に追加する conftest 構造になっている（確認が必要だが、現状既に動いているため維持可能）
- **pytest の実行ディレクトリ**: 各コンポーネントの `pyproject.toml` にある `[tool.pytest.ini_options]` の `testpaths=["tests"]` を生かすため、`cd <component>` してから `uv run --project <root>` で実行する
- **mypy 設定**: 両コンポーネントに `[tool.mypy]` セクションは存在しない。デフォルト設定で `mypy <component>/src` を実行する。将来的な型スタブ追加（`types-PyYAML` 等）が必要になった場合は別途追記
- **`REPO_ROOT` 変数**: `scripts/test.sh` には既にリポジトリルート検出ロジックがあるはず（`scripts/lib/common.sh` で定義）なので、それを `--project` に渡す
- **document-server の `pip install -r requirements.txt`**: これは Docker 用であり、ローカル開発者が実行する必要はない。CLAUDE.md から削除し、代わりに「ルートで `uv sync` 済みであれば追加操作不要」を明記する
- **workspace 化の将来拡張余地**: フラット配置でも、後日 workspace に切り替える場合は `[tool.uv.workspace] members = [...]` を追加するだけで移行可能。今は複雑さを避ける

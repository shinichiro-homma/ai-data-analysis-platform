タスク「$ARGUMENTS」を開始します。

以下の手順で作業してください：

## 1. 未コミットの変更確認

まず、未コミットの変更がないか確認してください：

```bash
git status
```

未コミットの変更がある場合は、先にコミットまたはスタッシュしてください。

## 2. ブランチの確認・切り替え

`.claude/rules/branch-workflow.md` の「ブランチ確認」に従い、現在のブランチを確認してください。

新しいブランチを作成する場合は「ブランチ作成」に従って作成してください。
既に対象タスクの feature ブランチが存在する場合は、「ブランチ切り替え」に従って切り替えてください。

## 3. タスク計画の確認

`docs/tasks/` ディレクトリに、タスク $ARGUMENTS の計画ファイルが存在するか確認してください。

**ファイル名パターン:** `docs/tasks/**/$ARGUMENTS-*.md`

### 計画ファイルが存在しない場合

先に `/custom-plan-task $ARGUMENTS` を実行して、計画を作成・レビューしてください。

**計画なしで実装を開始しないでください。**

### 計画ファイルが存在する場合

計画ファイルを開き、以下を確認してください：

- [ ] 「レビューステータス」の「計画レビュー完了」にチェックが入っている
- [ ] 実装計画が明確である
- [ ] 完了条件が明確である

レビューが完了していない場合は、先にレビューを依頼してください。

## 4. タスクの確認

`docs/plan/README.md` を Read ツールで読み、対象カテゴリファイルを特定してから該当カテゴリファイルも Read し、タスク $ARGUMENTS を見つけてください。

タスクが存在し、ステータスが `[ ]`（未着手）であることを確認してください。

## 5. ステータス更新

タスク $ARGUMENTS のステータスを `[ ]` から `[→]` に更新してください。

**注意: `[x]`（完了）にしないこと。`[→]`（進行中）に更新すること。完了は `/custom-complete-task` で行う。**

## 6. 関連 Skill の特定

タスクの内容に応じて、サブエージェントに渡す Skill パスを特定してください：

| タスク内容 | 参照する Skill |
|-----------|---------------|
| MCP サーバー実装（jupyter-mcp, document-mcp） | `.claude/skills/mcp-typescript-server/SKILL.md` |
| JupyterLab 拡張実装（jupyterlab-ai-sync） | `.claude/skills/jupyterlab-extension/SKILL.md` |
| Jupyter カーネル通信 | `.claude/skills/jupyter-kernel-communication/SKILL.md` |

該当する Skill パスを記録してください（ステップ 7・8 でサブエージェントに渡します）。

## 7. テスト準備（Agent: general-purpose, model: opus）

Agent ツールでサブエージェントを起動してください。

**設定:**
- subagent_type: `general-purpose`
- model: `opus`

**プロンプト:**

```
タスク「{タスク番号}: {タスク内容}」のテスト準備を行ってください。
対象コンポーネント: {コンポーネント名}

## 必読
- `.claude/rules/subagent-defaults.md` を Read し、必読ルール表の役割『テスト準備（Red）』のルールを Read すること

## タスク計画
{計画ファイルの内容を貼る}

## 関連 Skill
{Skill パスがあれば: 実装前に `{Skill パス}` を読んでください}
{なければ: なし}

## 手順

`.claude/rules/tdd.md` の「Red フェーズ」の手順と「テスト実行コマンドの規律」「テストコードの読み方の規律」に従ってテストを準備してください。
lint 失敗時は `.claude/rules/lint.md` に従うこと。
テスト実行コマンド（反復用）: `scripts/test.sh --quiet --test --no-lint {コンポーネント名} -- {対象テストファイル}`
（ユニットテストにリビルドは不要。`--rebuild` を付けないこと）

## 制約
タスク計画の「調査したファイル」「参照ファイル」「作成・変更するファイル」「テスト参照ポインタ」の範囲でのみ作業すること。
範囲外の Glob/Grep 探索は禁止。情報が不足していたら探索せず、不足内容を報告して終了すること。

## 報告
以下の形式で報告してください：
- テストファイル: {パスの一覧}
- テスト状態: {PASS / FAIL（Red フェーズ） / 既存テスト流用}
- 新規作成したテスト: {あれば一覧}
- テスト実行コマンド: {使用するコマンド}
```

**結果を確認し、テストファイルのパスとテスト実行コマンドを記録してください。**

### 7a. Red フェーズの確認（メインで実行）

新規テストが作成された場合、報告を鵜呑みにせず**メインで**テスト実行コマンドを実行し、
**新規テストが失敗（Red）であること**を確認してください。

- 新規テストが最初から通ってしまう場合、テストが実装を検証できていない可能性がある → テスト準備サブエージェントに差し戻す（最大 2 回。解消しなければユーザーに報告して停止）
- 既存テスト流用の場合はこの確認をスキップする

## 8. 実装（Agent: general-purpose, model: opus）

Agent ツールでサブエージェントを起動してください。

**設定:**
- subagent_type: `general-purpose`
- model: `opus`

**プロンプト:**

```
タスク「{タスク番号}: {タスク内容}」を実装してください。
対象コンポーネント: {コンポーネント名}

## 必読
- `.claude/rules/subagent-defaults.md` を Read し、必読ルール表の役割『実装（Green）・バグ修正』のルールを Read すること

## タスク計画
{計画ファイルの内容を貼る}

## 関連 Skill
{Skill パスがあれば: 実装前に `{Skill パス}` を読んでください}
{なければ: なし}

## テスト情報
- テストファイル: {ステップ 7 で記録したテストファイルのパス}
- テスト実行コマンド: {ステップ 7 で記録したコマンド}

## 実装手順

`.claude/rules/tdd.md` の「Green フェーズ」の手順と「テスト実行コマンドの規律」「テストコードの読み方の規律」に従って実装してください。
lint 失敗時は `.claude/rules/lint.md` に従うこと。
テストが通るまで**最大 2 回**試行すること。2 回で通らなければ粘らず、失敗テスト一覧・エラー出力の要約・試行した修正の要約を報告して終了すること。
テストコードは変更しないこと。実装に関係のないファイルを変更しないこと。

## 制約
タスク計画の「調査したファイル」「参照ファイル」「作成・変更するファイル」「テスト参照ポインタ」の範囲でのみ作業すること。
範囲外の Glob/Grep 探索は禁止。情報が不足していたら探索せず、不足内容を報告して終了すること。

## 報告
以下の形式で報告してください：
- 変更ファイル: {パスの一覧}
- テスト結果: {PASS / FAIL}
- テスト修正の有無: {なし / あり（理由: ...）}
- 失敗した場合の原因: {あれば}
```

**結果を確認してください:**
- **テスト PASS** → ステップ 8a に進む
- **テスト FAIL** → ユーザーに報告して停止する

### 8a. Green フェーズの確認（メインで実行）

**メインで**フルゲート `scripts/test.sh --quiet {コンポーネント名}`（lint + 型チェック + 全テスト）を実行し、全テスト PASS を確認してください。
あわせて `git diff --name-only` で変更ファイルが計画の範囲内か照合してください。

- テストが FAIL、または「テスト修正あり」の報告があるのに正当な理由がない場合 → ユーザーに報告して停止
- 計画範囲外の変更がある場合 → 実装サブエージェントに理由を確認し、不要な変更は差し戻す

## 9. 実装報告

以下の形式で報告してください：

```
## タスク実装完了

- タスク: $ARGUMENTS
- 計画ファイル: docs/tasks/{カテゴリ}/{ファイル名}.md
- 実装内容: （計画の概要）
- 変更ファイル: {サブエージェントが報告した変更ファイル一覧}
- テスト結果: PASS

次のステップとして `/custom-complete-task` でコミット・PR 作成に進めます。
```

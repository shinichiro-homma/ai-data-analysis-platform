現在進行中のタスクを完了します。

以下の手順で作業してください：

## 0. ブランチの確認

現在 feature ブランチ上にいることを確認してください。
dev ブランチ上にいる場合は、対象タスクの feature ブランチに切り替えてください（`.claude/rules/branch-workflow.md` の「ブランチ切り替え」参照）。

## 1. 進行中タスクの特定（メインで直接実行）

`docs/plan/README.md` を Read ツールで読み、対象カテゴリファイルを特定してから該当カテゴリファイルも Read し、ステータスが `[→]` のタスクを見つけてください。
**サブエージェントは使わず、メインで直接読むこと。**

以下を特定してください：

- **タスク番号**と**タスク内容**
- **対象コンポーネント**（jupyter-server / jupyter-mcp / jupyterlab-ai-sync / document-server / document-mcp）
- **タスク種別**（mcp / api / extension / infra / test / other）

`[→]` のタスクが存在しない場合は、ステップ2〜7をスキップして**ステップ8（次のタスクの提案）**に進んでください。

## 2. タスク計画の確認（メインで直接実行）

`docs/tasks/**/{タスク番号}-*.md` を Glob で検索し、見つかった計画ファイルを Read ツールで読み、**完了条件**を確認してください。

## 3. テスト再実行（必須）

タスク完了前の最終確認として、リビルド＋テストを実行してください。

`scripts/test.sh --rebuild {対象コンポーネント名}` を実行してください。
`.claude/rules/rebuild-before-test.md` に従うこと。

## 4. 完了検証

以下の検証を **1 つのメッセージで並列に実行** してください。

まず `.claude/skills/parallel-investigation/SKILL.md` を読み、テンプレートを確認してください。

### 4a. 要件照合（条件に応じたサブエージェントを起動）

以下の起動判定表に従って Agent ツールでサブエージェントを起動してください。

#### 起動判定表

| Agent | 起動条件 | subagent_type | model |
|-------|----------|---------------|-------|
| A: 要件照合 | **常に起動** | `requirements-verifier` | `haiku` |
| B: API 仕様照合 | `api` または `mcp` タスクのみ | `requirements-verifier` | `haiku` |
| C: ドキュメント整合性 | `api` または `mcp` タスクのみ | `requirements-verifier` | `sonnet` |

#### Agent A — 要件定義との照合

**テンプレート A**（単一ドキュメント読み取り）を使用:
- ファイル: `docs/requirements/{コンポーネント名}.md`
- subagent_type: `requirements-verifier`, model: `haiku`
- 目的: タスク「{タスク内容}」の実装が要件を満たしているか検証
- コンテキスト: 完了条件（ステップ2で読んだ内容をここに貼る）
- 調査対象の追加指示: 対象コンポーネントの src/ ディレクトリから実装ファイルも確認し、完了条件の各項目が実装されているか検証する
- 出力: 充足している要件一覧、未充足の要件一覧（あれば）、ブラウザ動作確認が必要か（はい/いいえ）

#### Agent B — API 仕様との照合

**テンプレート A**（単一ドキュメント読み取り）を使用:
- ファイル: `docs/design/api-contracts.md`
- subagent_type: `requirements-verifier`, model: `haiku`
- 目的: タスク「{タスク内容}」の実装が API 仕様に準拠しているか検証
- コンテキスト: 対象コンポーネント名
- 調査対象の追加指示: 対象コンポーネントの src/ から該当する実装を確認し、リクエスト/レスポンス形式が仕様と一致しているか検証する
- 出力: 準拠している仕様一覧、不一致の箇所一覧（あれば）

### 4b. ドキュメント整合性チェック（条件に応じたサブエージェントを起動）

要件照合と **同時に**、以下の起動判定に従って Agent ツールでサブエージェントを起動してください。

#### 起動判定

| Agent | 起動条件 | subagent_type | model |
|-------|----------|---------------|-------|
| C: ドキュメント整合性 | `api` または `mcp` タスクのみ | `requirements-verifier` | `sonnet` |

`infra` / `docs` / `test` タスクではスキップしてください。

#### Agent C — ドキュメント整合性チェック（コード → ドキュメント方向）

**テンプレート C**（ドキュメント整合性検証）を使用:
- subagent_type: `requirements-verifier`, model: `sonnet`
- タスク名: `{タスク内容}`
- コンポーネント: `{コンポーネント名}`
- 追加の検証観点: `.claude/skills/doc-code-audit/SKILL.md` の「監査の3つのモード」（A. 欠落検出 / B. 陳腐化検出 / C. 冗長検出）に従うこと

### 検証結果の統合

要件照合結果・ドキュメント整合性チェック結果を統合して判断してください：

- **要件全充足 + ドキュメント整合**: ステップ 5 に進む
- **要件不充足**: 問題を修正してから再検証
- **ドキュメント不整合あり（欠落・陳腐化）**: ステップ 5 に進まず停止し、以下の案内を出力する
- **ドキュメント冗長のみ**: ステップ 5 に進まず停止し、以下の案内を出力する
- **ブラウザ動作確認が必要**: Playwright MCP で確認してからステップ 5 に進む

#### ドキュメント不整合検出時の停止と案内

不整合が見つかった場合、以下の形式で報告して **停止** してください（ステップ 5 以降は実行しない）：

```
## ドキュメント整合性チェック: 不整合を検出

### A. 欠落（ある場合のみ）
1. {ファイルパス}: {具体的な差異}

### B. 陳腐化（ある場合のみ）
1. {ファイルパス}: {具体的な差異}

### C. 冗長（ある場合のみ）
1. {ファイルパス}: {冗長な記述の内容・行番号}

`.claude/skills/doc-code-audit/SKILL.md` の「不整合検出時の修正案内テンプレート」を参照してください。

修正後、`/custom-complete-task` を再実行してください。
```

### ブラウザ動作確認（要件照合で必要と判定された場合のみ、ステップ 5 へ進む前に実施）

`.claude/rules/testing.md` のブラウザ確認手順に従うこと。

## 5. ステータス更新

タスクのステータスを `[→]` から `[x]` に更新してください。

## 6. コミット & PR 作成

### 6a. コミット

`.claude/skills/commit-and-push/SKILL.md` を読み、その手順に従って commit & push を行ってください。

パラメータ:
- context: タスク {番号} {タスク名} 完了
- push: true
- agent: none

### 6b. PR 作成

`.claude/rules/branch-workflow.md` の「PR 作成」に従い、feature → dev の PR を作成してください。

### 6c. CI 待機 + ブランチクリーンアップ

`.claude/rules/branch-workflow.md` の「CI 待機 + dev 切り替え + ブランチ削除」に従い、CI パスを待ってから dev に切り替え、ローカルブランチを削除してください。

CI が失敗した場合はブランチを削除せず、修正を案内して停止してください。

## 7. 次のタスクの提案

同じフェーズ内で、次に着手すべきタスク（ステータスが `[ ]` のもの）を提案してください。
依存関係がある場合は考慮してください。

## 8. 完了報告

以下の形式で報告してください：

```
## タスク完了

- タスク: {番号} {タスク名}
- PR: {PR URL}
- 次のタスク候補: {番号} {タスク名}
```
**次のタスクを案内する際は /custom-plan-task {番号} としてください。**

Issue #$ARGUMENTS の修正を実装します。

以下の手順で作業してください：

## 1. 未コミットの変更確認

まず、未コミットの変更がないか確認してください：

```bash
git status
```

未コミットの変更がある場合は、先にコミットまたはスタッシュしてください。

## 2. ブランチの確認・切り替え

`.claude/rules/branch-workflow.md` の「ブランチ確認」に従い、現在のブランチを確認してください。

新しいブランチを作成する場合は「ブランチ作成」に従って作成してください。
既に対象 Issue の fix ブランチが存在する場合は、「ブランチ切り替え」に従って切り替えてください。

## 3. イシュー詳細ファイルの確認

`docs/issues/` ディレクトリから、Issue #$ARGUMENTS に対応するファイルを探して読んでください。

### 確認事項

以下をすべて確認してください：

- [ ] ファイルが存在する
- [ ] 「修正方針レビュー完了」にチェックが入っている
- [ ] 原因が記載されている
- [ ] 修正ファイル一覧が記載されている
- [ ] テスト計画が記載されている

**「修正方針レビュー完了」にチェックが入っていない場合は、先に `/custom-fix-bug $ARGUMENTS` を実行して設計を完了させてください。設計なしで実装を開始しないでください。**

## 4. 関連ドキュメントの確認

イシュー詳細ファイルに記載されている関連ドキュメントを確認してください：

- 影響範囲に記載されたファイル
- 関連する要件定義（`docs/requirements/*.md`）
- 関連する API 仕様（`docs/design/api-contracts.md`）

## 5. 関連 Skill の特定

修正対象に応じて、サブエージェントに渡す Skill パスを特定してください：

| 修正対象 | 参照する Skill |
|----------|---------------|
| MCP サーバー（jupyter-mcp, document-mcp） | `.claude/skills/mcp-typescript-server/SKILL.md` |
| JupyterLab 拡張（jupyterlab-ai-sync） | `.claude/skills/jupyterlab-extension/SKILL.md` |
| Jupyter カーネル通信 | `.claude/skills/jupyter-kernel-communication/SKILL.md` |

該当する Skill パスを記録してください（ステップ 6・7 でサブエージェントに渡します）。

## 6. テスト準備（Agent: general-purpose, model: opus）

Agent ツールでサブエージェントを起動してください。

**設定:**
- subagent_type: `general-purpose`
- model: `opus`

**プロンプト:**

```
Issue #{Issue番号} の修正に向けたテスト準備を行ってください。
対象コンポーネント: {コンポーネント名}

## 必読
- `.claude/rules/subagent-defaults.md` を Read し、必読ルール表の役割『テスト準備（Red）』のルールを Read すること

## イシュー詳細
{イシュー詳細ファイルの内容を貼る（原因、修正方針、修正ファイル一覧、テスト計画）}

## 関連 Skill
{Skill パスがあれば: 実装前に `{Skill パス}` を読んでください}
{なければ: なし}

## 手順

`.claude/rules/tdd.md` の「Red フェーズ」の手順と「テスト実行コマンドの規律」に従ってテストを準備してください。
**バグを再現する回帰テストを必ず作成すること**（修正前に失敗することを確認するため）。
lint 失敗時は `.claude/rules/lint.md` に従うこと。
テスト実行コマンド（反復用）: `scripts/test.sh --quiet --test --no-lint {コンポーネント名} -- {対象テストファイル}`
（ユニットテストにリビルドは不要。`--rebuild` を付けないこと）

## 報告
以下の形式で報告してください：
- テストファイル: {パスの一覧}
- テスト状態: {PASS / FAIL（Red フェーズ） / 既存テスト流用}
- 新規作成したテスト: {あれば一覧}
- テスト実行コマンド: {使用するコマンド}
```

**結果を確認し、テストファイルのパスとテスト実行コマンドを記録してください。**

### 6a. Red フェーズの確認（メインで実行）

報告を鵜呑みにせず**メインで**テスト実行コマンドを実行し、
**バグ再現テストが失敗（Red）であること**を確認してください。

- 新規テストが最初から通ってしまう場合、バグを再現できていない可能性がある → テスト準備サブエージェントに差し戻す（最大 2 回。解消しなければユーザーに報告して停止）
- 既存テスト流用の場合はこの確認をスキップする

## 7. 実装（Agent: general-purpose, model: opus）

Agent ツールでサブエージェントを起動してください。

**設定:**
- subagent_type: `general-purpose`
- model: `opus`

**プロンプト:**

```
Issue #{Issue番号} の修正を実装してください。
対象コンポーネント: {コンポーネント名}

## 必読
- `.claude/rules/subagent-defaults.md` を Read し、必読ルール表の役割『実装（Green）・バグ修正』のルールを Read すること

## イシュー詳細
{イシュー詳細ファイルの内容を貼る（原因、修正方針、修正ファイル一覧、テスト計画）}

## 関連 Skill
{Skill パスがあれば: 実装前に `{Skill パス}` を読んでください}
{なければ: なし}

## 関連ドキュメント
{ステップ 4 で確認した関連ドキュメントのパス一覧}

## テスト情報
- テストファイル: {ステップ 6 で記録したテストファイルのパス}
- テスト実行コマンド: {ステップ 6 で記録したコマンド}

## 実装手順

`.claude/rules/tdd.md` の「Green フェーズ」の手順と「テスト実行コマンドの規律」に従って実装してください。
修正方針から逸脱しないこと。影響範囲外のファイルを不必要に変更しないこと。
lint 失敗時は `.claude/rules/lint.md` に従うこと。
テストが通るまで**最大 2 回**試行すること。2 回で通らなければ粘らず、失敗テスト一覧・エラー出力の要約・試行した修正の要約を報告して終了すること。テストコードは変更しないこと。

## ブラウザ動作確認

対象がブラウザ動作確認に該当するかの判定と手順は `.claude/rules/testing.md` に従うこと。
バグの再現手順に沿って操作し、修正後は症状が解消されていることを確認する。

## 報告
以下の形式で報告してください：
- 変更ファイル: {パスの一覧}
- テスト結果: {PASS / FAIL}
- テスト修正の有無: {なし / あり（理由: ...）}
- ブラウザ確認: {実施 / 対象外}
- 失敗した場合の原因: {あれば}
```

**結果を確認してください:**
- **テスト PASS** → ステップ 7a に進む
- **テスト FAIL** → ユーザーに報告して停止する

### 7a. Green フェーズの確認（メインで実行）

**メインで**フルゲート `scripts/test.sh --quiet {コンポーネント名}`（lint + 型チェック + 全テスト）を実行し、バグ再現テストを含む全テスト PASS を確認してください。
あわせて `git diff --name-only` で変更ファイルが修正ファイル一覧の範囲内か照合してください。

- テストが FAIL、または「テスト修正あり」の報告があるのに正当な理由がない場合 → ユーザーに報告して停止
- 範囲外の変更がある場合 → 実装サブエージェントに理由を確認し、不要な変更は差し戻す

## 8. 実装報告

以下の形式で報告してください：

```
## 修正実装完了

- Issue: #$ARGUMENTS
- 設計ファイル: docs/issues/{番号}-{名前}.md
- 変更ファイル: {サブエージェントが報告した変更ファイル一覧}
- テスト結果: PASS

次のステップとして `/custom-complete-task` で完了検証・コミット・PR 作成に進めます。
（リファクタが必要な場合は先に `/custom-refactor $ARGUMENTS`）
```

**注意:** イシューファイルの `docs/issues/archive/` への退避は完了時に行う（`docs/plan/README.md` の「アーカイブ規約」に従い `/custom-complete-task` が実施）。このコマンドでは移動しないこと。

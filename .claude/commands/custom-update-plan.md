開発プランを更新します: $ARGUMENTS

以下の手順で作業してください：

## 1. 現在の開発プランを読む

`docs/plan/README.md` を Read ツールで読み、全体構造を把握してください。
指示内容に応じて、該当するカテゴリファイル（`docs/plan/01-jupyter.md`, `docs/plan/02-document.md`, `docs/plan/03-workspace.md`, `docs/plan/04-infrastructure.md`）も Read してください。
**サブエージェントは使わず、メインで直接読むこと。**

## 2. ユーザーの指示を解釈する

以下の指示内容を解釈し、操作種別を特定してください：

**指示:** $ARGUMENTS

### 操作種別の判定

| 操作種別 | 例 |
|----------|-----|
| `add-task` | 「タスク 14.3 を追加」「14.2 の後にテストタスクを追加」 |
| `add-phase` | 「新しいフェーズを追加」 |
| `edit-task` | 「タスク 1.2 の備考を更新」「9.1 の E2E テスト欄を修正」 |
| `edit-phase` | 「Phase 14 の説明を修正」 |
| `change-status` | 「タスク 14.1 をブロック中にする」「1.3 を未着手に戻す」 |
| `remove-task` | 「タスク 14.2 を削除」 |
| `remove-phase` | 「Phase 15 を削除」 |
| `reorder` | 「タスク 14.2 と 14.3 の順番を入れ替え」 |

## 3. タスク追加時の検証（add-task / add-phase の場合のみ）

タスクを追加する場合は、以下のタスク設計ルールに準拠しているか検証してください：

`.claude/rules/task-design.md` のチェックリストに従うこと。

ルールに準拠していない場合は、ユーザーに改善案を提示してください。

## 4. 変更内容のプレビュー

変更を適用する**前に**、以下の形式で変更内容を表示してください：

```
## PLAN.md 更新プレビュー

**操作:** {操作種別}
**対象:** {対象のタスク番号 or Phase 番号}

### 変更内容

{変更前と変更後の diff を分かりやすく表示}

### 変更履歴に追加するエントリ

| {今日の日付} | {変更内容の要約} |
```

## 5. 確認と適用

`AskUserQuestion` ツールで確認を取ってください：

**質問:** "この変更を PLAN.md に適用しますか？"
**選択肢:**
1. **適用する** - この内容で更新する
2. **修正する** - 変更内容を修正してから適用する

### 「適用する」が選択された場合

1. 該当するカテゴリファイル（`docs/plan/01-jupyter.md` 等）に変更を適用する（Edit ツールを使用）
2. 変更履歴セクションに新しいエントリを追加する（日付は今日の日付を使用）
3. 以下のコマンドでコミットする：

```bash
git add docs/plan/ && git commit -m "docs: 開発プランを更新 - {変更内容の要約}" && git push
```

### 「修正する」が選択された場合

1. ユーザーの修正内容を確認する
2. ステップ 4 に戻り、修正後のプレビューを再度表示する

## 6. 完了報告

```
## 開発プラン更新完了

- 操作: {操作種別}
- 対象: {対象}
- 更新ファイル: {更新したカテゴリファイル}
- コミット: {コミットメッセージ}
```

## 注意事項

- このコマンドは `docs/plan/` 配下のカテゴリファイル**のみ**を変更します
- 要件定義（`docs/requirements/*.md`）やAPI仕様（`docs/design/api-contracts.md`）の変更が必要な場合は、`/custom-change-requirement` → `/custom-apply-change` フローを案内してください
- ステータス変更で `[→]`（進行中）に変更する場合は `/custom-start-task` の使用を案内してください
- ステータス変更で `[x]`（完了）に変更する場合は `/custom-complete-task` の使用を案内してください（検証が必要なため）

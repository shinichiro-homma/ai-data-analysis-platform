# 実装後リビルド必須ルール

コードを変更した後にテストを実行する場合、**必ず先にリビルドを行うこと**。
ソースコードの変更がビルド成果物や Docker イメージに反映されていない状態でテストを実行してはならない。

## 推奨: `--rebuild` によるリビルド + テスト一括実行

`test.sh --rebuild` は MCP/Docker を自動判定してリビルドし、テストを実行する。

```
コード変更 → scripts/test.sh --rebuild {コンポーネント名}
```

具体的な使用例は `.claude/rules/scripts.md` の「よく使うパターン」を参照すること。

> **カスタムコマンド経由の場合**: `start-task`, `start-fix`, `refactor`, `complete-task` では `--rebuild` 付きテストが自動実行されるため、手動リビルドは不要。

## 手動リビルド（`--rebuild` が使えない場合）

変更したコンポーネントに応じて、`.claude/rules/scripts.md` のリビルド系スクリプトを使い分けること。

## 禁止事項

- リビルドせずにテストを実行し、その結果を信頼すること
- 鮮度チェック（`scripts/check-freshness.sh`）の警告を無視してテストを続行すること

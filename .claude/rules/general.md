# 一般ルール

このプロジェクト全体に適用されるルール。

## 開発フロー

1. 作業開始前に `docs/plan/` で対象タスクを確認する
2. 関連する要件定義（`docs/requirements/*.md`）を確認する
3. 1タスク1機能で進める（複数タスクを同時に進めない）
4. 作業完了後に `docs/plan/` の該当カテゴリファイルのステータスを更新する

## コミット規約

コミットメッセージは以下の形式で記述する：

```
<type>: <subject>

<body>
```

**type:**
- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメントのみの変更
- `refactor`: リファクタリング
- `test`: テストの追加・修正
- `chore`: ビルド、設定等の変更

**例:**
```
feat: セッション作成APIを実装

- POST /api/kernels エンドポイントを追加
- カーネル起動処理を実装
```

## Bash コマンドの description は日本語で書く

`Bash` ツールを呼び出す際の `description` パラメータは**日本語**で記述すること。
ユーザーが承認プロンプトで何をするコマンドかを即座に判断できるよう、具体的かつ簡潔に書く。

**良い例:**
- `"jupyter-mcp をリビルドして統合テストを実行"`
- `"postgres コンテナのログを直近100行表示"`
- `"dev ブランチから feature/18.3 を作成"`

**悪い例:**
- `"Run tests"` (英語 + 抽象的)
- `"リビルド"` (具体性がない、対象不明)
- `"scripts/test.sh を実行"` (コマンドそのままでは意図が伝わらない)

## アドホックスクリプトの実行

開発・デバッグ中の使い捨てスクリプトは `.claude/rules/adhoc-script-execution.md` に従うこと。
ヒアドキュメントでのワンライナー実行は禁止。`tmp/` 配下にファイルを書き出してから実行する。

## 禁止事項

- 要件定義を確認せずにコードを書き始めること
- 複数タスクを同時に進めること
- テストなしで「完了」とすること（テストが定義されているタスクの場合）

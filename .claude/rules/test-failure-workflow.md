# テスト失敗時のワークフロー

テスト実行時に失敗が発生した場合、以下の手順で対応すること。

## 1. 分類

失敗が **自タスク起因** か **無関係** かを判断する。

- **自タスク起因:** 現在のタスクで変更したコードに起因する失敗 → 通常通り修正する
- **無関係:** 現在のタスクとは関係のない失敗 → 以下のステップ2に進む

## 2. 既知障害の確認

```bash
scripts/manage-known-failures.sh check {コンポーネント名}
```

- **exit 0（登録済み）:** 既知障害のため、現在のタスクでは対応不要。作業を継続する。
- **exit 1（未登録）:** ステップ3に進む。

## 3. 未登録の失敗への対応

`AskUserQuestion` ツールを使って、以下の3択をユーザーに確認する：

### 選択肢

1. **記録して継続** — `scripts/manage-known-failures.sh add` で既知障害として登録し、タスクを続行する
2. **Issue 起票して継続** — `scripts/create-test-issue.sh --add-known` で Issue を作成＆登録し、タスクを続行する
3. **修正する** — `/custom-report-bug` の重要バグフローに従って対応する

## 4. 再確認

対応後、`scripts/test.sh --health` で新規障害がないことを確認する。

```bash
scripts/test.sh --health {コンポーネント名}
```

既知障害のみであれば exit 0 で正常終了する。

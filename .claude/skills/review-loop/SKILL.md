# Review Loop Skill

強モデルによるレビュー → 軽量モデルによる修正 → 再レビューのループを汎用化した共通スキル。

「一発実行で品質保証なしに完了する」経路をなくすために、成果物（計画・コード・ドキュメント等）を
強いモデル（opus）でレビューし、REJECT なら軽いモデル（sonnet）で修正して再レビューする。
規定回数で APPROVE に至らない場合はユーザーへエスカレーションする。

呼び出し側コマンドは「## 呼び出し側が定義するパラメータ」を埋めてこのループを実行する。

---

## 呼び出し側が定義するパラメータ

| パラメータ | 説明 | 例 |
|-----------|------|-----|
| 対象 | レビューする成果物のパスまたは差分 | `docs/tasks/{番号}-*.md`、`git diff HEAD` |
| レビュー観点 | APPROVE/REJECT を判定する基準（コマンド固有） | 完了条件の検証可能性、セキュリティ 等 |
| レビューエージェントの `subagent_type` | レビューを担うサブエージェント種別 | `code-reviewer` / `general-purpose` |
| 修正エージェントへの指示 | 修正時にサブエージェントへ渡す情報・依頼内容 | 対象パス、REJECT 理由と修正指示 |
| 最大修正回数 | 修正ループの上限（**デフォルト 5 回**） | 5 |

`.claude/rules/general.md` の「サブエージェントのモデル選択」に従い、起動時は `subagent_type` と `model` を必ず併記すること。

---

## ステップ 1: レビュー（model: opus）

Agent ツールでレビューエージェントを起動する。

**設定:**
- subagent_type: 呼び出し側が定義（`code-reviewer` / `general-purpose` 等）
- model: `opus`（強モデル。軽量モデルの出力を強いモデルで担保する）

**プロンプトに必ず含める情報:**
- 冒頭に「**あなたは作成者ではありません。批判的に検証してください。**」
- 対象（成果物のパスまたは差分の確認方法）
- レビュー観点（呼び出し側が定義した判定基準）
- 指摘は `.claude/rules/subagent-defaults.md` の証拠スキーマ（場所・問題・根拠・修正案）に従うこと

**出力形式:** `APPROVE` または `REJECT`（REJECT の場合は証拠スキーマ形式の指摘一覧を含める）

**結果をメインで確認する:**
- 指摘のうちバグ・欠陥系は、該当箇所を Read して失敗シナリオが実際に成立するか確認する。**成立が確認できない指摘は修正に流さない**（もっともらしいが誤った指摘を排除する）
- **APPROVE** → ループを終了し、呼び出し側の後続処理へ進む
- **REJECT** → ステップ 2（修正ループ）へ進む

---

## ステップ 2: 修正ループ（model: sonnet、最大 N 回）

Agent ツールで修正エージェントを起動する。

**設定:**
- subagent_type: `general-purpose`
- model: `sonnet`（軽量モデル）

**プロンプトに含める情報:**
- 対象のパス
- 直前のレビューの REJECT 理由と修正指示（メインで検証済みのもののみ）
- `.claude/rules/subagent-defaults.md` を Read し、必読ルール表の役割『リファクタ・レビュー指摘の修正』のルールを Read すること

修正後、再度ステップ 1（レビュー）を実行する。APPROVE になればループを終了する。

**最大修正回数（デフォルト 5 回）修正しても REJECT の場合 → ステップ 3（エスカレーション）へ進む。**

---

## ステップ 3: エスカレーション

最大修正回数で APPROVE に至らない場合、ループを **停止** してユーザーに報告する。

呼び出し側コマンドに固有のエスカレーション導線（例: `custom-auto-dev.md` のステップ 2g）が
ある場合はそちらに従う。ない場合は以下のテンプレートで報告する。

```
## レビューが規定回数で完了しませんでした

- 対象: {成果物のパス}
- 修正回数: {N} 回（すべて REJECT）
- 最後の指摘: {レビューの REJECT 理由の要約}

対応方針をご判断ください（人手での修正 / 観点の見直し / このまま採用 等）。
```

報告後はこのループを終了し、後続処理には進まない。

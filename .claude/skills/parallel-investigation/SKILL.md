# Parallel Investigation Skill

カスタムコマンドで共通的に使われる「並列サブエージェント調査」のテンプレート集。
コマンド内でドキュメント・コード・API仕様を並列に調査する際に使用する。

---

## 並列起動フレーム

以下の構造に従い、起動判定表で必要なエージェントのみ選択して起動する。

```
{前ステップ}で特定した{分類軸}と{対象}に基づき、以下の起動判定表に従ってサブエージェントを選択してください。

**必要なものだけを選び、1 つのメッセージで並列に起動すること。**

### 起動判定表

| Agent | 起動条件 | subagent_type | model |
|-------|----------|---------------|-------|
| {各コマンドで定義} | ... | ... | ... |

（各 Agent のプロンプトは以下のテンプレートを使用）

### 調査結果の統合

すべてのエージェントの結果を統合し、{目的に応じた出力}にまとめてください。
```

---

## エージェントテンプレート

### テンプレート A: 単一ドキュメント読み取り

要件定義・API仕様・全体像・Skill など、1ファイルを読んで関連情報を抽出する。

```
{目的の説明}

対象コンポーネント: {コンポーネント名}
検証対象ファイル: {ファイルパス}

**読むファイルは上記 1 つだけです。他のファイルは読まないでください。**

{コンテキスト情報（タスク内容、変更内容、バグ内容など）}

出力形式:
{調査項目リスト}
```

パラメータ:

| パラメータ | 説明 | 例 |
|-----------|------|-----|
| `{ファイルパス}` | 読み取り対象 | `docs/requirements/jupyter-mcp.md` |
| `{目的の説明}` | 調査の目的 | 「タスクに関連する要件定義を確認してください」 |
| `{コンテキスト情報}` | 調査のスコープを絞る情報 | タスク名、変更内容、バグの症状 |
| `{調査項目リスト}` | 出力で期待する項目 | 関連する機能要件、影響を受けるAPI |

よく使う対象ファイル:

| 用途 | ファイル | subagent_type | model |
|------|---------|---------------|-------|
| 要件定義 | `docs/requirements/{コンポーネント名}.md` | `requirements-researcher` | `haiku` |
| API仕様 | `docs/design/api-contracts.md` | `requirements-researcher` | `haiku` |
| 全体像 | `docs/overview.md` | `requirements-researcher` | `haiku` |
| Skill | `.claude/skills/{関連スキル}/SKILL.md` | `codebase-explorer` | `haiku` |
| タスク計画 | `docs/tasks/{category}/{番号}-{名前}.md` | `requirements-researcher` | `haiku` |

**注意**: コンポーネントが複数ある場合は、コンポーネントごとにエージェントを分けて起動すること。

### テンプレート B: コード調査

特定コンポーネントのソースコードを検索・読み取りして、パターンや影響箇所を特定する。

```
{目的の説明}

対象コンポーネント: {コンポーネント名}

**調査は {コンポーネント名}/ ディレクトリ内のみに限定してください。他のコンポーネントは見ないでください。**

調査手順:
1. {コンポーネント名}/src/ を Grep/Glob で検索
2. 関連ファイルを Read で確認
3. テストの有無を {コンポーネント名}/tests/ で確認

{コンテキスト情報}

出力形式:
{調査項目リスト}
```

パラメータ:

| パラメータ | 説明 | 例 |
|-----------|------|-----|
| `{目的の説明}` | 調査の目的 | 「既存の類似実装パターンを調査してください」 |
| `{コンテキスト情報}` | 検索キーワードのヒントなど | ツール名、関数名、エラーメッセージ |
| `{調査項目リスト}` | 出力で期待する項目 | 関連ファイル一覧、実装パターン、テスト有無 |

| 用途 | subagent_type | model |
|------|---------------|-------|
| コードパターン調査 | `codebase-explorer` | `sonnet` |
| 影響範囲の特定 | `impact-analyzer` | `sonnet` |

**注意**: コンポーネントが複数ある場合は、コンポーネントごとにエージェントを分けて起動すること。

### テンプレート C: ドキュメント整合性検証

実装とドキュメントの一致を検証する（主に complete-task で使用）。
詳細な監査が必要な場合は `doc-code-audit` Skill を参照。

```
タスク「{タスク名}」で変更されたコードと、ドキュメントの整合性を検証してください。

検証対象:
- {変更されたコンポーネント}/CLAUDE.md のツール/API一覧
- docs/overview.md の該当セクション
- README.md のコンポーネント表・ツール一覧

git diff で変更内容を確認し、ドキュメントに反映漏れがないか確認してください。

出力形式:
- 整合: 不整合なし / 不整合あり
- 不整合がある場合: ファイルパスと具体的な差異
```

| 用途 | subagent_type | model |
|------|---------------|-------|
| ドキュメント整合性 | `requirements-verifier` | `sonnet` |
